# RFC: v0.30 Evidence Review Surface

Status: active first slice

## Purpose

Define the first review surface for AIR evidence. AIR's product thesis is that
humans should approve intent and evidence, not read raw `i32` SSA. AIR source
is for AI generation, verification, and deterministic lowering. Human review
should operate on verifier evidence, package reports, diffs, replay summaries,
host policy results, and anti-slop diagnostics.

The first implemented slices are package diff JSON and deterministic Markdown
evidence reports with optional host policy, conformance/replay, and benchmark
summaries. This RFC does not change AIR ABI, Host ABI, language syntax, host
imports, `output.emit`, structured data/tablegroups, benchmarks, or demos.

## 1. Current Evidence Inputs

The review surface should reuse existing evidence sources:

- package reports;
- verification evidence JSON;
- conformance replay reports;
- benchmark reports where relevant as evidence, not performance claims;
- Output Contract manifests;
- command buffer metadata;
- bounded fact and rowset schemas;
- generated artifact freshness metadata;
- LSP-lite and Full LSP diagnostics;
- API gate and reviewPolicy diagnostics;
- host profile/package compatibility diagnostics.

These sources remain the machine-readable truth. Human-readable reports must be
derived from them rather than creating a second diagnostics or proof engine.

## 2. Human-Readable Decision / Evidence Report

The first-slice review report should summarize:

- package name and package status;
- required AIR ABI and Host ABI;
- selected profile and profile compatibility;
- capability summary;
- effect summary;
- output contracts;
- fact schemas and bounded rowset schemas;
- command buffer/output intent metadata;
- generated artifact status;
- verification evidence status;
- replay/conformance status;
- host policy result status;
- diagnostics and red flags.

The report must avoid raw private payloads, raw URLs, secrets, tokens, and
private text. It should show stable identifiers, fingerprints, counts, statuses,
and diagnostic codes instead.

The first implementation is:

```sh
node bin/airc.js evidence report <package-dir> --format markdown -o <file>
```

Optional evidence inputs:

- `--host-evidence <host-interaction-evidence.json>`;
- `--conformance <conformance-report.json>`;
- `--benchmark <benchmark-report.json>`;
- `--profile <profile-id>`.

The first slice emits Markdown with deterministic section ordering:

- package identity;
- verification status;
- AIR ABI and required Host ABI;
- package hash;
- capabilities;
- effects;
- output intents;
- host policy result;
- replay/conformance;
- diagnostics grouped by severity;
- generated artifacts;
- benchmark summary;
- privacy boundary.

Host policy denial is reported as a host policy result, not silently collapsed
into verifier failure.

Golden Markdown fixtures under `test/fixtures/evidence_report/` lock the
deterministic report structure and privacy boundary for canonical evidence
report examples, including passing replay, failing mismatch replay, and
state-digest summary shapes.

Replay summaries are derived from existing `air.conformance.report` JSON. The
Markdown report shows fixture id/kind, status, replay checksum,
expected/observed output and command counts, mismatch count and kinds, output
IDs involved, state digest status when present, and host interaction evidence
status when host evidence is provided. It does not expose raw fixture rows,
command arguments, state digest helper return values, or hidden host state.

## 3. Package Diff

Package diff is a review aid for answering what changed between two package
states or evidence snapshots.

Required first-slice delta categories:

- capability delta;
- effect delta;
- Host ABI requirement delta;
- output contract delta;
- fact schema delta;
- bounded rowset schema delta;
- command buffer metadata delta;
- generated artifact freshness delta.

Useful P1 deltas:

- diagnostic code delta;
- command buffer metadata delta;
- verification evidence status delta;
- replay checksum delta;
- benchmark evidence reference delta without treating timings as claims.

Diff output must be deterministic and must not include absolute paths, local
temporary paths, timestamps as proof, private payloads, or raw host data.

The first implementation is:

```sh
node bin/airc.js diff package <old-package-dir> <new-package-dir> --json
```

It emits:

```json
{
  "schemaVersion": "0.30",
  "kind": "air.packageDiff",
  "status": "passed",
  "oldPackageHash": "sha256:...",
  "newPackageHash": "sha256:...",
  "airAbiDelta": {},
  "hostAbiDelta": {},
  "capabilityDelta": {},
  "effectDelta": {},
  "outputContractDelta": {},
  "factSchemaDelta": {},
  "rowsetSchemaDelta": {},
  "commandBufferDelta": {},
  "generatedArtifactDelta": {},
  "diagnostics": [],
  "limitations": []
}
```

The first slice compares `air.package.json`, package reports, fact schema and
rowset schema fingerprints, output contract fingerprints, command buffer
metadata, generated artifact metadata, and package-required ABI metadata. It
does not diff raw private payloads or introduce a parallel verifier.

Golden JSON fixtures under `test/fixtures/package_diff/` lock deterministic
package diff shape, ordered deltas, and privacy-safe output for controlled
old/new package comparisons.

## 4. Replay Summary

Replay summaries should answer:

- what was replayed;
- which fixture/trace identity was used;
- whether replay passed or failed;
- replay checksum;
- mismatch count;
- mismatch categories;
- output IDs involved;
- state digest status when available;
- host interaction evidence status when available;
- diagnostic codes.

Mismatch categories may include output count mismatch, output ID mismatch,
argument mismatch, row bound exceeded, privacy leak, unsupported profile,
nondeterministic field, unsafe state digest helper, and checksum mismatch where
existing conformance paths can identify them.

## 5. Host Policy Result Summary

The review surface should summarize host policy outcomes without implying host
execution authority:

- allowed;
- denied;
- unknown output;
- unsupported profile.

This is review evidence. It does not add real host adapters, automatic
host-side action execution, new Host ABI imports, or platform authority.

## 6. Machine-Readable Diagnostics Consistency

Human-facing reports must preserve machine-readable diagnostic identity:

- stable diagnostic code;
- severity;
- source/category;
- path/module where available;
- range/line/column where available;
- stable structured fields;
- repair hint where available.

The review surface must not collapse specific diagnostics into generic
`package-check failed` output when specific diagnostics already exist. Generic
failures are acceptable only when no more specific diagnostic source exists.

## 7. Privacy Boundary

Human-readable evidence is not a payload dump.

Allowed:

- stable IDs;
- counts;
- schema names;
- output IDs or generated output handles;
- hashes/fingerprints;
- pass/fail status;
- bounded scalar arguments where already public review evidence;
- diagnostic codes and minimized fields.

Rejected:

- raw private text;
- raw URLs;
- secrets;
- tokens;
- credentials;
- raw logs;
- arbitrary JSON payload dumps;
- host object handles;
- browser/network/filesystem authority evidence that was not explicitly
  authorized by a prior accepted Host ABI/profile.

## 8. No Performance Claims

v0.30 may reference v0.29 benchmark evidence as context, but it must not create
new public performance claims. No `x50`, `x200`, global language-speed claim,
or optimization claim is accepted by this RFC.

## 9. JSON And Human Surfaces

The preferred model is:

- stable JSON evidence remains source of truth;
- human-readable Markdown or HTML is derived output;
- diffs are deterministic and schema-backed;
- no hidden repair or proof engine is introduced.

If a future viewer is added, it must not hide diagnostic codes or suppress
machine-readable evidence needed for review.

## 10. P1 Viewer / Pretty Printer

P1 may add:

- Markdown evidence viewer;
- minimal HTML evidence viewer;
- diff pretty-printer;
- AI repair prompt export;
- evidence snapshot comparison across commits.

Any AI repair prompt export must remain suggestion-only. LSP code actions,
automatic rewrites, and parallel repair engines are deferred.

## 11. Deferred

- structured IO implementation;
- tablegroups;
- LSP code actions;
- real host adapters;
- new Host ABI;
- performance dashboard;
- automatic host action execution;
- raw payload review dumps.

## 12. ABI Status

AIR ABI latest remains `0.10`.

Host ABI latest remains `0.11`, limited to bounded `output.emit`. Host ABI
`0.10` remains the default/baseline compatibility target. This RFC adds no host
imports, output events, payloads, dynamic output IDs, or platform authority.

## 13. Acceptance Criteria

The v0.30 first-slice plan is acceptable when it defines:

- human-readable decision/evidence report scope;
- package diff categories;
- replay summary fields;
- host policy result summary fields;
- diagnostics consistency rules;
- privacy boundary;
- no-performance-claims rule;
- ABI non-change statement;
- deferred boundaries.
