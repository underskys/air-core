# RFC: v0.32 Bounded Structured IO First Slice

Status: implemented first slice

## Purpose

Define the implementation target for a minimal executable bounded structured IO
slice. The first slice must be useful to consumers without adding runtime JSON,
dynamic objects, maps, tablegroup syntax, declared pools, Host ABI expansion, or
host authority.

## Scope

P0 first slice:

- bounded scalar records;
- fixed rowset input;
- bounded structured output summaries;
- generated field handles, offsets, and host binding metadata;
- package report, verification evidence, package diff, evidence report, and
  replay visibility;
- negative tests against JSON/object drift.

## Accepted First-Slice Representation

v0.32 first slice uses package metadata and generated bindings. It does not add
new AIR parser syntax.

Allowed representation:

- record schema JSON;
- rowset schema JSON;
- output summary schema JSON;
- generated AIR handle constants;
- generated host binding metadata;
- package-check validation;
- package report, verification evidence, package diff, evidence report, and
  replay visibility.

Implemented manifest and generated artifact paths:

- `structuredIO`: package-local structured record, structured rowset, and
  structured output summary schema JSON files;
- `generated/structured_io_handles.air`: constants-only generated AIR module;
- `generated/structured_io.meta.json`: deterministic source fingerprint,
  schema, and handle metadata.

Rejected for the first slice:

- new AIR record syntax;
- runtime JSON;
- dynamic objects;
- nested records;
- strings;
- nullable fields;
- dynamic row counts without package bounds;
- host object handles.

## Source of Truth

Source-of-truth surfaces remain:

- `factSchemas` and bounded rowset schemas for input facts;
- Output Contracts for output IDs/intents;
- command buffer schemas for batch output intents;
- state declarations for AIR-owned fixed state.

Generated field handles, offsets, and bindings are derived artifacts. They must
be deterministic, freshness-checked, report-visible, and unable to become
semantic source of truth.

## Data Model

Allowed first-slice data:

- integer IDs;
- enum IDs;
- scalar handles that identify host-owned objects without granting access;
- flags;
- bounded scores;
- counters;
- booleans where already supported by surrounding schemas.

Rejected:

- runtime JSON;
- strings;
- nested records;
- dynamic arrays;
- maps;
- objects or object identity;
- ORM/database semantics;
- host object handles;
- raw URLs, private text, tokens, secrets, credentials, raw packet payloads.

## Rowsets

Fixed rowset input must remain package metadata/tooling and conformance-owned.
AIR must not parse JSON at runtime, receive arbitrary objects, or access dynamic
keys. Host/test harnesses may decode fixture JSON into minimized scalar records.

Package-check must reject unbounded rows, non-scalar fields, forbidden private
fields, generated artifact source-of-truth drift, and schema/generated binding
freshness mismatches.

The implemented first slice rejects missing `maxRows` for structured rowsets,
runtime JSON/object/map/any/string-like field types, nested field/property/item
shapes, and forbidden privacy classifications. Generated structured IO handles
are fresh only when derived from the current `structuredIO` schemas.

Package-check must be able to prove row bounds from package metadata before a
rowset participates in the first executable slice. If package-check cannot prove
row bounds, the package is outside this first slice.

## Executable Path Without Runtime JSON

The executable path is:

1. The host owns rich objects, private payloads, network/browser/platform state,
   and JSON decoding.
2. The host converts rich objects into bounded scalar rowset fixtures or
   generated binding inputs.
3. AIR receives scalar IDs, enum IDs, flags, scores, counters, and other
   minimized scalar fields through a generated fixed layout.
4. AIR performs deterministic scalar decisions.
5. AIR output is represented as scalar output IDs, command buffer records, or
   bounded `output.emit` records already covered by existing contracts.
6. Conformance fixtures prove the deterministic input/output path without
   giving AIR runtime JSON or host authority.

This path is executable because the generated fixed layout maps schema-declared
fields to scalar values before AIR execution. AIR never parses JSON, receives
runtime objects, or dereferences host-owned objects.

## Structured Output Summary

Bounded structured output summary is a review/evidence model, not a new Host
ABI feature. It may summarize Output Contracts, command buffers, bounded
`output.emit`, generated output handles, and conformance evidence.

It must not mean:

- `output.emit` payload objects;
- `output.event`;
- host side-effect expansion;
- Host ABI `0.12`;
- automatic host-side action execution.

First-slice structured output remains scalar IDs and handles plus bounded
summaries as package/evidence/tooling contracts. Host-owned rich execution stays
outside AIR.

## Generated Field Handles / Offsets / Bindings

Generated artifacts may provide:

- stable field constants;
- scalar offsets into host-owned encoded records;
- deterministic metadata for host bindings;
- freshness checks.

They must not add hidden host imports, hidden compiler exports, runtime object
semantics, or authority.

## Evidence / Diff / Replay

Reports expose:

- schema paths and hashes;
- record names and field summaries;
- row bounds;
- generated binding freshness;
- output summary metadata;
- diagnostics.

Package diff should expose schema, output summary, generated binding, capability,
effect, and Host ABI deltas where relevant.

Replay compares deterministic scalar rowset records using existing batch
conformance fixture shape. Structured IO rowsets are schema sources for bounded
row validation; replay summaries include mismatch kinds without raw private
payloads.

## ABI Decision

AIR ABI remains `0.10` as long as the first slice does not change executable
calling conventions, exported function signatures, runtime memory contracts, or
host/runtime interpretation of AIR executable metadata.

Metadata, generated binding metadata, validation, reporting, evidence, diff,
replay, and LSP diagnostics alone do not require an AIR ABI bump.

Host ABI remains unchanged. Host ABI changes are required only if new host
imports or host-visible runtime structured IO semantics are accepted separately.

## Kill Criteria

Stop the implementation if it requires:

- runtime JSON;
- dynamic objects/maps;
- host object handles;
- strings/private payloads as AIR data;
- generated artifacts as source of truth;
- tablegroup syntax;
- declared mutable pools;
- Host ABI expansion;
- package-check unable to prove row bounds.

## Acceptance Checklist

- scalar-only schemas;
- fixed bounds;
- privacy classification;
- generated binding freshness;
- report/evidence/diff/replay visibility;
- negative tests for JSON/object drift;
- FlowDesk-style fixture shape accepted;
- lan-observer-style fixture shape accepted;
- package-check can prove row bounds;
- AIRON tablegroup pressure remains metadata/RFC only.

Implemented first-slice test coverage:

- FlowDesk-style task summary schema and conformance fixture pass without raw
  notes, raw URLs, browser authority, or private text in AIR.
- lan-observer-style observation schema and conformance fixture pass without raw
  packet payloads, network authority, dynamic maps, or host object handles.
- negative JSON/object drift tests reject string/object/nested fields and stale
  generated bindings;
- package-check rejects structured rowsets without `maxRows`.
