# AIR v0.23 RFC: Fixed Bounded State Segment Implementation First Slice

Status: RFC / implementation plan

Purpose: define the minimal implementation path for Fixed Bounded State Segment
after v0.22 established the backend-neutral semantic model, API gates, and ABI
decision boundaries.

This RFC does not implement state segments by itself. It does not change parser,
verifier, lowering, AIR ABI, Host ABI, host authority, Output Contracts,
command buffers, demos, or examples.

This plan follows:

- [AIR v0.22 RFC: Fixed Bounded State Segment](v0.22-fixed-bounded-state-segment.md)
- [AIR v0.23 Decision: Fixed Bounded State ABI](v0.23-fixed-state-abi-decision.md)

## 1. Scope

P0 implementation target:

- fixed-size AIR-owned state segments;
- `i32` cells only;
- compile-time literal length only;
- zero or fill-literal initialization;
- per AIR execution instance / package execution instance persistence;
- `state.len`;
- `state.get`;
- `state.set`;
- verifier accounting for read/write budgets;
- report/evidence metadata;
- conformance final-state digest.

## 2. Chosen First-Slice Syntax

Candidate syntax for implementation:

```air
state board:i32[200] = fill 0
```

Operation syntax:

```air
%len:i32 = state.len board
%cell:i32 = state.get board, %idx
state.set board, %idx, %value
```

Rules:

- `state` declarations are module-level.
- State names share the module namespace with globals, tables, constants, and
  functions where collisions would be ambiguous.
- Length must be a positive integer literal.
- Cell type is `i32` only in P0.
- Initializer is `fill 0` or `fill <i32 literal>`.
- State is mutable only through `state.set`.
- State is not exported as memory, pointer, slice, reference, object, JSON, or
  host handle.

The first parser slice uses bare state names, matching the existing static table
operand style.

## 3. Operations

| Operation | Result | P0 rule |
| --- | --- | --- |
| `state.len name` | `i32` | Returns compile-time fixed length as an `i32` value. |
| `state.get name, idx` | `i32` | Reads one `i32` cell. Static OOB fails. Dynamic indexes lower to a deterministic bounds check/trap. |
| `state.set name, idx, value` | none | Writes one `i32` cell. Static OOB fails. Dynamic indexes lower to a deterministic bounds check/trap. |

P0 excludes:

- `state.fill` unless separately accepted;
- `state.swap`;
- compact state cells;
- bool state cells;
- tablegroups;
- host direct state reads/writes.

## 4. Verifier Model

Verifier must prove or enforce:

- fixed state length;
- deterministic initialization;
- no uninitialized cells;
- `i32` cell type only;
- no pointer, slice, reference, object, JSON, or host handle escape;
- static out-of-bounds rejection;
- dynamic bounds check or deterministic trap;
- state read/write budget upper bounds;
- loop upper-bound multiplied state read/write accounting;
- no dynamic allocation or resizing;
- no aliasing between named state segments;
- no host direct state access;
- no state-conditional Output Contract declarations.

Budget model:

- `state.len` counts as metadata read only if the verifier/report policy decides
  to count it; the first implementation must document the choice.
- `state.get` increments state read usage.
- `state.set` increments state write usage.
- Loops multiply read/write usage by verifier-known upper bounds.
- Unknown or unbounded loop effects fail.

## 5. Lowering Model

AIR semantics are backend-neutral. The current Wasm first slice lowers each
`i32` state cell to a private mutable Wasm global:

```wat
(global $__air_state_board_0 (mut i32) (i32.const 0))
```

This representation is intentionally conservative. It avoids placing state in
exported linear memory, so existing user-visible memory, slice, and buffer
operations cannot alias state storage. State global names are compiler-managed,
not exported, and are not AIR-visible addresses.

Lowering rules:

- `state.len` lowers to an `i32.const` length.
- static `state.get` lowers to `global.get` for the selected private cell.
- static `state.set` lowers to `global.set` for the selected private cell.
- dynamic `state.get` and `state.set` first emit a deterministic bounds check;
  out-of-bounds indexes trap with Wasm `unreachable`.
- dynamic in-bounds indexes dispatch over the fixed private cells.
- state persists across exported calls within the same Wasm instance.
- re-instantiating the Wasm module resets state to its fill initializer.

The lowering must not:

- expose raw Wasm pointers to AIR code or hosts;
- export state memory;
- alias state with user-visible dynamic memory in a way the verifier cannot
  reason about;
- introduce shared memory, atomics, or cross-instance state;
- require Host ABI `0.11`;
- require output events or host-side action execution.

Future lowerings may use a compiler-managed memory region only if they can prove
that user-visible memory operations cannot alias state. If aliasing cannot be
prevented by construction, that lowering must stop rather than accept unsafe
state storage.

## 6. Report / Evidence Model

Reports include a `stateSegments` section when state exists:

- module path;
- state segment name;
- cell type;
- length;
- static byte size;
- `persistent: true`;
- `exported: false`;
- `shared: false`;
- initializer kind;
- declared read/write budgets where available;
- `moduleObservedReads` / `moduleObservedWrites` when available;
- diagnostics and budget violations.

Verification evidence includes the same state metadata when package-visible.

Report visibility is not proof. Reports must not imply a verifier property was
proven unless the verifier enforces it.

`moduleObservedReads` and `moduleObservedWrites` are module-level aggregate
counters for the current first slice. They must not be interpreted as per-state
access counts until per-state tracking is implemented.

Dynamic bounds:

- statically visible out-of-bounds `state.get` and `state.set` are verifier
  errors;
- dynamic indexes are accepted and lower to deterministic bounds checks;
- dynamic out-of-bounds traps with Wasm `unreachable`.

## 7. Conformance Model

Conformance final-state digest uses explicit package-authored scalar snapshot
helpers in the first slice. A package may export helpers such as:

```air
export func board_cell(index: i32) -> i32
export func state_digest_word(slot: i32) -> i32
```

The conformance trace lists helper calls, the runner calls those public exports,
and the runner hashes the scalar return values deterministically.

First-slice rules:

- no hidden compiler-generated state export;
- no host direct readback of private state globals;
- no pointer, slice, or reference export;
- no raw state dump by default;
- no Host ABI or AIR ABI change;
- digest input excludes wall-clock time, randomness, local environment, and host
  private data.
- helpers must be observation-only: they must not write state, write globals or
  memory, write command buffers, call host imports, use `debug.metric` as an
  event/output path, or otherwise mutate package-visible state.
- generated state handles/accessors may improve ergonomics later, but they must
  remain explicit package-visible AIR code rather than hidden compiler exports.

Conformance supports:

- deterministic final state digest;
- expected digest comparison;
- mismatch diagnostics for digest mismatch, trap mismatch, budget violation,
  unsupported profile, and static verifier failure;
- optional explicit exported scalar snapshot helper functions when examples
  need human-readable state checks.

The runner reports helper names, arguments, status, observed digest, and expected
digest. It does not report raw helper return values by default.

Conformance must not require:

- host state read API;
- wall-clock time;
- randomness;
- local environment dependency;
- private host data;
- raw snapshots as Host ABI.

## 8. ABI Decision Gate

Host ABI remains `0.10`.

AIR ABI remains `0.10` if Fixed Bounded State Segment is an internal AIR
semantic surface lowered behind existing package execution boundaries and does
not change public entrypoints, calling convention, runtime package contract, or
host/runtime-required executable metadata.

Stop and report before implementation if:

- state layout becomes externally visible runtime/package contract;
- host/runtime must understand new executable metadata to instantiate packages;
- state snapshots become public ABI;
- exported function ABI changes;
- command buffer or Output Contract semantics become state-conditional.

AIR ABI `0.11` requires a separate accepted decision record.

## 9. Kill Criteria

Stop or reject the implementation if it requires:

- runtime-sized state;
- dynamic collections;
- JSON, object, or map state;
- compact state in P0;
- silent truncation;
- pointer, slice, or reference escape;
- host direct state access;
- shared mutable state across execution instances;
- atomics or shared memory;
- state-conditional host authority;
- state-conditional Output Contract declarations;
- `output.emit`;
- Host ABI `0.11`;
- Canvas/ImageData/pixel-buffer authority;
- game-specific Core APIs;
- report claims that treat visibility as proof.

## 10. Test Plan

Required tests before implementation can be accepted:

- valid `i32` state declaration with `fill 0`;
- valid `i32` state declaration with non-zero fill literal;
- `state.len` returns `i32`;
- `state.get` returns `i32`;
- `state.set` mutates per-instance state;
- static OOB `state.get` fails verifier;
- static OOB `state.set` fails verifier;
- dynamic OOB traps deterministically or requires explicit bounds proof;
- loop read/write accounting multiplies by upper bound;
- unbounded loop state access fails;
- no pointer/slice/reference escape;
- report exposes `stateSegments` metadata;
- conformance final-state digest is deterministic;
- re-instantiation resets state;
- AIR ABI remains `0.10`;
- Host ABI remains `0.10`.

## 11. Phase Acceptance

| Phase | Scope | Acceptance |
| --- | --- | --- |
| Phase 1 | Parser/formatter and diagnostic taxonomy. | Syntax round-trips deterministically, unsupported forms are diagnosed or rejected, and no lowering/ABI behavior is implied. |
| Phase 2 | Verifier/report/evidence. | Verifier distinguishes proof/enforcement from report visibility and exposes `stateSegments` as tooling metadata only. |
| Phase 3 | Wasm lowering with memory isolation. | Lowered programs preserve state semantics through private mutable Wasm globals, dynamic out-of-bounds traps deterministically, and user-visible memory operations cannot alias state. |
| Phase 4 | Conformance final digest. | Replay evidence is deterministic and does not require host state read APIs or runtime JSON. |
| Phase 5 | RC scope audit. | Checks confirm no compact state, tablegroups, output events, Host ABI `0.11`, AIR ABI `0.11`, or state export/escape entered the release. |
