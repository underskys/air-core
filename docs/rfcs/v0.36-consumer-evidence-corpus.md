# RFC v0.36: Consumer Evidence Corpus & Demo Pressure Intake

Status: proposed / planning

Target milestone: v0.36

## Purpose

Define a standardized evidence and pressure intake layer for downstream demos
and consumer projects.

AIR Core review bundles prove the compiler, verifier, reports, conformance,
benchmarks, API gates, and package tooling. Consumer evidence bundles prove that
AIR survives pressure from downstream domains without letting those domains
directly define Core ABI or smuggle raw host authority into AIR.

This RFC is docs/planning only. It does not add language features, AIR ABI
changes, Host ABI changes, game-specific APIs, raw host authority, external demo
source code, or large demo assets.

## Design Principle

Demos are pressure. Core is law.

Consumer evidence can motivate work, but implementation must still route
through architecture review, RFCs, API gates, compatibility policy, verifier
semantics, evidence/report visibility, and conformance expectations.

## Directory Structure

The proposed corpus root is:

```text
consumer_evidence/
  README.md
  DEMO_REGISTRY.json
  proofs/
    <consumer-id>/
      proof-card.json
      demo-manifest.json
      replay-summary.json
      evidence-summary.json
      pressure-routing.json
```

Initial v0.36 scope defines this structure. Adding the actual validator and
seed files should happen only after the docs/schema shape is accepted.

## `DEMO_REGISTRY.json` Schema

The registry lists evidence sources, not imported demo projects.

Required fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `schemaVersion` | string | Corpus registry schema version. |
| `kind` | string | Must be `air.consumerEvidenceRegistry`. |
| `entries` | array | Registered consumer evidence entries. |

Each entry:

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | Stable corpus id such as `lan_observer_readonly`. |
| `displayName` | string | Human-readable name. |
| `domain` | string | Domain label such as `network-observation`, `game-demo`, `ops`, or `policy`. |
| `status` | string | `active`, `proposed`, `deferred`, or `archived`. |
| `proofCard` | string | Relative path to proof card. |
| `ownerLayer` | string | `Core`, `stdlib`, `kit`, `host-adapter`, `demo-local`, or `external`. |
| `lastReviewedMilestone` | string | Last AIR milestone that reviewed the evidence. |
| `safetySummary` | object | High-level allowed/denied authority summary. |

Registry entries must not include raw URLs, tokens, local absolute paths,
secrets, or private text.

## Proof Card Schema

Proof cards summarize what a downstream pressure source demonstrates.

Required fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `schemaVersion` | string | Proof card schema version. |
| `kind` | string | Must be `air.consumerEvidenceProofCard`. |
| `id` | string | Stable proof id. |
| `title` | string | Human-readable proof title. |
| `sourceType` | string | `core-example`, `external-demo`, `consumer-project`, or `pressure-summary`. |
| `summary` | string | Short sanitized description. |
| `surfacesExercised` | array | AIR surfaces exercised, such as structured IO, output contracts, replay, benchmark, eval. |
| `allowedCapabilities` | array | Capabilities the proof intentionally exercises. |
| `deniedAuthorities` | array | Authorities explicitly denied. |
| `artifacts` | array | Relative evidence artifact paths. |
| `routing` | array | Pressure routing decisions. |
| `limitations` | array | What this proof does not demonstrate. |

Proof cards are summaries. They must not embed large logs, media, raw private
payloads, raw URLs, secrets, tokens, local absolute paths, or demo source.

## Demo Manifest Schema

The demo manifest records evidence boundaries for a downstream domain.

Required fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `schemaVersion` | string | Manifest schema version. |
| `kind` | string | Must be `air.consumerEvidenceDemoManifest`. |
| `consumerId` | string | Matches registry entry. |
| `domain` | string | Domain classification. |
| `capabilitiesUsed` | array | Allowed AIR/package capabilities used by the evidence. |
| `authoritiesDenied` | array | Explicitly denied host authorities. |
| `hostOwnedState` | array | Host-owned rich state categories. |
| `airOwnedLogic` | array | AIR-owned bounded deterministic logic categories. |
| `evidenceArtifacts` | array | Relative paths to summarized evidence artifacts. |
| `pressureRequests` | array | Requested changes with route hints. |
| `privacyBoundary` | object | Forbidden private/raw data classes. |

The manifest must make the host/AIR boundary explicit.

## Replay/Evidence Summary Schema

Replay/evidence summaries provide small deterministic review facts.

Required fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `schemaVersion` | string | Summary schema version. |
| `kind` | string | `air.consumerEvidenceReplaySummary` or `air.consumerEvidenceSummary`. |
| `consumerId` | string | Registry id. |
| `status` | string | `passed`, `failed`, `not_run`, or `unsupported`. |
| `packageCheck` | object | Status and diagnostic code counts, if available. |
| `verification` | object | Status and diagnostic code counts, if available. |
| `replay` | object | Fixture id, status, checksum, mismatch summary, if available. |
| `evidenceReport` | object | Status and privacy summary, if available. |
| `benchmark` | object | Benchmark id, status, available metric names, if available. |
| `aiEval` | object | Eval case id, status, repair result, if available. |
| `limitations` | array | Known gaps. |

Summaries should expose metadata and diagnostics, not raw rows or private
payloads by default.

## `check:consumer-evidence` Validator

The planned validator should:

- validate `DEMO_REGISTRY.json`;
- validate proof cards;
- validate demo manifests;
- validate replay/evidence summaries;
- reject local absolute paths;
- reject raw URLs unless explicitly represented as redacted external references;
- reject secrets, tokens, credentials, private text, and raw private payloads;
- reject large logs and large assets;
- verify referenced files stay inside `consumer_evidence/`;
- verify every pressure request has a route;
- verify every proof lists allowed capabilities and denied authorities.

The npm script should be named:

```sh
npm run check:consumer-evidence
```

Implementation is not part of the initial docs-only plan unless separately
approved.

## Separate Consumer Evidence Bundle

Consumer evidence bundles are separate from Core review bundles.

Core review bundles answer:

- Did compiler/verifier/report/package-check/API gates pass?
- Did Core source and docs remain safe?

Consumer evidence bundles answer:

- What downstream pressure was observed?
- Which AIR surfaces were exercised?
- What authority was denied?
- What route does each pressure item take?

Consumer evidence bundles must not include full demo bundles, large assets,
browser smoke artifacts, `node_modules`, external source trees, secrets, tokens,
or raw private data.

## Demo-side Contribution Rules

Downstream demos and consumer projects may contribute evidence summaries if:

- evidence is small and deterministic;
- artifacts are sanitized;
- allowed capabilities are listed;
- denied authorities are listed;
- raw host/platform data is summarized or redacted;
- pressure requests are routed explicitly;
- no demo-specific API is presented as Core authority;
- no local absolute paths, raw URLs, tokens, secrets, private notes, or large
  logs are included.

## Pressure Routing Rules

Every pressure item must be routed to exactly one of:

| Route | Rule |
| --- | --- |
| Core | Generalized language/package/verifier/report mechanism. Requires RFC/gates. |
| stdlib | Generic helper/library surface, not host authority. |
| kit | Domain/project kit convention outside Core semantics. |
| host adapter | Host-owned integration or policy behavior. |
| demo-local | Remains local to the downstream project. |
| rejected | Not accepted due to authority, privacy, ABI, slop, or domain-specific risk. |

Accepted pressure must not skip architecture review.

## Seed Candidates

### lan-observer read-only proof

Route: Core proof evidence.

Use a summary of `examples/lan_observer_readonly_package/` and its existing
evidence/replay/benchmark/AI-eval coverage. Do not duplicate package files in
the consumer evidence corpus.

### AIRON pressure summary

Route: pressure-only evidence.

Summarize tablegroup, authored package composition, declared pool, resource
validation, and kit pressure. Do not import AIRON source, assets, screenshots,
browser artifacts, or game-specific APIs into Core.

### AirOps / FlowDesk

Route: optional existing evidence summary only.

Use only evidence already present in the repo. Do not import product scope or
external code.

## Deferred

- full demo bundles in Core;
- large assets;
- browser smoke artifacts;
- `node_modules`;
- production host adapters;
- demo-specific Core APIs;
- automatic roadmap changes from demo pressure;
- media ingestion beyond hashes/links;
- external demo evidence ingestion beyond documented summaries.

## Kill Criteria

Stop if the corpus design:

- imports external demo source into Core;
- turns demo pressure into direct ABI authority;
- accepts raw host authority;
- includes secrets, tokens, raw private data, raw URLs, local absolute paths, or
  large logs;
- creates game-specific Core APIs;
- bypasses RFC/gates;
- allows automatic roadmap changes from demo pressure.

## ABI Decision

AIR ABI remains `0.10`.

Host ABI latest remains `0.11`, limited to bounded `output.emit`; Host ABI
`0.10` remains the default/baseline compatibility target for packages that do
not use `output.emit`.

The consumer evidence corpus is docs/tooling/review metadata. It does not
require AIR ABI or Host ABI changes.
