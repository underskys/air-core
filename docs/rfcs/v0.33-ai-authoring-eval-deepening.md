# RFC: v0.33 AI Authoring Eval Deepening

Status: proposed for v0.33 P0

Milestone: v0.33

Layer: eval tooling / diagnostics evidence / review surface

## Purpose

v0.33 expands the deterministic AI authoring eval replay harness created in
v0.32. The goal is to measure how well AI-authored AIR stays inside the
verified Core surface, how quickly common diagnostics can be repaired, and how
often forbidden surfaces appear in captured outputs.

This is not a live model integration milestone. P0 remains replay-only.

## Current Baseline

v0.32 added:

- `airc eval-ai` replay mode;
- deterministic captured model output fixtures;
- captured repair transcript fixtures;
- replay metrics;
- no live model calls, API keys, network, timestamps, or nondeterministic CI
  output.

v0.33 keeps that boundary and expands corpus coverage and reporting.

The first v0.33 corpus expansion adds replay fixtures for:

- a valid small scalar module;
- a fixed state module;
- a bounded `output.emit` module using a static handle/id path;
- a valid bounded structured IO module;
- runtime JSON hallucination;
- dynamic object/map hallucination;
- dynamic `output_id` hallucination;
- raw host authority hallucination;
- a repairable invalid module that succeeds on the first captured repair.

## P0 Eval Corpus

The v0.33 corpus should include deterministic captured fixtures for:

- incident policy modules;
- structured IO modules;
- bounded `output.emit` modules;
- fixed state modules;
- generated handle usage;
- forbidden surface negative cases.

Forbidden surface cases must include:

- runtime JSON;
- dynamic objects;
- host object handles;
- dynamic `output_id`;
- raw host authority.

Fixtures must be source-controlled, deterministic, and safe for review bundles.
They must not contain API keys, tokens, secrets, private notes, raw private URLs,
large logs, live model API payloads, or absolute local paths.

Each case may declare expected replay constraints in
`evals/ai_authoring/expected/constraints.json`, including:

- first-pass verify status;
- first-pass package-check status;
- required diagnostic codes;
- expected repair success iteration;
- forbidden surface category when applicable.

Replay must fail with `air.eval_ai.expected_mismatch` if captured fixture
results drift away from those expectations.

## Replay-Only P0

P0 eval execution must:

- read captured prompts, model outputs, and repair transcripts;
- run local verifier/package-check/report surfaces;
- compute deterministic metrics;
- avoid live provider calls;
- avoid API keys;
- avoid network;
- avoid wall-clock timestamps in output;
- avoid nondeterministic CI behavior.

Live model eval design may be documented as P1, but live execution is deferred.

## Repairability Metrics

v0.33 eval reports should track:

- first-pass verify rate;
- first-pass package-check rate;
- repair success at 1;
- repair success at 3;
- average repair iterations;
- forbidden surface rate;
- top diagnostic codes;
- diagnostic repair hint coverage.

Metrics should be computed from replay fixtures only. The report should make it
clear that these numbers describe the captured corpus, not global model quality.

## Diagnostic Repair Hint Coverage

Repair hint coverage answers whether high-value diagnostics expose actionable,
stable guidance to an AI authoring loop.

P0 should prioritize diagnostics tied to:

- structured IO schema rejection;
- runtime JSON/object drift;
- dynamic maps;
- host object handles;
- dynamic output ids;
- raw host authority;
- fixed state bounds;
- output contract violations;
- generated artifact freshness.

Repair hints must remain suggestions. v0.33 does not add automatic code actions
or automatic repair.

The first repairability slice adds stable hints for current eval top
diagnostics and nearby high-value diagnostics:

- runtime JSON rejection;
- dynamic object/map rejection;
- dynamic and invalid `output_id`;
- unsupported Host ABI/profile for `output.emit`;
- structured IO schema and field type failures;
- generated handle stale/missing/mismatch failures;
- raw host authority rejection;
- host object handle rejection;
- `debug.metric` event-bus misuse.

Eval reports expose:

- `metrics.diagnosticRepairHintCoverage`;
- `metrics.diagnosticRepairHintCoverage.missingRepairHints`;
- per-case `diagnosticDetails[]` with diagnostic code and repair hint.

Missing hints are allowed, but they are visible so repairability can be tracked
over time.

## Eval Regression Report

The v0.33 first slice is implemented as deterministic replay regression output:

```sh
node bin/airc.js eval-ai evals/ai_authoring --json --regression
```

It emits `air.aiAuthoringEvalRegressionReport` and summarizes:

- corpus id or fixture set;
- metric values;
- changed diagnostic coverage;
- changed forbidden surface rate;
- repair transcript pass/fail;
- new or removed top diagnostic codes;
- limitations.

If no prior baseline fixture is provided, the report sets `previousMetrics` to
`null`, emits empty `deltas` and `changedTopDiagnosticCodes`, and includes the
limitation `no prior baseline provided`. It does not invent historical data.

Reports are deterministic, path-normalized, and safe for review bundles. They
contain no timestamps, absolute paths, API keys, provider metadata, live model
information, or network data.

## Safety and Privacy

Eval artifacts must not include:

- live API keys;
- tokens or secrets;
- raw private URLs;
- private notes or private text;
- raw host data;
- absolute local paths;
- wall-clock timestamps;
- nondeterministic provider metadata.

Captured outputs are fixtures, not live telemetry.

## P1 Design Only

P1 may define designs for:

- live model eval mode;
- model-by-model comparison;
- repair transcript viewer;
- deeper fuzz/eval corpus;
- parser roundtrip fuzz planning.

P1 design must not introduce live provider calls, network, API keys,
nondeterministic CI, code actions, or automatic repair in v0.33.

## Deferred

- live AI provider calls;
- provider credentials;
- network;
- nondeterministic CI;
- automatic code actions;
- automatic repair;
- model ranking claims from insufficient corpus evidence;
- new language syntax;
- Host ABI expansion.

## Acceptance Criteria

Before v0.33 closes, the eval deepening work should provide:

- expanded deterministic corpus fixtures;
- structured IO, `output.emit`, fixed state, and forbidden surface cases;
- repairability metric output;
- diagnostic repair hint coverage summary;
- eval regression report;
- review bundle visibility for deterministic fixtures and reports;
- explicit limitations for corpus size and representativeness.

## ABI Impact

No AIR ABI change is expected.

No Host ABI change is expected.

Eval fixtures exercise existing package/tooling surfaces and must not add host
imports or runtime authority.
