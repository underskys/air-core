# RFC v0.38: AI Eval Capture/Import Mode

Status: implemented / P0

Target milestone: v0.38

## Purpose

Define a safe way to measure real model outputs without making Core CI
nondeterministic.

v0.38 allows `eval-ai` to import captured model outputs from files and compute
the existing replay metrics. It does not call live provider APIs, require API
keys, use network access, or add provider SDK dependencies.

The implemented command is:

```sh
node bin/airc.js eval-ai import <capture-dir> --json
```

It emits `kind: air.aiAuthoringEvalImportReport`.

## Model

The capture/import model has two separate phases:

1. Capture phase outside Core CI:
   - a human or external script obtains model outputs;
   - outputs are saved as deterministic files;
   - secrets, tokens, provider metadata, raw private prompts, and network logs
     are stripped before import.
2. Import/replay phase inside Core:
   - `eval-ai` reads captured files;
   - validates file shape and safety constraints;
   - computes eval metrics deterministically;
   - produces the same style of report as replay fixtures.

Only the import/replay phase is in v0.38 P0.

## Capture Directory Shape

```text
capture-dir/
  MANIFEST.json
  model_outputs/*.json
  repair_transcripts/*.json
  constraints.json optional
```

`MANIFEST.json` uses `kind: air.aiAuthoringEvalCapture` and schema version
`0.38`. It lists stable case ids and relative paths under `model_outputs/` and
optional `repair_transcripts/`. The importer reads only local files and reports
relative paths.

## Allowed Inputs

Captured files may include:

- prompt id;
- model output text or generated AIR source if review-safe;
- package-check/verifier diagnostics from replay;
- repair transcript steps if deterministic and sanitized;
- expected constraints metadata.

Captured files must not include:

- API keys;
- tokens;
- provider request ids;
- account ids;
- raw private prompts;
- raw URLs;
- network logs;
- timestamps required for correctness;
- nondeterministic provider metadata.

## Metrics

Imported captures should feed existing AI authoring metrics:

- first-pass verify rate;
- first-pass package-check rate;
- repair success at 1;
- repair success at 3;
- average repair iterations;
- forbidden surface rate;
- top diagnostic codes;
- diagnostic repair hint coverage;
- hallucination category counts.

## Determinism

Reports have deterministic JSON shape and stable ordering. CI does not depend
on live model availability, provider latency, network state, or API key
configuration.

## Safety Gates

The importer rejects or fails safely on:

- secret-like content;
- provider SDK dependency in Core;
- network access;
- live provider call paths;
- raw host authority suggestions not classified as rejected/forbidden;
- runtime JSON/object drift not classified as a negative case.

The importer also rejects provider request ids, account ids, provider metadata,
raw private prompts, raw URLs, timestamps, absolute paths, and secret-like
content.

## Non-goals

- live model API integration;
- automatic repair;
- code actions;
- provider SDK dependencies;
- model-by-model leaderboard claims;
- nondeterministic CI.

## ABI Decision

AI eval capture/import is tooling only. It does not change AIR ABI or Host ABI.
