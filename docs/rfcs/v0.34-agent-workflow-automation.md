# AIR v0.34 Agent Workflow Automation RFC

Status: proposed / v0.34 P0 planning

## Purpose

AIR Core review work now has a repeatable shape:

- preflight branch and dirty-state checks;
- task-scoped edits;
- full check set;
- RC review results;
- review bundle sanity;
- clear final report.

Manual repetition is error-prone. v0.34 should add a small `agent:finish`
workflow that automates the final handoff without adding language features or
changing review policy.

## Non-goals

- no compiler semantic changes;
- no AIR ABI change;
- no Host ABI change;
- no language features;
- no live AI provider calls;
- no network dependency;
- no automatic code repair;
- no merge automation;
- no CI enforcement in the first slice;
- no demo changes.

## Proposed Command

```sh
npm run agent:finish
```

The npm script should call a checked-in script, for example
`scripts/agent_finish.js` or `scripts/agent_finish.sh`.

## P0 Workflow

The first slice should perform:

1. preflight git checks;
2. expected branch report;
3. dirty working tree check;
4. full Core check set;
5. RC check run;
6. review bundle sanity;
7. `MOBILE_SUMMARY.md` generation;
8. `REVIEW_REQUEST.md` generation;
9. final status summary.

## Preflight Checks

The script should report:

```sh
git fetch origin --prune
git branch --show-current
git rev-parse --short HEAD
git status --short
node -v
npm -v
```

If the Core working tree is dirty, the script should stop unless an explicit
debug/planning override is provided. Dirty demo paths should continue to follow
the existing Core/demo separation policy rather than weakening Core review
bundle rules.

## Full Check Set

The script should run the current branch-appropriate checks, including:

```sh
npm test
npm run test:bundle
npm run check:api-gates:v0.21
npm run check:api-gates:v0.22
npm run check:api-gates:v0.26
npm run check:api-gates:v0.27
npm run check:api-gates:v0.28
npm run check:api-gates:v0.32
npm run check:api-gates:v0.33
bash scripts/run_rc_checks.sh
node scripts/check_review_bundle.js --keep
node scripts/check_markdown_links.js
node scripts/check_abi_requests.js
node test/layer_guard.test.js
git diff --check
```

The exact list should remain data-driven where possible so older branches do
not fail when a future gate is absent.

## `MOBILE_SUMMARY.md`

`MOBILE_SUMMARY.md` should be short enough to read on a phone. It should
include:

- branch;
- commit;
- dirty status;
- short summary of changed files;
- commands run and pass/fail;
- RED_FLAGS status;
- AIR ABI status;
- Host ABI status;
- remaining blockers.

It must not include raw logs, private payloads, secrets, tokens, or absolute
machine-local paths beyond deliberate review artifact paths.

## `REVIEW_REQUEST.md`

`REVIEW_REQUEST.md` should be a reviewer-ready prompt. It should include:

- scope;
- explicit non-goals;
- files changed;
- evidence bundle path;
- key commands and outcomes;
- review questions;
- ABI status;
- Host ABI status;
- forbidden implementation checklist.

The first slice should generate a generic review request. Model-specific
Claude/GPT prompt templates remain P1.

## Review Bundle Inclusion

Review bundles should include `MOBILE_SUMMARY.md` and `REVIEW_REQUEST.md` once
the files are generated by the finish workflow.

The bundle must still reject dirty Core snapshots unless explicitly marked as
debug/planning output.

## Safety Requirements

The finish workflow must:

- not run live AI provider calls;
- not require API keys;
- not use network services except normal `git fetch`/`npm` operations already
  required by existing workflow;
- not mutate source files except generated review summaries;
- not auto-commit;
- not auto-merge;
- not force-push;
- not change AIR ABI or Host ABI.

## Acceptance Criteria

Before v0.34 closes:

- `npm run agent:finish` exists;
- the command stops on dirty Core state;
- the command runs the full check set or reports a clear failure;
- `MOBILE_SUMMARY.md` and `REVIEW_REQUEST.md` are deterministic enough for
  review;
- review bundles include both summary files;
- `RED_FLAGS` remains the source of truth for RC blockers.
