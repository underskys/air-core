# AIR v0.24 RFC: Generated State Handles

Status: RFC / P0 first slice implemented for generated constants, metadata,
freshness, report/evidence, and package diagnostics

Purpose: define how AIR may generate reviewable state handle artifacts and
validate package-authored state accessors for Fixed Bounded State without
adding hidden ABI, host authority, or runtime object semantics.

The implemented first slice generates constants and sidecar metadata only. It
does not generate accessor functions. It does not change parser, verifier,
lowering, AIR ABI, Host ABI, host imports, output events, examples, or demos.

## 1. Background

v0.23 implemented the first Fixed Bounded State executable slice. The syntax is
intentionally low-level and explicit:

```air
state board:i32[200] = fill 0
%cell:i32 = state.get board, %idx
state.set board, %idx, %value
```

Manual helper exports such as `board_cell(idx) -> i32` work, but they create
AI-slop pressure: repeated magic indexes, stale helper names, unclear digest
helpers, and review difficulty when state declarations change.

v0.24 improves ergonomics through package-visible generated handle constants,
metadata sidecars, freshness checks, report/evidence mapping, LSP diagnostics,
and validation of package-authored accessor helpers.

## 2. P0 Scope

P0 includes:

- generated state handle constants;
- generated metadata sidecar;
- package-check freshness checks;
- report/evidence visibility;
- LSP diagnostics for missing, stale, or mismatched state handles through
  package-check diagnostics;
- accessor policy validation model for package-authored helpers.

P0 must not include:

- automatically generated public accessor functions;
- hidden compiler exports;
- hidden state snapshots;
- hidden state dumps;
- host direct state access;
- compact state;
- tablegroups;
- `output.emit`;
- Host ABI `0.11`.

## 3. Source Of Truth

State declarations are the source of truth.

Generated handles are derived artifacts. Generated handles must not become the
source of truth. If generated handles disagree with source state declarations,
package-check must diagnose stale or mismatched generated state handles.

The source state declaration controls:

- state name;
- state identity;
- cell type;
- fixed length;
- static byte size;
- initialization form.

Generated handle files only mirror that information for ergonomic use and
review.

## 4. Generated Files

### `generated/state_handles.air`

The generated AIR file contains constants only in P0. Example constants:

```air
module generated_state_handles

const STATE_BOARD_ID:i32 = 1
const STATE_BOARD_LEN:i32 = 200
const STATE_BOARD_BYTES:i32 = 800
const STATE_BOARD_CELL_I32:i32 = 1
```

P0 generated handle constants are package-visible AIR source. They are imported
through existing package-local module graph rules, and verifier/report/LSP can
inspect them.

Generate these files with:

```sh
node bin/airc.js generate state-handles <package-dir>
```

P0 does not automatically generate public accessor functions. If a package has
helpers such as `board_cell(idx)`, those helpers are authored by the package
and validated through an accessor policy.

### `generated/state_handles.meta.json`

The generated metadata sidecar records deterministic provenance. Required
fields:

```json
{
  "schemaVersion": "0.24",
  "kind": "air.generatedStateHandles",
  "generator": "airc state-handles",
  "sourceModules": [
    {
      "path": "src/main.air",
      "fingerprint": "sha256:..."
    }
  ],
  "states": [
    {
      "name": "board",
      "id": 1,
      "cellType": "i32",
      "length": 200,
      "byteSize": 800
    }
  ],
  "generatedFiles": [
    {
      "path": "generated/state_handles.air",
      "fingerprint": "sha256:..."
    }
  ]
}
```

Metadata must be deterministic. It must not contain timestamps, absolute paths,
local environment data, host-private data, raw state values, or backend
addresses.

## 5. Manifest / Generated Artifact Integration

Prefer reusing the existing generated artifact freshness machinery where
possible.

The implemented integration model:

- package metadata lists `generated/state_handles.air` in existing
  `generatedModules`;
- package-check reads the generated AIR file and sidecar metadata;
- package-check compares source fingerprints and generated file fingerprints;
- report and verification evidence include `stateHandleSets` metadata;
- LSP consumes the same diagnostics.

No new package manifest field is added for the first slice. If a future slice
proposes a new package manifest field, the proposal must document why the
existing generated artifact model is insufficient.

## 6. Accessor Policy

P0 validates package-authored helpers only. It does not generate those helper
functions automatically.

Accessor policy file:

```json
{
  "schemaVersion": "0.24",
  "kind": "air.stateAccessorPolicy",
  "helpers": [
    {
      "name": "board_cell",
      "state": "board",
      "mode": "readCell",
      "exported": true,
      "observationOnly": true
    }
  ]
}
```

The file path for the P0 slice is package-root
`state_accessors.policy.json`. It is auto-detected by package-check/report and
is not a manifest entry.

Validation requirements:

- helper exists;
- helper refers to known state;
- helper is exported if required;
- helper returns a scalar;
- helper is observation-only;
- helper does not call `state.set`;
- helper does not write memory;
- helper does not write globals;
- helper does not write command buffers;
- helper does not call host imports;
- helper does not expose pointers, slices, or references.

Accessor policy validation is a package-check/report/LSP surface. It must not
silently grant authority or bypass verifier rules.

The P0 implementation reuses the same observation-only safety checker used by
final state digest conformance helpers. It is intentionally conservative:
unknown calls, host imports, memory writes, global writes, state writes, and
host output are not observation-safe.

## 7. Safety Rules

This RFC explicitly rejects:

- hidden `__air_state_*` exports;
- hidden `__air_state_dump`;
- hidden `__air_state_digest`;
- raw state dumps;
- host direct read/write access;
- state pointer/slice/reference escape;
- generated code bypassing verifier;
- generated helpers mutating state by default;
- stale handles tolerated in canonical examples;
- runtime JSON/object model;
- hidden runtime package ABI.

Generated code is ordinary visible package code. It must go through verifier,
report, and LSP surfaces like authored AIR.

## 8. Report / Verification Evidence

Reports and verification evidence may include `stateHandleSets`:

- `path`;
- `metadataPath`;
- `status`: `fresh`, `stale`, `missing`, or `mismatch`;
- `sourceFingerprint`;
- `generatedFingerprint`;
- `states[]` with `name`, `id`, `cellType`, `length`, and `byteSize`;
- `diagnostics[]`.

Reports and verification evidence may include `stateAccessorPolicies`:

- `path`;
- `status`;
- `helpers[]` with `name`, `state`, `exported`, `observationOnly`, and
  `status`;
- `diagnostics[]`.

Reports must not include raw state values, backend addresses, hidden state
exports, raw dumps, host object references, pointers, slices, or references.

These fields are tooling/report metadata only. They are not AIR ABI, Host ABI,
runtime package ABI, or host state access.

## 9. LSP Diagnostics

P0 LSP support is diagnostics-only. Both `airc check <file-or-package>
--lsp-json` and the diagnostics-only Full LSP server consume the same
package-check diagnostics for generated state handles and state accessor
policies.

P0 LSP diagnostics:

- missing generated state handles;
- stale generated state handles;
- metadata mismatch;
- invalid accessor policy;
- missing accessor helper;
- unsafe accessor helper.

No code actions in P0. No regenerate-handles code action is exposed. No hover,
go-to-definition, document symbols, or VS Code extension is included in P0
unless explicitly marked deferred or P1 in a future plan.

Diagnostics should include repair hints suitable for AI repair loops, such as
"regenerate `generated/state_handles.air` and
`generated/state_handles.meta.json` from current state declarations".

## 10. Planned Diagnostic Codes

Planned diagnostic codes:

- `air.generated.state_handles_missing`;
- `air.generated.state_handles_stale`;
- `air.generated.state_handles_mismatch`;
- `air.generated.state_metadata_invalid`;
- `air.state.accessor_policy_invalid`;
- `air.state.accessor_missing`;
- `air.state.accessor_export_mismatch`;
- `air.state.accessor_not_observation_safe`;
- `air.state.accessor_unknown_state`;
- `air.state.accessor_return_invalid`.

Diagnostic names are planned surfaces. Implementation must keep severity,
category, repair hint, and package status impact consistent with existing
diagnostic normalization.

## 11. ABI Decision Gate

AIR ABI remains `0.10` if:

- generated handles are package-visible artifacts;
- generated accessors are visible AIR source if ever generated later;
- no hidden compiler exports exist;
- no runtime ABI is required.

AIR ABI `0.11` becomes a candidate if:

- hidden compiler exports are introduced;
- state handles become runtime-required metadata;
- snapshot/restore becomes standardized runtime ABI;
- host/runtime must understand generated accessor metadata.

Host ABI remains `0.10` because generated handles add no host imports, no host
state access, no host-managed state, and no direct state handles.

Host ABI `0.11` remains deferred unless a separate host import or host semantic
change is accepted.

## 12. P0 / P1 / Deferred Split

P0:

- generated constants metadata model;
- freshness model;
- report/evidence model;
- accessor policy validation model;
- LSP diagnostics model.

P1:

- generated observation-only helper stubs/templates;
- state-aware hover/explain;
- repair prompt planning.

Deferred:

- automatic public accessors;
- hidden exports;
- state snapshots as ABI;
- compact state;
- tablegroups;
- Host ABI `0.11`;
- `output.emit`;
- code actions;
- VS Code extension.

## 13. Non-Goals

This RFC does not approve:

- automatically generated public accessor functions in P0;
- compact state;
- tablegroups;
- hidden compiler exports;
- host direct state access;
- state export/pointer/slice/reference escape;
- host-managed snapshot/restore;
- output/audio/effect events;
- Host ABI `0.11`;
- AIR ABI `0.11`;
- code actions or automatic repair;
- VS Code extension work;
- runtime JSON/object model.

## 14. Acceptance For v0.24 P0

- RFC requires generated code to be package-visible.
- P0 scope is constants plus metadata, freshness, report/evidence, accessor
  policy validation, and LSP diagnostics planning.
- P0 does not generate public accessor functions.
- Freshness checking is required before canonical examples depend on generated
  handles.
- Accessor policy validation covers package-authored helpers.
- Report/evidence mapping is metadata only.
- AIR ABI remains `0.10`.
- Host ABI remains `0.10`.
- No accessor, parser, verifier, lowering, AIR ABI, or Host ABI implementation
  is added.
