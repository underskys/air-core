# AIR v0.16 RFC: airpkg Artifact

Status: accepted first-slice design

Target milestone: v0.16

## Purpose

Define the first AIR package artifact contract (`airpkg`) as deterministic,
inspectable metadata for verified authored AIR packages. The v0.16 first slice
is not a full native/web product bundle; it is metadata that target hosts or
later bundlers can inspect before richer artifact forms exist.

## Artifact Goals

The first `airpkg` slice should be:

- deterministic: identical verified inputs produce identical artifact metadata;
- inspectable: tooling can summarize package identity, ABI requirements,
  capabilities, host imports, generated artifacts, manifests, reports, and
  diagnostics without running package source;
- package-check compatible: package-check results map directly into artifact
  metadata and inspection output;
- host-profile aware: artifact metadata records supported/requested profiles,
  host imports, and profile compatibility status;
- runtime/build-time boundary aware: runtime-required files are separated from
  build-time-only tools, source inputs, and generators.

## Scope

- artifact metadata shape;
- package source/report relationship;
- deterministic inspection and check expectations;
- generated artifact and manifest status in artifact metadata;
- ABI decision points before any executable/runtime contract is accepted.

## Artifact Shape

The v0.16 first slice defines a deterministic metadata-only JSON artifact,
optionally stored inside a directory artifact.

Preferred implemented first-slice shape:

```text
dist/app.airpkg.json
```

The same JSON may also be stored as `dist/app.airpkg/airpkg.json` for tools that
want a directory wrapper. The JSON is still the normative artifact in this
slice.

Compressed archive semantics, embedded resources, native app bundles, web
deploys, and Steam-ready product packages are deferred. Compression, tar/zip
ordering, signing, and binary payload normalization are easy places to introduce
non-determinism, so v0.16 stabilizes JSON metadata first.

## Required Metadata

`airpkg.json` must include deterministic fields equivalent to:

```json
{
  "schemaVersion": "0.16",
  "kind": "airpkg",
  "package": {
    "name": "example",
    "version": null,
    "manifestPath": "air.package.json",
    "manifestFingerprint": "sha256:..."
  },
  "sourceGraph": {
    "entrypoint": "src/main.air",
    "modules": [],
    "moduleCount": 0,
    "edgeCount": 0,
    "fingerprint": "sha256:..."
  },
  "abi": {
    "airAbiRequired": "0.10",
    "hostAbiRequired": "0.10",
    "airAbiBumpRequired": false,
    "hostAbiBumpRequired": false
  },
  "hostProfiles": {
    "requested": [],
    "compatible": [],
    "incompatible": []
  },
  "authority": {
    "capabilities": [],
    "hostImports": []
  },
  "generatedArtifacts": [],
  "manifests": [],
  "report": {
    "schemaVersion": "0.15",
    "summaryFingerprint": "sha256:...",
    "reviewSummary": {},
    "diagnosticsSummary": {}
  },
  "linkedWasm": {
    "enabled": false,
    "status": "deferred"
  },
  "linkedOutput": {
    "status": "planned",
    "kind": "link-plan",
    "hash": null,
    "linkPlanHash": "sha256:...",
    "sourceGraphHash": "sha256:...",
    "moduleOrder": [],
    "packageExports": [],
    "hostImports": {},
    "capabilities": {},
    "abiImpact": {}
  },
  "boundary": {
    "runtimeRequired": [],
    "runtimeRequires": [],
    "buildTimeOnly": [],
    "forbiddenAtRuntime": [
      "Node",
      "npm install",
      "Python",
      "source AIR repo",
      "Codex",
      "build scripts"
    ]
  }
}
```

Required metadata categories:

- `schemaVersion`;
- package identity;
- package manifest fingerprint;
- source graph summary;
- entrypoint if available;
- AIR ABI requirement;
- Host ABI requirement;
- host profile requirements;
- capabilities;
- host imports;
- generated artifact fingerprints;
- manifest/resource references;
- report/review summary;
- diagnostics summary;
- `linkedWasm` status;
- `linkedOutput` status, link-plan fingerprint, source graph hash, module order,
  package exports, host imports, capabilities, and ABI impact prediction;
- build-time/runtime boundary fields.

See [Build-Time vs Runtime Boundary](../BUILD_RUNTIME_BOUNDARY.md).

Fingerprints should use a named algorithm prefix such as `sha256:`. A missing
fingerprint must be represented as `null` plus a diagnostic or status field, not
by omitting the field.

## Determinism Rules

- no timestamps in deterministic metadata;
- no absolute paths;
- all paths are package-relative or artifact-relative;
- deterministic JSON key ordering;
- deterministic array ordering by stable keys such as path, module identity,
  diagnostic code, and symbol;
- stable fingerprints over normalized bytes;
- stable relative path separators using `/`;
- no environment-dependent fields such as username, machine path, locale, or
  current branch;
- generated files are fingerprinted by content and tied to their declared
  source manifest or generator metadata when available.

## Non-goals

- No native installer.
- No Steam packaging.
- No package registry.
- No remote dependency resolution.
- No runtime dynamic linking.
- No Host ABI changes.
- No game-specific artifact fields.

## Runtime Rules

`airpkg` may contain verified AIR package metadata, generated reports,
manifests, generated handle/data modules, optional built Wasm artifacts, and
profile/conformance metadata.

Runtime artifacts produced from `airpkg` must not require:

- Node;
- npm install;
- Python;
- source AIR repo checkout;
- Codex;
- build scripts.

The v0.16 first slice records this as `boundary.runtimeRequires: []`. A non-empty
runtime dependency list requires a future accepted runtime contract and ABI
decision review.

Generated/linked output is an artifact. Authored package modules and package
metadata remain the review source unless a later executable package contract
changes that rule.

`linkedOutput.status` values:

- `planned`: link-plan metadata is available but no built linked output is
  referenced by package metadata.
- `available`: package metadata references an existing linked `.wasm` or `.wat`
  artifact and the airpkg records its deterministic hash.
- `deferred`: neither linked output nor link-plan evidence applies.

`linkedOutput.kind` values:

- `none`;
- `link-plan`;
- `wat`;
- `wasm`.

Build-time tooling may use Node, npm, Python, CI, Codex, asset generation,
review bundle tooling, and transitional generators. Those tools must be recorded
as build-time-only if they are part of artifact production evidence.

## Compatibility

No AIR ABI or Host ABI bump is implied by defining `airpkg` metadata.

AIR ABI stays `0.10` when `airpkg` records existing package-check/report
metadata, generated artifact status, host profile compatibility, diagnostics,
or build-time/runtime boundary information without changing runtime execution.

AIR ABI bump is required if `airpkg` defines a stable executable runtime
contract, entrypoint runtime semantics, import/export layout, memory/data
representation, linked package execution semantics, or runtime-required package
metadata consumed by the AIR runtime contract.

Host ABI stays `0.10` when `airpkg` only records existing host imports,
capabilities, profile compatibility, and conformance metadata.

Host ABI bump is required only if new host imports are added, existing host
import signatures change, host import required semantics change, or a future
event/output Host ABI is accepted.

## Commands

Implemented first-slice command shape:

```sh
node bin/airc.js package <package-dir> -o dist/app.airpkg
node bin/airc.js inspect-airpkg dist/app.airpkg --json
```

The current implementation accepts JSON-file output such as:

```sh
node bin/airc.js package <package-dir> -o dist/app.airpkg.json
node bin/airc.js inspect-airpkg dist/app.airpkg.json
```

and directory output such as:

```sh
node bin/airc.js package <package-dir> -o dist/app.airpkg
node bin/airc.js inspect-airpkg dist/app.airpkg
```

Implementation semantics:

- package command verifies/package-checks authored package input;
- output is a deterministic `airpkg` JSON or directory artifact;
- inspect command reads only the artifact and reports metadata;
- inspect does not require source package files, Node build scripts, Python
  generators, or demo assets beyond files embedded or referenced as runtime
  artifact contents.

## Acceptance Tests

- deterministic artifact metadata for the same package input;
- deterministic output across repeated builds;
- inspect output reports required metadata;
- missing package fails with a package diagnostic;
- package-local paths only;
- no timestamps;
- no absolute paths;
- artifact inspection can report package name, ABI versions, entry, profiles,
  capabilities, manifests, generated artifacts, and linked build status;
- artifact inspection reports `linkedOutput.status` clearly;
- link-plan hash is deterministic;
- existing linked Wasm hash is recorded when package metadata references it;
- invalid or stale generated artifacts remain visible as package-check failures
  or warnings according to policy;
- generated stale status is reflected in artifact metadata;
- AIR ABI and Host ABI remain unchanged unless a runtime or Host ABI contract
  change is explicitly accepted.

## Risks

- artifact metadata may be mistaken for a product bundle contract;
- deterministic metadata rules may be underspecified without fixtures;
- adding executable fields too early may imply an AIR ABI bump before the
  runtime contract is accepted;
- artifact inspection may accidentally depend on the source checkout unless
  tests run against artifact-only directories.

## Deferred Items

- compressed archive format decision;
- signing/checksum policy;
- `airpkg inspect` / `airpkg check` CLI shape;
- target product bundle integration;
- registry publishing.
