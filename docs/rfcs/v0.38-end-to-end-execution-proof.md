# RFC v0.38: End-to-End Execution Proof

Status: implemented / P0 first slice

Target milestone: v0.38

## Purpose

Define and implement a deterministic end-to-end proof for AIR's
consumer-facing loop:

```text
host-shaped input
-> sanitized structured facts
-> AIR execution
-> bounded output intent
-> mock host policy
-> evidence report
```

The proof should show that AIR can make a bounded deterministic decision from
sanitized host-shaped facts without becoming a raw host API wrapper, without
network access, and without adding new Host ABI imports.

## Scope

The first proof uses the existing lan-observer-style read-only package in Core.
It exercises:

- structured input fixture;
- AIR package validation;
- AIR execution;
- output intent capture;
- mock host policy simulation;
- conformance/replay linkage;
- evidence report generation;
- benchmark timing where available.

## Runner Path

Implemented command:

```sh
node bin/airc.js run-proof examples/lan_observer_readonly_package \
  --fixture examples/lan_observer_readonly_package/traces/pass.json \
  --policy examples/lan_observer_readonly_package/host_policies/lan_observer_readonly.policy.json \
  --profile cli \
  --json
```

The command emits `kind: "air.e2eProofReport"`.

The runner should make the execution boundary explicit:

1. Load a deterministic structured input fixture.
2. Validate/package-check the AIR package.
3. Execute the AIR package with sanitized scalar facts.
4. Capture bounded output intent.
5. Run mock host policy against that intent.
6. Produce or attach evidence report data.
7. Fail deterministically on mismatch.

No step may read from OS/network devices, call cloud/browser/database APIs, or
use secrets.

## Killer Test

The implemented killer test is:

- change AIR decision logic;
- leave expected output/evidence unchanged;
- execution proof fails with a stable mismatch.

This prevents the proof from becoming a static report-only fixture that cannot
catch executable drift.

## Evidence Report Boundaries

Markdown evidence reports accept `--e2e-proof <json>`. When provided, the
report includes an End-to-End Proof section with separate rows for:

- static validation;
- package policy validation;
- conformance replay;
- runtime execution proof;
- host policy simulation.

The report must not collapse these into a single generic "passed" line. A
package can pass static validation but fail runtime proof, or pass runtime proof
while receiving a denied mock host policy result.

## Benchmark Updates

The first E2E benchmark fixture is:

```text
benchmarks/e2e_lan_observer_readonly_basic/
```

Benchmark output includes, where available:

- E2E proof timing;
- evidence report timing;
- mock host policy timing;
- host crossing count;
- output intent count.

Benchmarks remain evidence-gated. v0.38 must not add broad performance claims.

## Privacy and Authority Boundary

The proof must not include:

- real network scans;
- raw packet captures;
- secrets or tokens;
- raw URLs;
- private hostnames;
- raw MAC/IP values unless represented as sanitized IDs;
- host writes or automatic remediation.

The host owns real platform state and policy execution. AIR owns bounded
deterministic logic and bounded output intent.

## ABI Decision

AIR ABI remains `0.10` if the proof uses existing AIR package execution and
existing scalar Wasm conventions.

Host ABI remains unchanged. Host ABI `0.11` remains limited to bounded
`output.emit`.

If implementation requires a new executable/runtime contract or host import,
the work must stop and produce an ABI review instead.

## Non-goals

- package composition implementation;
- real host adapter;
- network/OS access;
- production lan-observer integration;
- new Host ABI imports;
- external demo source changes;
- live AI provider calls.
