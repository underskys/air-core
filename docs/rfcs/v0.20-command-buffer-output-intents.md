# AIR v0.20 RFC: Command Buffer Output Intents

Status: active first slice

Target milestone: v0.20

## Purpose

Command buffers make package-local output intent usage reviewable before any
Host ABI output import is accepted. They let packages declare bounded scalar
intent records that can be inspected by package-check, reports, verification
evidence, and conformance replay.

Commands are intents only. Host policy decides whether any future host action is
allowed. v0.20 does not add automatic host-side action execution.

## Boundary

The first slice is package/tooling/conformance metadata only:

- no `output.emit`;
- no `output.event`;
- no `audio.event` or `effect.event`;
- no Host ABI `0.11`;
- no raw host authority;
- no standardized exported AIR entrypoint shape;
- no AIR ABI change.

If a future design requires a standardized exported command buffer entrypoint,
linear-memory runtime contract, host import, or package runtime representation
change, it must go through an explicit ABI decision gate.

## Manifest Integration

Packages may reference command buffer metadata through `air.package.json`:

```json
{
  "outputContracts": ["outputs/task_policy.output.json"],
  "commandBuffers": ["outputs/task_policy.commands.json"]
}
```

`commandBuffers` paths are package-local. Absolute paths and path escapes fail
manifest validation.

## Command Buffer Shape

```json
{
  "schemaVersion": "0.20",
  "kind": "air.commandBuffer",
  "name": "task_policy_commands",
  "maxCommands": 4,
  "records": [
    {
      "output_id": 1001,
      "arg0": 101,
      "arg1": 3,
      "arg2": 1,
      "arg3": 0
    }
  ]
}
```

The first-slice command record is:

```json
{
  "output_id": "i32",
  "arg0": "i32",
  "arg1": "i32",
  "arg2": "i32",
  "arg3": "i32"
}
```

`output_id` must match an ID declared by package `outputContracts`. Args are
scalar `i32` values. There are no strings, blobs, maps, objects, host handles,
or runtime imports.

## Validation

Package-check validates:

- `schemaVersion: "0.20"`;
- `kind: "air.commandBuffer"`;
- stable command buffer `name`;
- positive bounded `maxCommands`;
- `records[]` length does not exceed `maxCommands`;
- each record contains exactly `output_id`, `arg0`, `arg1`, `arg2`, and `arg3`;
- all record fields are `i32`;
- each `output_id` exists in package `outputContracts`;
- no absolute paths;
- no timestamps, random IDs, nonces, or other nondeterministic fields;
- no dynamic payload fields such as `payload`, `data`, `values`, `rows`,
  `properties`, `json`, `map`, `object`, or `hostHandle`.

## Report Surface

Package reports expose:

- command buffer path;
- fingerprint;
- name;
- `maxCommands`;
- record count;
- used output IDs;
- records;
- diagnostics;
- output intent usage grouped by `output_id`.

Verification evidence includes command buffer summaries so downstream systems
can embed package-local output intent usage in machine-readable evidence.

## Conformance

Batch conformance fixtures may include:

```json
{
  "observedCommands": [
    { "output_id": 1001, "arg0": 101, "arg1": 3, "arg2": 1, "arg3": 0 }
  ],
  "expectedCommands": [
    { "output_id": 1001, "arg0": 101, "arg1": 3, "arg2": 1, "arg3": 0 }
  ]
}
```

The harness compares command records deterministically. This is conformance
evidence, not host execution.

## Non-goals

- no Host ABI output implementation;
- no automatic host-side action execution;
- no raw host authority;
- no command buffer linear-memory ABI;
- no generated command handles in this slice;
- no tablegroups;
- no runtime JSON object model.

## Acceptance Tests

- valid command buffer fixture passes package-check;
- unknown `output_id` fails;
- capacity exceeded fails;
- wrong command args fail in conformance;
- output intent usage appears in package report;
- deterministic conformance output and replay checksum;
- AIR ABI remains `0.10`;
- Host ABI remains `0.10`.
