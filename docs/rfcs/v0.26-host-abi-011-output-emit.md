# AIR v0.26 RFC: Host ABI 0.11 Bounded Output Emit

Status: runtime/lowering first slice implemented

Target milestone: v0.26

This RFC defines the first narrow Host ABI `0.11` candidate:

```text
output.emit(output_id:i32, arg0:i32, arg1:i32, arg2:i32, arg3:i32) -> i32
```

The v0.26 implementation recognizes Host ABI `0.11` in package/profile
validation, validates `output.emit` usage, and lowers the exact scalar import
when declared by a module. It does not implement real host side effects, raw
host authority, event streams, string/object payloads, host object handles, or a
runtime JSON/object model.

## 1. Purpose

v0.25 proved that bounded output intent can be represented and reviewed through
Output Contracts, command buffers, a reference mock host, verification evidence,
and two-domain fixtures.

v0.26 considers the first runtime boundary for the same bounded intent model:
AIR may request that a host record or consider a declared scalar output intent.
The host still owns policy and execution.

`output.emit` is not a side-effect guarantee. It is a bounded request into host
policy.

## 2. ABI Signature

```text
extern output.emit(output_id:i32, arg0:i32, arg1:i32, arg2:i32, arg3:i32) -> i32
```

Semantics:

- `output_id` identifies an Output Contract entry.
- `arg0..arg3` are scalar `i32` values.
- return value is deterministic status code.
- host policy decides whether the output is accepted, denied, or unsupported.
- no object, pointer, slice, string, map, JSON, raw URL, raw log, token, secret,
  credential, or host object may cross this ABI.

## 3. Return Status Codes

Suggested first-slice return status:

| Code | Name | Meaning |
| ---: | --- | --- |
| `0` | `accepted` | Host policy accepted the declared bounded intent. |
| `1` | `denied_by_policy` | Host policy recognized but denied the intent. |
| `2` | `unsupported_profile` | Selected host profile does not support runtime output emit. |
| `3` | `invalid_output_id` | Output id is not known to the selected package/profile contract. |
| `4` | `budget_exceeded` | Emit exceeds verifier/host budget. |

Static invalid output ids should fail package-check or verifier before runtime
where possible. Runtime status `3` remains for defensive host behavior and
non-static future cases.

## 4. Static Output ID First Slice

The first slice requires `output_id` to be statically resolvable:

- integer literal;
- module/package constant;
- generated output handle.

Dynamic output ids are deferred. A value computed through arithmetic, branch
selection, host import, memory load, state read, table lookup, or function return
is not accepted in the first slice unless the verifier can prove a single
concrete Output Contract id.

## 5. Args

Args are exactly four `i32` scalar slots.

If an Output Contract has fewer logical args, unused slots must be zero.

If Output Contracts later mark args private or sensitive, reports and
`air.hostInteractionEvidence` must prefer hash-only representation for those
arguments. Raw private payloads remain rejected.

Deferred:

- strings;
- slices;
- pointers;
- payloads;
- object/map args;
- runtime JSON;
- raw private text;
- raw URLs;
- raw logs.

## 6. Capability And Effect Model

`output.emit` requires explicit authority.

Planned first-slice model:

- module declares output capability or bundle;
- exact `output.emit` host import signature is registry-known;
- effect budgets include emit count, for example `output.emit <= N`;
- package-check/report expose output usage, counts, and policy expectations;
- verifier rejects emit calls without authority or budget.

Denied output is a valid policy outcome, not a verifier failure by itself.
Unknown output ids, missing authority, missing budget, and non-static output ids
are validation failures.

## 7. Package-Check Model

Package-check must validate:

- package declares Host ABI `0.11` when using `output.emit`;
- selected host profile supports `output.emit`;
- Output Contracts exist and are valid;
- static `output_id` values resolve to Output Contract entries;
- emitted arg count fits the first-slice scalar slots;
- output contract args are first-slice `i32` scalar args;
- module and package declare capability `output`;
- emit count has an explicit `output.emit` or `output.*` effect budget;
- profile constraints for the selected output are satisfied;
- no raw authority or private payload fields are introduced;
- unsupported profiles fail deterministically.

Host ABI `0.10` packages continue to use command buffers and do not gain
runtime `output.emit` implicitly.

## 8. Verifier And Lowering Model

Verifier:

- accepts only exact `output.emit(i32,i32,i32,i32,i32) -> i32`;
- requires capability/effect budget;
- requires statically resolvable output id in P0;
- validates output id against package Output Contracts where package context is
  available;
- rejects dynamic output ids in P0;
- rejects pointer/slice/string/object payload attempts.

Lowering:

- lowers to a normal Wasm import under the `output` namespace only when the
  module declares `extern output.emit`;
- emits no `output.emit` import for modules that do not use it;
- preserves scalar ABI only;
- does not introduce AIR ABI changes;
- does not introduce hidden exports;
- does not add automatic host-side execution.

## 9. Mock Host Behavior

The reference mock host supports `output.emit` trace evidence without real side
effects.

It should:

- resolve `output_id` through Output Contracts;
- apply allow/deny host policy;
- return/record deterministic status codes;
- record command/evidence decisions;
- preserve replay checksum determinism;
- reject unknown output ids, unsupported profiles, raw authority, and
  nondeterministic fields.

The mock host remains an evidence tool. It is not a real platform host.

## 10. Conformance Matrix

Required P0 fixtures:

| Case | Expected |
| --- | --- |
| known output allowed | status `0`, accepted evidence |
| known output denied | status `1`, denied decision/warning evidence |
| unsupported profile | package-check failure or status `2` |
| unknown static output | package-check/verifier failure, or status `3` for defensive host |
| budget exceeded | verifier failure or status `4` if host observes runtime excess |
| dynamic output id | verifier/package-check failure in P0 |
| raw authority payload | failure |
| object/map/runtime JSON payload | failure |

Fixtures must cover at least:

- non-game policy/ops domain;
- interactive/visual-like domain.

## 11. Report And Evidence Fields

Reports should expose:

- output emit usage by module/function;
- static output ids used;
- output contract names/channels/capabilities;
- emit budget and usage;
- required package Host ABI and selected host profile Host ABI support;
- diagnostics and repair hints.

Verification evidence includes compact, non-payload output emit metadata when
`output.emit` is used:

- usage count;
- output ids, names, capabilities, and arg counts from Output Contracts;
- required Host ABI `0.11` in profile compatibility;
- selected profile Host ABI when a profile is used.

Verification evidence may include host interaction summary when mock-host
evidence is provided:

- host interaction summary;
- accepted/denied counts;
- compact policy decisions and status codes where available;
- unsupported count;
- diagnostics count;
- replay checksum;
- output ids and names where non-sensitive.

Evidence must not include raw private payloads, timestamps, absolute paths, raw
URLs, logs, tokens, secrets, credentials, runtime JSON, or host object handles.

## 12. LSP Diagnostics

LSP-lite (`airc check <file-or-package> --lsp-json`) and diagnostics-only Full
LSP publish stable output emit diagnostics. They do not add code actions,
hover, go-to-definition, document symbols, generated accessors, or editor
extension behavior.

Diagnostics:

- unknown output id;
- dynamic output id in P0;
- missing output capability;
- missing `output.emit` effect budget;
- unsupported host profile;
- non-scalar output arg;
- output contract/profile mismatch;
- sensitive arg requires hash-only reporting if sensitive args are accepted in a
  future slice.

Package/profile/check diagnostics implemented in the first slice:

- `air.output_emit.host_abi_unsupported`;
- `air.output_emit.output_id_invalid`;
- `air.output_emit.output_id_dynamic`;
- `air.output_emit.args_invalid`;
- `air.output_emit.capability_missing`;
- `air.output_emit.budget_exceeded`;
- `air.output_emit.profile_unsupported`.

Code actions are P1/deferred.

## 13. Compatibility And Rollback

Host ABI `0.10` remains valid. Packages that do not opt into Host ABI `0.11`
continue to use Output Contracts, command buffers, mock-host evidence,
verification evidence, and conformance replay.

A package using `output.emit` must declare Host ABI `0.11` after implementation
is accepted. Unsupported hosts must fail package-check or return deterministic
unsupported status before performing any side effect.

Rollback path:

- replace runtime `output.emit` calls with command buffer output intents;
- keep Output Contract ids stable;
- keep host policy evidence through the mock host.

## 14. AIR ABI Decision

AIR ABI remains `0.10` if:

- `output.emit` is only a host import;
- AIR calling convention does not change;
- no hidden exports are added;
- no runtime JSON/object model is added;
- no pointer/slice/reference escape is introduced;
- AIR Core semantics remain scalar and verifier-visible.

AIR ABI changes only if executable AIR semantics or calling conventions change.

## 15. Rejection Conditions

Reject or defer any version of this proposal that requires:

- dynamic output ids in P0;
- raw host authority;
- raw Chrome/DOM/DB/cloud/Kubernetes/Jira/fetch APIs;
- strings, payloads, objects, maps, runtime JSON, or host object handles;
- automatic host-side action guarantee;
- game-specific semantics;
- hidden compiler exports;
- side effects that bypass host policy.

## 16. v0.26 Decision Gate

The narrow runtime/lowering slice is accepted for scalar `output.emit`. Richer
payloads, event imports, automatic side-effect guarantees, or raw host authority
require a follow-up decision.
