# RFC v0.35: lan-observer-style Read-only Consumer Proof

Status: active / implemented Core proof

Target milestone: v0.35

## Purpose

Define the first read-only consumer proof for AIR Core.

The proof demonstrates that a host-owned application can convert realistic
host-shaped platform/network observations into sanitized bounded scalar
structured facts, pass those facts to AIR, and receive deterministic
diagnosis/recommendation output without AIR becoming a raw host API wrapper or
general application language.

The Core fixture lives under `examples/lan_observer_readonly_package/`. It is
synthetic and read-only. It does not implement a real lan-observer adapter, real
network access, host writes, secrets, new Host ABI imports, AIR ABI changes, or
external demo changes.

## Non-negotiable Boundary

The host owns:

- real network/platform state;
- real network access;
- OS and device APIs;
- packet capture and packet parsing;
- raw hostnames, MAC addresses, IP addresses, URLs, and private names;
- secrets, tokens, credentials, and private text;
- wall-clock time, randomness, persistence, and execution policy;
- any writes, mutations, remediation, notifications, or external effects.

AIR sees only:

- bounded scalar structured facts;
- sanitized ids/handles/enums/flags/scores/counters;
- deterministic package-local inputs;
- output contracts or command buffer contracts;
- no raw private payloads.

## Sanitized Structured Facts

The first proof should use scalar fields like:

| Field | Type | Meaning | Privacy rule |
| --- | --- | --- | --- |
| `device_id` | `i32` | Sanitized stable test id. | Not a MAC/IP/hostname. |
| `link_status` | `i32` | Enum for link up/down/degraded/unknown. | No raw interface names. |
| `latency_ms` | `i32` | Bounded latency bucket or sanitized measurement. | No packet payloads. |
| `packet_loss_x1000` | `i32` | Loss ratio scaled by 1000. | No packet dumps. |
| `gateway_reachable` | `i32` | Boolean-as-i32 reachability flag. | No gateway address. |
| `dns_reachable` | `i32` | Boolean-as-i32 reachability flag. | No resolver address. |
| `recent_change_flag` | `i32` | Bounded host-provided change flag. | No raw changelog text. |
| `source_flags` | `i32` | Bounded source/confidence flags. | No source names. |

The implementation may add fields only if they remain scalar, bounded,
privacy-classified, and source-owned by the host fixture.

Rejected field forms:

- strings;
- raw URLs;
- raw hostnames;
- MAC addresses;
- IP addresses;
- packet payloads;
- nested records;
- runtime JSON;
- dynamic maps;
- host object handles;
- arbitrary raw notes/private text.

## AIR Diagnosis And Recommendation

AIR may compute bounded scalar outputs such as:

| Output | Type | Meaning |
| --- | --- | --- |
| `diagnosis_code` | `i32` | Bounded enum such as `ok`, `link_down`, `gateway_issue`, `dns_issue`, `loss_or_latency`, `unknown`. |
| `severity` | `i32` | Bounded enum. |
| `recommended_action_id` | `i32` | Bounded host-policy action intent id. |
| `confidence_x1000` | `i32` | Confidence scaled by 1000. |
| `requires_human_approval` | `i32` | Boolean-as-i32 policy handoff flag. |

AIR must not execute remediation. It may emit an intent for host policy to
review. Host policy decides whether anything happens.

## Mock Reference Host Fixture

The fixture is synthetic and read-only:

- no real network scan;
- no packet capture;
- no OS device enumeration;
- no cloud/database/browser APIs;
- no credentials;
- no writes;
- no host-side mutation.

The mock host fixture provides deterministic sanitized observations and
deterministic host policy decisions.

## Output Path

The proof may use:

- command buffer output intents;
- bounded `output.emit`;
- or both, if the distinction is useful and remains small.

It must not add:

- new Host ABI imports;
- `output.event`;
- `audio.event`;
- `effect.event`;
- dynamic output ids;
- object/string/JSON payloads;
- automatic host-side action execution.

## Evidence, Replay, And Report Expectations

The implemented proof produces:

- package-check result;
- verification evidence;
- package report;
- human-readable evidence report;
- deterministic conformance/replay result;
- replay checksum or equivalent summary;
- mock host policy result;
- privacy-safe diagnostics;
- package diff for an old/new fixture or output contract change.

Reports must show schema/output/decision metadata, not raw private inputs.

## Package Diff Workflow

The proof should include or exercise an old/new comparison that can show at
least one meaningful delta:

- structured IO schema delta;
- output contract delta;
- capability/effect delta;
- generated artifact freshness delta;
- Host ABI requirement delta only if the proof compares command buffer vs
  bounded `output.emit` packages.

The diff output must remain deterministic and path-safe.

## Acceptance Criteria

The implementation is acceptable only if:

- structured facts are scalar-only and bounded;
- all private/raw host/network data is stripped before AIR;
- package-check rejects unsupported schema drift;
- AIR produces deterministic diagnosis/recommendation;
- output is bounded and policy-owned;
- mock host policy owns execution decisions;
- conformance/replay passes deterministically;
- evidence reports are readable and privacy-safe;
- package diff surfaces relevant metadata changes;
- no real network access exists;
- no OS/network devices are accessed;
- no secrets, tokens, credentials, raw URLs, hostnames, MACs, IPs, packet dumps,
  or private text are present in package inputs/reports by default;
- no writes/mutations are added;
- no external demos are touched;
- AIR ABI remains `0.10`;
- Host ABI remains unchanged.

## Kill Criteria

Stop implementation if the proof requires:

- raw packet capture in Core;
- raw network/device authority in AIR;
- runtime JSON/object values;
- dynamic maps;
- host object handles;
- raw hostnames/MACs/IPs/private text in AIR facts;
- secrets/tokens;
- real writes or remediation;
- new Host ABI imports;
- AIR ABI changes;
- external demo rewrites.

## ABI Decision

This proof should not require an AIR ABI bump if it uses existing package
metadata, structured IO schemas, AIR scalar functions, command buffers,
bounded `output.emit`, reports, evidence, and conformance surfaces.

This proof should not require a Host ABI bump. Host ABI `0.11` remains limited
to bounded `output.emit`; command buffers and mock host policy remain tooling /
package contract surfaces.

## Fixture Location

The proof lands as:

```text
examples/lan_observer_readonly_package/
```

Rejected unsafe variants live under test fixtures so the review surface can show
the unsafe-to-safe boundary without giving AIR raw host authority.
