# AIR v0.27 RFC: Output Handles Ergonomics

Status: first slice implemented / P1

Target milestone: v0.27

This RFC defines the v0.27 P1 ergonomics slice for generated output handle
constants. The implemented first slice generates constants and freshness
metadata only; it does not generate emit wrapper functions and does not change
AIR ABI or Host ABI.

## 1. Problem

The v0.26 `output.emit` first slice requires static, resolvable output ids.
Literal ids are reviewable but easy for AI agents to drift from
`outputContracts`.

Generated output handles can reduce drift if they remain visible,
deterministic, freshness-checked, and derived from package Output Contracts.

## 2. Source Of Truth

Output Contracts are the source of truth for output ids, output names,
channels, capabilities, argument counts, and scalar argument types.

Generated output handles are derived artifacts. They must not become the source
of truth, and stale generated handles must not be accepted by canonical
examples.

If generated handles disagree with Output Contracts, package-check must treat
the generated handles as stale or mismatched. It must not reinterpret Output
Contracts from generated handle names or constants.

## 3. Candidate Generated Files

P1 generated AIR file:

```text
generated/output_handles.air
```

First-slice generated AIR contains constants only and is produced by:

```sh
node bin/airc.js generate output-handles <package-dir>
```

Example constants:

```air
const OUTPUT_INCIDENT_RECOMMEND_ACTION:i32 = 1
const OUTPUT_PANEL_SET_BADGE:i32 = 2
const OUTPUT_INCIDENT_RECOMMEND_ACTION_ID:i32 = 1
const OUTPUT_INCIDENT_RECOMMEND_ACTION_ARG_COUNT:i32 = 4
```

The short constant form, such as `OUTPUT_INCIDENT_RECOMMEND_ACTION`, is the
preferred AIR authoring handle. Suffix constants, such as `_ID` or
`_ARG_COUNT`, are metadata conveniences. They are still derived from Output
Contracts and must not introduce new ids.

P1 metadata sidecar:

```text
generated/output_handles.meta.json
```

Required metadata should include:

- `schemaVersion`;
- `kind: air.generatedOutputHandles`;
- generator name/version;
- source Output Contract paths and fingerprints;
- generated file fingerprint;
- outputs with id, name, channel, capability, arg count, and arg types.

Example shape:

```json
{
  "schemaVersion": "0.27",
  "kind": "air.generatedOutputHandles",
  "generator": "airc output-handles",
  "sourceContracts": [
    {
      "path": "outputs/main.output.json",
      "fingerprint": "sha256:..."
    }
  ],
  "generatedFiles": [
    {
      "path": "generated/output_handles.air",
      "fingerprint": "sha256:..."
    }
  ],
  "outputs": [
    {
      "id": 1,
      "name": "incident_recommend_action",
      "handle": "OUTPUT_INCIDENT_RECOMMEND_ACTION",
      "channel": "policy",
      "capability": "output.emit",
      "argCount": 4,
      "argTypes": ["i32", "i32", "i32", "i32"]
    }
  ]
}
```

This sidecar is package-visible review metadata. It is not runtime Host ABI
metadata.

## 4. Freshness Model

Package-check should be able to diagnose:

- missing generated output handles;
- stale source fingerprint;
- generated file fingerprint mismatch;
- metadata/schema mismatch;
- handle for unknown output id;
- missing handle for declared output id.

Freshness checking is required before canonical examples may depend on generated
output handles.

Freshness must be deterministic and reviewable. Generated handle files and their
metadata sidecar should be package-visible and checked into review bundles when
packages depend on them.

Freshness is computed from Output Contract fingerprints, generated file
fingerprints, generator identity, and generated metadata. Wall-clock time,
absolute paths, random ids, and local environment data must not affect
freshness.

## 5. LSP Diagnostics

Stable diagnostics:

- `air.generated.output_handles_missing`;
- `air.generated.output_handles_stale`;
- `air.generated.output_handles_mismatch`;
- `air.generated.output_metadata_invalid`;
- `air.output_handle.unknown_output`;
- `air.output_handle.missing_output`;

LSP diagnostics must cover stale, missing, and mismatched generated handles.
v0.27 P1 diagnostics are diagnostics-only unless a later prompt explicitly
accepts more editor features. No code actions, hover, go-to-definition,
document symbols, or VS Code extension are part of P1 by default.

## 6. Report And Evidence Mapping

Reports expose `outputHandleSets` when `generated/output_handles.air` is listed
in `generatedModules`:

- generated output handle path;
- metadata path;
- fresh/stale/missing/mismatch status;
- source fingerprints;
- generated fingerprints;
- output ids/names/capabilities/arg counts;
- handle names mapped to output ids;
- diagnostics.

Verification evidence may include handle metadata, but not raw output payloads
or host-side execution results.

Report/evidence mapping must make it possible to review:

```text
OUTPUT_INCIDENT_RECOMMEND_ACTION -> output_id 1
OUTPUT_PANEL_SET_BADGE -> output_id 2
```

This mapping is evidence metadata only. Output Contracts remain the source of
truth, and the mapping does not authorize host-side side effects.

## 7. Safety Rules

Generated output handles must not:

- generate public emit wrapper functions in P1 unless separately approved;
- generate private emit wrapper functions;
- hide compiler exports;
- bypass the verifier;
- allow dynamic `output_id`;
- add string/object/map/payload args;
- add pointer or slice args;
- add runtime JSON/object model;
- add host object handles;
- expand `output.emit`;
- add `output.event`, `audio.event`, or `effect_event`;
- imply automatic host-side side effects;
- become a Host ABI requirement.

Generated handles may be used only where `output.emit` already accepts a static,
resolvable output id. They must not create a dynamic output id path.

## 8. ABI Decision

AIR ABI remains `0.10` if generated output handles are visible AIR constants and
metadata-only derived artifacts.

Host ABI remains `0.11` only for the existing bounded `output.emit` first slice.

Generated output handles do not expand Host ABI and do not add host imports.

Host ABI or AIR ABI changes become candidates only if generated output handles
become runtime-required metadata, hidden compiler exports, or host-interpreted
state.

## 9. P1 First Slice

The implemented first slice includes:

- generator command: `node bin/airc.js generate output-handles <package-dir>`;
- deterministic handle naming from Output Contract names;
- collision rejection for duplicate ids or normalized handle names;
- `generatedModules` integration;
- freshness diagnostics for missing/stale/mismatch metadata;
- `outputHandleSets` in package reports and verification evidence;
- LSP-lite and diagnostics-only Full LSP diagnostics for stale generated
  output handles;
- tests proving no emit wrapper functions are generated.

P1 still excludes generated emit wrapper functions, dynamic `output_id`, Host
ABI expansion, and payload args.
