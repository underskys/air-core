# AIR v0.25 RFC: Host ABI 0.11 Decision Record

Status: accepted decision record for v0.25

Decision: Host ABI `0.11` is not accepted in v0.25.

This document records the v0.25 Host ABI decision. It does not implement Host
ABI `0.11`, add `output.emit`, `output.event`, `audio.event`, or
`effect.event`, add host imports, change AIR ABI, change Host ABI, add raw host
authority, or add a runtime JSON/object model.

## 1. Decision Summary

- Keep Host ABI at `0.10`.
- Keep AIR ABI at `0.10`.
- Keep `output.emit`, `output.event`, `audio.event`, and `effect.event`
  deferred.
- Treat the reference mock host and command buffer evidence as
  tooling/evidence surfaces, not Host ABI imports.
- Treat `air.hostInteractionEvidence` as review/conformance evidence, not a
  runtime host import contract.
- Require a separate accepted RFC before any future Host ABI `0.11`
  implementation.

Host interaction evidence proves that command-buffer output intents can be
interpreted by deterministic host policy. It does not require new runtime host
imports.

## 2. Evidence Available In v0.25

v0.25 has enough evidence to continue the command-buffer/policy model:

- Output Contracts exist and describe stable scalar output intent ids.
- Command buffers exist and carry bounded scalar command intent records.
- Verification evidence exists and records package/report fingerprints.
- The reference mock host / policy executor exists.
- `airc mock-host` produces deterministic `air.hostInteractionEvidence`.
- `airc verify package --host-evidence <json> --json` embeds a compact host
  interaction summary.
- Mock host policy is a strict allow/deny schema, not a general data container.
- Two-domain fixture evidence exists:
  - AirOps-style policy/ops fixture;
  - synthetic interactive/visual-like panel fixture.
- Negative tests exist for raw authority, unknown outputs, unsupported
  profiles, nondeterministic fields, and object/map/payload command records.

This evidence supports Host ABI `0.10` command-buffer policy interpretation. It
does not justify a public runtime emit import yet.

## 3. Why Host ABI `0.11` Is Not Accepted Yet

`output.emit` would be a public runtime host import. That changes the runtime
host boundary and makes host interaction a live import semantics question
rather than a package metadata / conformance evidence question.

Current v0.25 evidence shows that:

- command-buffer intents are interpretable;
- host policy can allow or deny them deterministically;
- evidence can record decisions without executing real side effects;
- two independent domains can use the same policy/evidence shape.

That is enough to keep improving command-buffer evidence. It is not enough to
standardize runtime side-effect imports.

Host adapters may be rich. Public Host ABI must remain narrow, canonical,
versioned, capability-scoped, and conformance-tested.

## 4. Conditions For A Future Host ABI `0.11`

A future Host ABI `0.11` RFC must provide:

- generic semantics;
- at least two independent domains beyond one implementation;
- package-check visibility;
- report and verification visibility;
- conformance fixtures;
- LSP diagnostics;
- host profile support;
- rollback or downgrade path to command buffer intent;
- negative tests against raw authority;
- no runtime JSON/object model;
- no host object handles.

The RFC must also explain why command buffers, Output Contracts, verification
evidence, and mock-host policy evidence are insufficient.

## 5. Deny Decision Semantics

A denied output can be a valid host policy outcome.

Denied output means the mock host interpreted a declared output intent and host
policy chose not to allow it. The denial is recorded as a warning-style policy
decision and does not imply host side-effect execution.

These are failures:

- unknown output id;
- unsupported host profile;
- raw authority request;
- nondeterministic field;
- object/map/payload command record;
- command record that cannot be interpreted as bounded scalar intent.

## 6. Sensitive Args Future Note

The first mock-host slice may expose scalar command args when the Output
Contract treats them as non-sensitive.

If Output Contracts later mark args private or sensitive,
`air.hostInteractionEvidence` must prefer hash-only representation for those
arguments. Raw private payloads, raw logs, raw URLs, tokens, secrets,
credentials, object payloads, and runtime JSON remain rejected.

## 7. v0.25 Outcome

v0.25 keeps AIR ABI `0.10` and Host ABI `0.10`.

The milestone adds evidence and tooling, not a Host ABI implementation.
