# AIR v0.23 Decision: Fixed Bounded State ABI

Status: decision record / pre-implementation gate

Purpose: record the ABI decision for the first executable Fixed Bounded State
Segment slice before parser, verifier, lowering, report, or conformance changes
are implemented.

This decision record is docs-only. It does not implement state segments. It
does not change parser, verifier, lowering, AIR ABI, Host ABI, host imports,
Output Contracts, command buffers, examples, or demos.

## 1. Background

AIR v0.22 accepted Fixed Bounded State Segment as RFC/gates/design only. The
v0.23 implementation target is the first minimal executable slice:

- `state name:i32[N] = fill K`;
- `state.len`;
- `state.get`;
- `state.set`.

The feature is intended to model AIR-owned, deterministic, fixed-size scalar
storage per AIR execution instance. It is not a host state API and not a
runtime object model.

## 2. Default ABI Decision

Default v0.23 target:

- AIR ABI remains `0.10`;
- Host ABI remains `0.10`.

This is the default because the first slice can be treated as internal AIR
semantic storage managed by the compiler and verifier.

## 3. AIR ABI Remains 0.10 If

AIR ABI remains `0.10` if all of the following remain true:

- state is internal AIR semantic storage;
- compiler manages lowering;
- host does not need to understand state layout;
- entrypoint and calling convention do not change;
- state is not exported;
- state pointer, slice, or reference cannot escape;
- verification evidence/report `stateSegments` are tooling/report metadata
  only;
- conformance final digest is report evidence only.

Under these constraints, Fixed Bounded State is a Core semantic feature with a
compiler-managed backend representation. It does not become part of executable
package ABI.

## 4. AIR ABI 0.11 Candidate Conditions

AIR ABI `0.11` becomes a candidate if any of the following become necessary:

- state layout becomes a required executable package contract;
- host or runtime must allocate, restore, or interpret state;
- reset, init, or snapshot semantics become external ABI;
- state is exposed through package metadata that runtime must understand;
- state changes package entrypoint semantics;
- state snapshot/restore becomes standardized runtime ABI.

If any of these conditions appear during implementation, stop before changing
AIR ABI and write a separate ABI decision record.

## 5. Host ABI Remains 0.10 Because

Host ABI remains `0.10` for the v0.23 first slice because:

- no new host import is added;
- host does not directly access state;
- host receives no pointer, slice, or handle to state;
- host observes state only through exported scalar functions, command buffers,
  reports, or conformance evidence.

State does not grant host authority. State does not imply event emission,
host-managed snapshots, or host-visible memory.

## 6. Host ABI 0.11 Candidate Conditions

Host ABI `0.11` becomes a candidate only if any of the following are added:

- `output.emit`;
- `output.event`;
- `audio.event`;
- `effect.event`;
- host direct state access;
- host-managed state snapshot/restore;
- new host import signatures or semantics.

These are outside the v0.23 Fixed Bounded State first slice.

## 7. Required Stop Condition

Implementation must stop and report before changing ABI if Fixed Bounded State
appears to require either:

- AIR ABI `0.11`; or
- Host ABI `0.11`.

No parser, verifier, lowering, report, conformance, package metadata, or host
profile change may silently promote state into an ABI contract.

## 8. Non-Goals

This decision does not approve:

- exported state;
- host-visible state pointers, slices, references, or handles;
- host-managed state allocation;
- host-managed snapshot/restore;
- runtime JSON/object state;
- dynamic maps;
- state-dependent host authority;
- automatic host-side action execution;
- new host imports;
- AIR ABI `0.11`;
- Host ABI `0.11`.

## ABI Status

- AIR ABI remains `0.10`.
- Host ABI remains `0.10`.
- This decision record adds no implementation.
