# RFC v0.35: Read-only Consumer Proof & Product Evidence Pack

Status: active / product evidence pack planning

Target milestone: v0.35

## Purpose

Define the v0.35 proof that AIR can consume realistic host-shaped read-only
structured facts and produce deterministic diagnosis/recommendation output with
reviewable evidence, replay, diff, benchmark, and AI-eval coverage.

The first Core fixture exists under `examples/lan_observer_readonly_package/`.
This RFC defines the complete product evidence pack around that fixture. It
does not authorize real network access, host writes, secrets, new Host ABI
imports, AIR ABI changes, Host ABI changes, external demo changes, tablegroups,
or declared pools.

## Problem Demonstrated

AIR needs one consumer-grade proof that is not a game/demo and not a compiler
micro-test. The proof demonstrates AIR as a small deterministic decision layer
inside a host-owned read-only application:

```text
host real platform/network state
-> sanitized bounded scalar structured facts
-> AIR deterministic diagnosis/recommendation
-> bounded output intent
-> host policy decision
-> evidence, replay, report, diff, benchmark, and AI eval
```

The proof is intentionally synthetic at the Core boundary. It uses realistic
fact shapes without real network scans, packet capture, raw identifiers, or
private payloads.

## AIR Surfaces Exercised

The v0.35 proof exercises:

- bounded structured IO rowset and output summary schemas;
- generated structured IO handles as derived artifacts;
- AIR scalar decision functions;
- output contract and command buffer metadata;
- mock host policy evidence;
- package-check and verification evidence;
- human-readable evidence report;
- conformance/replay;
- package diff;
- benchmark runner baseline;
- AI authoring eval replay case.

## Host-owned Boundary

The host owns:

- real network/platform state;
- OS, network, device, cloud, browser, database, and packet capture APIs;
- raw hostnames, MACs, IPs, URLs, private names, and packet payloads;
- secrets, tokens, credentials, private notes, and raw logs;
- wall-clock time, randomness, persistence, write authority, and execution
  policy.

AIR sees only minimized scalar structured facts with fixed bounds. AIR emits
bounded recommendation/output intent only. Host policy owns any execution
decision.

## Synthetic / Sanitized Inputs

The proof facts are scalar-only and bounded. Representative fields:

| Field | Type | Rule |
| --- | --- | --- |
| `device_id` | `i32` | Sanitized id; not a MAC, IP, hostname, or private name. |
| `link_status` | `i32` | Bounded enum. |
| `latency_ms` | `i32` | Sanitized bounded counter. |
| `packet_loss_x1000` | `i32` | Sanitized score/counter, not packet data. |
| `gateway_reachable` | `i32` | Boolean-as-i32 flag; no gateway address. |
| `dns_reachable` | `i32` | Boolean-as-i32 flag; no resolver address. |
| `recent_change_flag` | `i32` | Host-shaped flag; no raw changelog text. |
| `source_flags` | `i32` | Bounded confidence/source flags; no source names. |

Rejected inputs include strings, raw URLs, raw hostnames, MAC addresses, IP
addresses, packet payloads, nested objects, runtime JSON, dynamic maps, host
object handles, secrets, tokens, credentials, and private text.

## Output Intent

The proof may use command buffer output intent or bounded `output.emit` if a
future variation needs Host ABI `0.11`. The current package uses Host ABI
`0.10` with output contract and command buffer metadata.

Bounded output fields:

- `diagnosis_code`;
- `severity`;
- `recommended_action_id`;
- `confidence_x1000`;
- `requires_human_approval` as explicit scalar decision helper and structured
  output summary metadata.

Output intent must not become `output.event`, object payloads, dynamic
`output_id`, host writes, or automatic host-side action execution.

## Evidence Boundary

Evidence proves the package boundary, not real-world network correctness.

Evidence must show:

- AIR ABI and required Host ABI;
- no host imports for the Host ABI `0.10` command-buffer path;
- bounded structured IO schema names, fields, classifications, and bounds;
- output contract and command buffer metadata;
- generated structured IO handle freshness;
- conformance/replay status;
- mock host policy status;
- diagnostics without raw payloads.

Evidence must not expose raw packet dumps, raw hostnames, MACs, IPs, raw URLs,
secrets, tokens, private text, helper dumps, absolute paths, timestamps, or
local environment details.

## Package Diff

Package diff should show change risk through metadata deltas:

- structured IO schema delta;
- output contract delta;
- command buffer delta;
- capability/effect delta;
- generated artifact freshness delta;
- Host ABI requirement delta if a future variant compares command buffer vs
  bounded `output.emit`.

The first test coverage exercises a changed output contract and validates that
the diff remains deterministic and path-safe. A committed golden diff fixture is
P0 product evidence hardening if reviewers need a static artifact.

## Benchmark Baseline

The benchmark fixture should use the existing v0.29 benchmark runner. It should
collect package-check, verification, report/evidence, replay, artifact size, and
runtime metrics where available.

Benchmark output is baseline evidence only. It must not claim AIR is globally
faster than TypeScript, Rust, Python, or host code, and must not revive x50/x200
claims without repeated measurements.

## AI Eval

The AI authoring eval case should use deterministic replay fixtures. It should
measure whether captured AI output can:

- produce the read-only structured facts schema shape;
- avoid runtime JSON, host object handles, raw host authority, and private
  payloads;
- produce bounded diagnosis/recommendation logic;
- repair stable diagnostics without live model calls.

No live AI provider calls, API keys, network access, nondeterministic CI, code
actions, or automatic repair are allowed.

## Acceptance Criteria

v0.35 can close when:

- the read-only package fixture passes package-check and verification;
- conformance/replay passes deterministically;
- mock host policy evidence passes;
- human-readable evidence report is privacy-safe;
- package diff shows change risk without raw payloads;
- benchmark fixture records baseline metrics without performance claims;
- AI eval replay case covers authorability/repairability;
- unsafe-to-safe rejection story covers raw host authority and private data;
- no real network access, packet capture, host writes, secrets, raw identifiers,
  external demos, new Host ABI imports, AIR ABI changes, or Host ABI changes are
  added.

## ABI Decision

AIR ABI remains `0.10`.

Host ABI latest remains `0.11`, limited to bounded `output.emit`; Host ABI
`0.10` remains the baseline/default. The current proof fixture uses Host ABI
`0.10` and does not add new Host ABI imports.

## Deferred

- real network scan;
- real packet capture;
- real device mutation;
- secrets/tokens;
- raw hostnames/MACs/IPs unless sanitized IDs;
- production observability;
- package registry;
- new Host ABI;
- real host adapter;
- tablegroups;
- declared pools.
