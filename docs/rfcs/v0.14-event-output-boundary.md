# RFC: v0.14 Event / Output Boundary

Status: draft

Target milestone: AIR v0.14 RFC/spec only

Possible implementation milestone: AIR v0.15 Host ABI 0.11 candidate, only if
accepted through spec, registry, profile, verifier, package-check, report, and
conformance tests.

## Summary

Events and outputs are generic capability-gated host-visible contracts. They are
not game-specific effects, renderer shortcuts, or hidden host behavior.

AIR packages may need to describe host-visible outputs such as:

- visual effects;
- audio events;
- alerts;
- notifications;
- pipeline outputs;
- DevOps actions;
- UI/dashboard output events.

This RFC defines the boundary. It does not add `audio.event`, `output.event`, or
any new Host ABI import in v0.14.

## Goals

- Keep events and outputs generic across domains.
- Require explicit capabilities for event/output authority.
- Bind event/output IDs through manifests where IDs are host-visible or
  resource-backed.
- Make event/output use visible in reports.
- Prevent hosts from inferring semantics from unrelated AIR state, debug
  telemetry, resource names, or generated handles.
- Preserve deterministic package-check diagnostics.

## Non-goals

- No new Host ABI in v0.14.
- No `audio.event` implementation in v0.14.
- No `output.event` implementation in v0.14.
- No game-specific effect API.
- No `draw_actor`, `draw_contra_enemy`, or domain-specific event names.
- No hidden gameplay, workflow, audio, graphics, filesystem, network, or UI
  authority through host code.
- No use of `debug.metric` as an event bus.
- No host object handles.
- No remote event registry.

## Boundary

AIR owns:

- capability declarations;
- calls to accepted event/output Host ABI imports, if such imports are promoted
  in a future release;
- event/output IDs when represented as AIR constants, generated handles, or
  static data;
- deterministic report surface.

Manifests own:

- host-visible event IDs;
- resource mappings where an event/output is resource-backed;
- optional fallback or mute/drop behavior;
- rate or budget policy when accepted by package-check.

Hosts own:

- execution of declared events/outputs;
- platform delivery policy;
- rendering, playback, notification, or action execution;
- refusal or fallback when profile support is unavailable.

Hosts must not infer event semantics from unrelated state, asset names, debug
metrics, resource paths, or conventional variable names.

## Required Properties For Any Future Event ABI

Any promoted event/output ABI must be:

- capability-gated;
- declared in the Host ABI registry;
- represented in host profiles;
- checked by the verifier for signature and capability;
- checked by package-check for profile compatibility;
- visible in report and audit output;
- backed by manifest IDs where host-visible IDs or resources are involved;
- deterministic in diagnostics and failure behavior.

## Debug Channel Rule

`debug.metric` is diagnostics-only.

It may expose telemetry for review, debugging, profiling, or visualization. It
must not silently authorize host side effects.

Rejected patterns:

- host plays audio when `debug.metric("shoot", 1)` appears;
- host emits visual effects when a debug value changes;
- host sends notifications from debug telemetry;
- host treats a metric name as a workflow action;
- host treats debug values as gameplay, deployment, alert, or UI command events.

AI review may warn when `debug.metric` appears to encode event-like pulses. A
future release may allow package policy to promote this warning to failure for
blessed packages.

## Manifest-backed IDs

Where an event/output maps to host-visible behavior or resources, IDs should be
manifest-backed and package-local.

Example shape, not a v0.14 schema commitment:

```json
{
  "outputs": {
    "notify_build_failed": {
      "capability": "ui",
      "kind": "notification",
      "fallback": "drop"
    },
    "play_warning_tone": {
      "capability": "audio",
      "kind": "audioSfx",
      "asset": "warning_tone",
      "fallback": "mute"
    }
  }
}
```

Manifest entries do not grant authority. The package must still declare the
required capability, and the selected host profile must support the corresponding
Host ABI import if one exists.

## Reporting Requirements

A future package report should include:

- declared event/output manifests;
- AIR references to event/output IDs;
- required capabilities;
- host profile support;
- missing manifest IDs;
- unused manifest entries;
- fallback behavior;
- event/output origin by module;
- debug-metric event-bus warnings.

JSON output must remain deterministic and machine-readable.

## Classification

v0.14:

- RFC/spec only.
- Report and AI-review warnings may identify `debug.metric` event-bus smells.
- No stable event/output Host ABI is added.

v0.15 candidate:

- possible Host ABI 0.11 work if a generic event/output ABI is accepted;
- requires spec, registry, verifier, package-check, host profile, report, and
  conformance coverage before promotion.

## Explicit Rejections

Rejected in AIR Core and public Host ABI:

- `debug.metric` as event bus;
- `draw_actor`;
- `draw_contra_enemy`;
- game-specific effect names;
- hidden host gameplay authority;
- hidden host workflow/action authority;
- output authority granted by asset existence;
- output authority granted by generated handles;
- output authority granted by host profiles without package/module capability
  declarations.

## Acceptance Tests For Future Promotion

Before implementation, accepted tests must cover:

- event/output import requires matching capability;
- package capability is required when a module uses the event/output import;
- selected host profile must support the import;
- missing manifest-backed ID fails deterministically;
- unsupported profile fails with repair hint;
- `debug.metric` event-bus fixture warns or fails by package policy;
- audio asset presence does not grant audio event authority;
- visual resource presence does not grant graphics event authority;
- JSON report order is deterministic.
