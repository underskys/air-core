# AIR v0.25 RFC: Reference Mock Host Policy Executor

Status: first slice implemented

Purpose: define a deterministic reference mock host that can consume AIR
command buffer output intents and apply host policy without executing real side
effects.

The v0.25 first slice implements this as tooling/evidence command. It does not
add Host ABI `0.11`, add `output.emit`, add host imports, change AIR ABI,
change Host ABI, or grant raw host authority.

Command:

```sh
node bin/airc.js mock-host <package-dir> --policy <policy.json> --profile <id> --json
node bin/airc.js mock-host <package-dir> --policy <policy.json> --profile <id> --trace <trace.json> --json
node bin/airc.js verify package <package-dir> --profile <id> --host-evidence <hostInteractionEvidence.json> --json
```

## 1. Role

The reference mock host is not a real platform host.

It is a conformance and evidence tool. It consumes package metadata, command
buffer records, Output Contracts, selected host profile metadata, and an
explicit host policy fixture. It then produces deterministic evidence about
what a host policy would allow or deny.

It proves:

- command buffers are interpretable;
- `output_id` values map to declared Output Contracts;
- host policy can allow or deny output intents;
- evidence can record policy decisions;
- no real side effects occur.

The mock host must not open sockets, write files, call cloud APIs, touch the
DOM, execute subprocesses, access secrets, or perform platform-specific
actions. It is a replay/evidence tool, not a runtime authority mechanism.

## 2. Inputs

The first slice may consume:

- package directory;
- package `air.package.json`;
- package-local `outputContracts`;
- package-local command buffer records;
- selected host profile;
- host policy fixture;
- verification evidence;
- conformance trace.

Inputs must be deterministic and package-local where applicable. The mock host
must reject absolute paths, timestamps as semantic inputs, private raw payloads,
runtime JSON objects, and host object handles.

The mock host may reuse existing package-check, verification evidence, and
conformance replay outputs rather than reparsing every source file directly.

## 3. Outputs

The mock host produces deterministic JSON:

```json
{
  "schemaVersion": "0.25",
  "kind": "air.hostInteractionEvidence",
  "status": "passed",
  "packageHash": "sha256:...",
  "abiHash": "sha256:...",
  "hostProfile": "mock-policy",
  "policyId": "incident-readonly",
  "commandRecords": [],
  "decisions": [],
  "deniedCapabilities": [],
  "diagnostics": [],
  "replayChecksum": "sha256:..."
}
```

Required fields:

- `schemaVersion`;
- `kind: air.hostInteractionEvidence`;
- `status: passed | failed`;
- `packageHash`;
- `abiHash`;
- `hostProfile`;
- `policyId`;
- `commandRecords[]`;
- `decisions[]`;
- `deniedCapabilities[]`;
- `diagnostics[]`;
- `replayChecksum`.

The output must not contain timestamps, absolute paths, secrets, raw private
payloads, host object references, or nondeterministic ordering.

Verification evidence integration embeds a summary of this output only:

- status;
- policy id;
- host profile;
- decision count;
- denied capability count;
- diagnostics count;
- replay checksum.

It does not embed raw command payloads. Failed host interaction evidence turns
the verification evidence status to `failed` and adds a deterministic
`air.host_interaction.policy_failed` diagnostic.

## 4. Policy Model

The first slice policy is allow/deny only. It is a strict schema, not a
general data container.

Example policy:

```json
{
  "schemaVersion": "0.25",
  "kind": "air.mockHostPolicy",
  "id": "incident-readonly",
  "allowOutputs": ["incident.recommend_action"],
  "denyOutputs": ["external.network_call"],
  "capabilities": {
    "network": "forbidden",
    "secrets": "forbidden",
    "filesystem.write": "reports-only"
  }
}
```

Policy fields are declarative. They do not execute real host actions.

Allowed top-level policy keys are:

- `schemaVersion`;
- `kind`;
- `id`;
- `hostProfile`;
- `allowOutputs`;
- `denyOutputs`;
- `capabilities`.

Unknown top-level keys fail validation. Policy files must not contain arbitrary
payload, data, object, map, raw private text, URL, token, secret, credential,
or platform API fields. They are not a place to store runtime data.

Initial semantics:

- an output name in `allowOutputs` may be allowed if the command record is
  valid and all required capabilities are compatible with the policy;
- an output name in `denyOutputs` is denied with a stable reason code;
- if an output is neither allowed nor denied, it is denied with reason
  `not_allowed`;
- a capability marked `forbidden` denies any command that requires it;
- a capability marked `reports-only` may appear in evidence but must not
  execute side effects;
- unknown outputs, unknown capabilities, or unsupported profiles fail or deny
  deterministically.

No policy rule may embed raw platform APIs such as `chrome.*`, DOM calls,
cloud SDK calls, SQL statements, shell commands, or URL fetch instructions.

Implemented first-slice schema validation requires:

- `schemaVersion` exactly `0.25`;
- `kind` exactly `air.mockHostPolicy`;
- optional `id` as a stable string;
- optional `hostProfile` as a stable string;
- `allowOutputs` and `denyOutputs` as arrays of stable strings;
- `capabilities` as a flat object mapping stable capability strings to stable
  policy strings.

Object or array values inside `allowOutputs`, `denyOutputs`, or `capabilities`
are rejected. Arbitrary extension fields are rejected in v0.25.

## 5. Decision Model

For each command record, the mock host records a decision:

```json
{
  "output_id": 1001,
  "output": "incident.recommend_action",
  "args": [1, 42, 80, 2],
  "argsHash": "sha256:...",
  "decision": "allow",
  "reason": "policy.allow_output",
  "diagnostics": []
}
```

Decision fields:

- `output_id`;
- output name resolved from Output Contracts;
- scalar args when non-sensitive;
- `argsHash` for stable comparison and privacy-friendly reporting;
- policy decision: `allow | deny`;
- stable reason code;
- diagnostics.

The implemented first slice records scalar `arg0`..`arg3` command values and an
`argsHash`; command payloads, maps, objects, JSON blobs, raw private text, and
host handles are rejected before evidence is considered valid. If a future
Output Contract marks an argument private or sensitive, evidence must prefer
`argsHash` and avoid raw argument values.

## 6. Safety Rules

The mock host rejects:

- raw host authority;
- `output_id` values not declared in `outputContracts`;
- unsupported host profiles;
- private/raw payloads in evidence;
- object/map/JSON runtime payloads as command args;
- nondeterministic fields;
- automatic host-side execution;
- host object handles;
- secrets, tokens, credentials, raw URLs, raw logs, or private text;
- policy files that behave like platform API wrappers.

The mock host may only explain and classify intent. It must not perform the
intent.

## 7. ABI Policy

The reference mock host does not require Host ABI `0.11`.

It does not add public host imports. It does not add `output.emit`. It does not
change AIR ABI. It consumes package metadata, command buffers, verification
evidence, and conformance traces as tooling/evidence inputs.

Host ABI `0.11` remains a candidate only if a future milestone accepts a new
runtime host import or changes public host import semantics.

## 8. Conformance

Implemented first-slice tests:

- valid command allowed;
- denied command reports a deny decision;
- unknown output fails with a stable diagnostic;
- denied capability reported;
- unsupported profile reported;
- deterministic checksum across repeated runs;
- no timestamps in evidence;
- no absolute paths in evidence;
- no raw private payloads in evidence;
- invalid policy schema fails;
- command record with object/map/runtime JSON payload fails;
- no real side effect occurs during replay.

Implemented first-slice diagnostics:

- `air.host_policy.schema_invalid`;
- `air.host_policy.unknown_output`;
- `air.host_policy.denied_output`;
- `air.host_policy.unsupported_profile`;
- `air.host_policy.nondeterministic_field`;
- `air.host_policy.raw_authority_rejected`.

Denied outputs are warning diagnostics because a deny decision can be a
successful policy outcome. Unknown outputs, unsupported profiles,
nondeterministic fields, raw authority, and object/map/payload command records
are failures.

The conformance fixture should include at least one non-game policy/ops package
and one interactive/visual package before this surface is used as Host ABI
promotion evidence.

Host ABI `0.11` remains not accepted in v0.25. `output.emit` remains deferred.
The current evidence supports promotion analysis only; it does not create a
runtime Host ABI import.

## 9. Kill Criteria

Stop the design or implementation if:

- the mock host starts performing real side effects;
- host policy becomes a raw platform API wrapper;
- the mock host implies `output.emit`;
- output intent execution becomes automatic;
- policy files carry secrets, tokens, credentials, raw URLs, raw logs, or
  private text;
- command arguments become dynamic objects, maps, or runtime JSON;
- the design requires Host ABI `0.11` before the promotion evidence gate is
  satisfied.

## 10. v0.25 Recommendation

Keep the reference mock host as evidence tooling in v0.25. Use it to prove
that command buffer semantics, Output Contracts, and host policy decisions are
generic across independent domains before considering any Host ABI `0.11`
runtime import.
