# RFC: v0.14 Package Graph Verify/Report/Check

Status: draft

Target milestone: AIR v0.14

## Summary

v0.14 should make package-level verify, report, and package-check operate over
the authored package-local AIR module graph. Authored `.air` modules are the
source of truth. Generated or flattened output is a build artifact, not the
primary review source.

This RFC does not add Host ABI functions and does not implement remote imports,
runtime imports, package registries, or arbitrary filesystem imports.

## Commands

Exact command names may adapt to existing CLI conventions, but the target
behavior is:

```sh
airc verify package <package-dir>
airc report package <package-dir> --json
airc package-check <package-dir> --profile <id>
```

Equivalent forms are acceptable if they preserve the same semantics, for
example:

```sh
airc verify <package-dir> --package
airc report <package-dir> --package --json
airc package-check <package-dir> --profile browser-webgpu --source-only
```

## Source Of Truth

The authored package-local `.air` modules are the source of truth.

Generated or flattened output:

- may be produced by build tooling;
- may be checked for freshness;
- may be included in review bundles;
- must not replace authored modules as the review source;
- must be treated as artifact, not authority.

Package reports should make this explicit by listing authored modules and
generated artifacts separately.

## Shared Module Graph

Verifier, report, and package-check must use the same resolved module graph.

Required behavior:

- resolve from the package entrypoint;
- include reachable package-local modules;
- preserve deterministic module ordering;
- preserve module ownership for declarations and diagnostics;
- expose graph errors consistently across verify/report/package-check.

If graph resolution fails, all three commands should report the same graph error
category and repair hint.

## Import Safety

Allowed imports are package-local source imports such as:

```air
use "./math.air" as math
use "../shared/fixed.air" as fixed
```

Rules:

- imports must start with `./` or `../`;
- resolved paths must remain inside the package root;
- remote imports are rejected;
- `file://` imports are rejected;
- absolute paths are rejected;
- arbitrary filesystem imports are rejected;
- missing imports fail deterministically.

Package-root import safety is a security boundary.

## Exported And Private Boundaries

Cross-module calls may target only exported functions.

Allowed:

```air
use "./math.air" as math

export func run(seed: i32) -> i32 {
entry:
  %next:i32 = call math.add_one(%seed)
  return %next
}
```

Rejected:

```air
use "./math.air" as math

export func run(seed: i32) -> i32 {
entry:
  %next:i32 = call math.internal_add_one(%seed)
  return %next
}
```

Private functions remain private at package graph level. Future linked output
must preserve that boundary.

## Capability Propagation

Package-level checks compute effective capabilities from all reachable modules.

Example:

```text
src/main.air -> src/audio_logic.air -> audio.beep
```

The package report must preserve:

- declared package capabilities;
- computed package capabilities;
- per-module capability declarations;
- capability origins;
- authority chains where practical.

A package that uses a capability through an imported module must declare that
capability in package metadata and select a host profile that supports it.

## Host Import Origin Reporting

Reports must list host imports by module.

Example JSON concept:

```json
{
  "hostImportOrigins": {
    "debug.metric": ["src/main.air"],
    "audio.beep": ["src/audio_logic.air"]
  }
}
```

Host import origin reporting must stay deterministic. It must not collapse
package authority into an opaque pass/fail.

## Deterministic Module Ordering

All package graph commands must emit modules in deterministic order.

Required properties:

- independent of filesystem iteration order;
- independent of absolute checkout path;
- stable across repeated runs;
- stable in JSON output;
- documented if topological order or normalized path order is chosen.

## Per-module Ownership Report

`airc report package <package-dir> --json` should include per-module ownership
metadata.

Required fields per module:

- module path;
- module name;
- imports;
- exported functions;
- private functions;
- globals;
- tables;
- capabilities;
- host imports;
- statement counts.

Example shape:

```json
{
  "modules": [
    {
      "path": "src/main.air",
      "name": "main",
      "imports": ["src/math.air"],
      "exports": ["run"],
      "privateFunctions": ["step"],
      "globals": [],
      "tables": ["retry_budget_ms"],
      "capabilities": ["debug"],
      "hostImports": ["debug.metric"],
      "statementCount": 12
    }
  ]
}
```

Statement counts are report metadata and anti-slop input. They are not verifier
failures unless a package review policy opts into budget enforcement.

## Diagnostics

Diagnostics should include:

- stable code;
- package-relative module path;
- source range where available;
- repair hint;
- deterministic JSON representation.

Required diagnostic categories:

- unresolved import;
- path escape;
- remote import;
- duplicate alias;
- import cycle;
- private function called externally;
- missing exported symbol;
- package capability missing for computed capability;
- unsupported host import for selected profile.

## Acceptance Tests

### Two-module Package Verifies

Fixture:

```text
package/
  air.package.json
  src/main.air
  src/math.air
```

Expected:

- package graph verifies;
- report lists both modules;
- package-check sees the same module graph.

### Private Function Cannot Be Called Externally

Expected:

- verify/report/package-check all surface the private/missing export error;
- diagnostic is deterministic;
- repair hint says to export a wrapper or keep the helper local.

### Unresolved Import Fails

Expected:

- missing package-local import fails;
- diagnostic includes the missing path and importing module.

### Path Escape Fails

Expected:

- `use "../../outside.air" as outside` fails if it escapes package root;
- no file outside the package root is read as AIR source.

### Capability Origin Is Reported

Expected:

- imported module capability contributes to computed package capabilities;
- report identifies the module that introduced the capability;
- package-check fails if package metadata omits that capability.

### Report Order Is Deterministic

Procedure:

```sh
airc report package package --json > a.json
airc report package package --json > b.json
diff a.json b.json
```

Expected:

- reports match exactly;
- module order, diagnostics, ownership fields, and origin maps are stable.

## Non-goals

- No linked multi-module Wasm implementation in this RFC.
- No remote imports.
- No runtime dynamic imports.
- No package registry.
- No arbitrary filesystem imports.
- No Host ABI changes.
- No demo-specific package semantics.
