# RFC: v0.29 Benchmark Report Schema

Status: implemented first slice

## Purpose

Define a stable first-slice JSON schema for AIR benchmark evidence. The schema
is intended for baseline measurement, trend analysis, and review. It is not a
performance claim by itself.

## Non-Goals

- no compiler optimization passes;
- no new language features;
- no AIR ABI changes;
- no Host ABI changes;
- no `output.emit` expansion;
- no performance dashboard UI;
- no public speed multiplier claims without measured evidence.

## Report Kind

Benchmark reports should use:

```json
{
  "schemaVersion": "0.29",
  "kind": "air.benchmarkReport"
}
```

## Top-Level Shape

First-slice report shape:

```json
{
  "schemaVersion": "0.29",
  "kind": "air.benchmarkReport",
  "status": "pass",
  "benchmarkName": "Fixed state basic",
  "benchmarkId": "fixed_state_basic",
  "packageHash": "sha256:...",
  "airAbi": "0.10",
  "hostAbi": "0.10",
  "runConfig": {},
  "metrics": {},
  "diagnostics": [],
  "limitations": []
}
```

`airAbi` is the AIR ABI used by the benchmark package. `hostAbi` is the Host
ABI required by the benchmark package or selected profile. It is not a
project-wide latest-version declaration. Host ABI latest is documented in
[Version and ABI Policy](../VERSION_AND_ABI_POLICY.md).

The first slice emits one report per benchmark directory. A future aggregate
runner may collect multiple `air.benchmarkReport` documents into a trend or
summary artifact without changing the single-benchmark report kind.

## Benchmark Entry

Each benchmark directory contains a `benchmark.json` descriptor:

```json
{
  "schemaVersion": "0.29",
  "kind": "air.benchmark",
  "benchmarkName": "Fixed state basic",
  "benchmarkId": "fixed_state_basic",
  "packageDir": "../../conformance_state",
  "profile": "cli",
  "trace": "../../conformance_state/traces/pass.json",
  "buildWasm": true,
  "runtime": {
    "export": "write_cell",
    "args": [1, 7]
  },
  "repeat": 4
}
```

Descriptor paths are benchmark-directory relative. Reported paths must be
repository-relative or benchmark-relative. Absolute paths are not allowed in
stable benchmark output.

## Metric Categories

The schema must represent these categories separately:

- runtime execution time;
- host crossing count;
- verification time;
- package-check time;
- report/evidence generation time;
- conformance replay time;
- artifact size;
- module/package size;
- AI repair iterations, as a plan-only metric.

## Metric Shape

The first slice uses direct scalar metrics so reports are easy to consume:

```json
{
  "verifierMs": 2,
  "packageCheckMs": 3,
  "reportMs": 1,
  "evidenceMs": 2,
  "conformanceReplayMs": null,
  "wasmBuildMs": null,
  "wasmExecutionMs": null,
  "hostCrossings": null,
  "outputEmitCount": 0,
  "commandBufferRecordCount": 0,
  "packageSizeBytes": 2048,
  "wasmSizeBytes": null
}
```

`null` means the metric is unavailable for that benchmark. The reason must be
listed in `limitations`.

## Required Metrics By Benchmark Class

### Fixed State

- runtime execution time;
- verification time;
- package-check time;
- report/evidence generation time;
- artifact size;
- conformance replay time when applicable.

### Output Emit vs Command Buffer

- host crossing count;
- `output.emit` call count;
- command record count;
- runtime execution time;
- mock host evidence time;
- conformance replay time;
- package/report timing.

### AirOps / FlowDesk Style

- verification time;
- package-check time;
- runtime execution time;
- report/evidence generation time;
- output intent count;
- package size;
- artifact size.

## Determinism Requirements

Stable benchmark JSON must not include:

- uncontrolled timestamps;
- absolute paths;
- random IDs;
- local temporary directories;
- private host data;
- raw logs, secrets, tokens, raw URLs, or payloads.

If elapsed wall-clock time is collected, the report must include environment
metadata and limitations. The first baseline should not use uncontrolled timing
as a release-blocking gate.

## First-Slice Diagnostics

The runner uses stable benchmark diagnostics:

- `air.benchmark.missing_dir`
- `air.benchmark.config_invalid`
- `air.benchmark.package_check_failed`
- `air.benchmark.report_failed`
- `air.benchmark.verify_failed`
- `air.benchmark.conformance_failed`
- `air.benchmark.wasm_build_failed`
- `air.benchmark.runtime_unavailable`
- `air.benchmark.package_size_unavailable`

## Claim Policy

Reports may include a `summary.claims` array, but v0.29 claims must be scoped
and evidence-backed. Broad claims such as `x50` or `x200` are not allowed unless
the benchmark report includes reviewed, reproducible evidence for that exact
scenario.

## ABI Status

AIR ABI latest remains `0.10`.

Host ABI latest is `0.11`, introduced in v0.26 for bounded `output.emit`
packages. Host ABI `0.10` remains the default/baseline compatibility target for
packages that do not use `output.emit`. This schema adds no host imports,
runtime authority, payload support, or language features, and v0.29 does not
expand Host ABI.
