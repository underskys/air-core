# RFC: v0.28 Output Emit Ergonomics Hardening

Status: active v0.28 hardening RFC

## Purpose

v0.26 introduced bounded Host ABI `0.11` `output.emit`. v0.27 stabilized
evidence, adapter boundaries, diagnostics, and API gates. v0.28 hardens the
authoring path so AI-authored packages stop depending on raw magic-number
`output_id` literals where generated output handles are available.

This RFC does not add Host ABI features and does not expand `output.emit`.

## Current Baseline

- Output Contracts define output ids, names, channels, capabilities, and scalar
  arg schemas.
- `airc generate output-handles <package-dir>` writes:
  - `generated/output_handles.air`;
  - `generated/output_handles.meta.json`.
- Generated handles are package-visible derived artifacts.
- Package-check/report/verification evidence expose generated handle status as
  `outputHandleSets`.
- LSP-lite and diagnostics-only Full LSP surface package-check diagnostics for
  missing, stale, or mismatched generated handles.

## Canonical Authoring Path

Canonical packages that declare `generated/output_handles.air` in
`generatedModules` should use generated `OUTPUT_*` constants for `output.emit`
output ids.

Do:

```air
%status:i32 = @output.emit(OUTPUT_INCIDENT_RECOMMEND_ACTION, %arg0, %arg1, %arg2, %arg3)
```

Do not:

```air
%status:i32 = @output.emit(1001, %arg0, %arg1, %arg2, %arg3)
```

Raw numeric ids may remain in low-level verifier/runtime tests, rejection
fixtures, ABI conformance fixtures, and docs that explain the underlying Host
ABI.

## Source Of Truth

Output Contracts remain the source of truth. Generated output handles must not:

- define new outputs;
- change output ids;
- change capabilities;
- grant host authority;
- bypass Output Contract validation;
- bypass profile compatibility checks.

Generated handles are derived from Output Contracts and must be regenerated when
contracts change.

## Generated AIR Shape

`generated/output_handles.air` is frozen as constants-only first slice.

Allowed:

```air
const OUTPUT_INCIDENT_RECOMMEND_ACTION:i32 = 1001
const OUTPUT_INCIDENT_RECOMMEND_ACTION_ID:i32 = 1001
const OUTPUT_INCIDENT_RECOMMEND_ACTION_ARG_COUNT:i32 = 4
```

Rejected in v0.28:

- generated emit wrapper functions;
- hidden compiler exports;
- generated `output.emit` calls;
- host imports;
- dynamic dispatch;
- string/object/JSON/payload helpers.

## Metadata Shape

`generated/output_handles.meta.json` remains deterministic metadata. It records:

- schema version;
- kind;
- generator;
- source Output Contract paths and fingerprints;
- generated file paths and fingerprints;
- output ids;
- output names;
- generated handle names;
- arg counts and scalar arg types.

The metadata file is not source of truth. It is freshness evidence for generated
artifacts derived from Output Contracts.

## Freshness Validation

Packages that declare `generated/output_handles.air` in `generatedModules` must
keep both generated files fresh.

Package-check/report/LSP diagnostics cover:

- missing generated output handle AIR file;
- missing or invalid metadata;
- stale source contract fingerprints;
- mismatched output metadata;
- generated file fingerprint mismatch;
- missing or unknown `OUTPUT_*` constants.

## Reports And Verification Evidence

Package reports and verification evidence expose `outputHandleSets`. The shape
must stay stable enough for downstream review tooling:

- generated AIR path;
- metadata path;
- status;
- source fingerprint;
- generated fingerprint;
- source contracts;
- outputs;
- diagnostics.

No raw payloads, private data, host object handles, or new host authority are
introduced by this evidence.

## LSP Diagnostics

LSP-lite and diagnostics-only Full LSP must continue to reuse package-check
diagnostics. v0.28 must not create a parallel LSP diagnostic engine and must not
add LSP code actions.

Stable diagnostics include:

- `air.generated.output_handles_missing`;
- `air.generated.output_handles_stale`;
- `air.generated.output_handles_mismatch`;
- `air.generated.output_metadata_invalid`;
- output-handle constant mismatch diagnostics.

## API Gates

v0.28 API gates should reject in canonical generated-handle examples:

- raw numeric `output_id` in `output.emit` when a generated handle exists;
- generated emit wrapper functions;
- dynamic `output_id`;
- string/object/JSON/payload output args;
- hidden host imports or hidden compiler exports in generated handle files.

The gates should remain conservative and low-noise. Docs-only rejected/future
mentions and low-level ABI/rejection fixtures may continue to discuss raw ids.

## ABI Status

AIR ABI remains `0.10`.

Host ABI remains `0.11` only for the bounded `output.emit` first slice. v0.28
does not add host imports, wrapper functions, dynamic output ids, richer
payloads, event streams, or automatic side-effect guarantees.

## Non-Goals

- generated emit wrapper functions;
- dynamic `output_id`;
- `output.event`;
- `audio.event`;
- `effect.event` / `effect_event`;
- string, object, map, JSON, payload, pointer, or slice output args;
- runtime JSON/object model;
- host object handles;
- raw Chrome/DOM/DB/cloud/Kubernetes/Jira/fetch authority;
- LSP code actions;
- real platform adapters.

## Acceptance

- Generated output handles are documented as the stable canonical authoring path
  for packages that opt into them.
- Output Contracts remain source of truth.
- Generated artifacts remain constants-only and deterministic.
- Freshness validation remains a hard gate for package-declared generated
  handles.
- `outputHandleSets` remains visible in report/evidence.
- LSP diagnostics remain package-check sourced.
- v0.28 API gates prevent wrapper/dynamic/payload creep.
- AIR ABI remains `0.10`.
- Host ABI remains limited to bounded `output.emit`.
