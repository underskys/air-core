# AIR v0.22 RFC: Fixed Bounded State Segment

Status: RFC skeleton / design only

Purpose: decide whether Fixed Bounded State Segment is acceptable as a future
Core semantic feature for persistent bounded AIR-owned scalar state.

This RFC does not implement state segments. It does not change parser,
verifier, lowering, AIR ABI, Host ABI, host imports, Output Contracts, command
buffers, demos, or examples.

## 1. Scope

Fixed Bounded State Segment is a candidate AIR Core semantic feature:

- statically declared;
- fixed max length;
- scalar cells only;
- deterministic initialization;
- persistent per AIR execution instance / package execution instance;
- verifier-counted reads and writes;
- report-visible budgets;
- conformance-visible final-state evidence.

The feature is not accepted for implementation by this RFC skeleton. v0.22 P0
is design and gates only unless separately approved later.

## 2. Backend-Neutral AIR Semantics

State must be specified as AIR semantic storage first. AIR is not conceptually
Wasm-only. Wasm is the current primary backend and lowering target, not the
semantic definition of the feature. Do not define Fixed Bounded State Segment as
Wasm-only memory.

## 3. State Sharing And Execution Instances

- state belongs to one AIR execution instance / package execution instance;
- state is not shared package-global mutable state;
- parallel executions or parallel AI agents use separate state instances;
- re-instantiating the package resets state unless a future reset/persistence
  RFC says otherwise;
- no shared memory;
- no atomics;
- no cross-instance state;
- no host-visible shared state.

## 4. Minimal First-Slice Candidate

Chosen first-slice syntax for v0.23 parser/formatter implementation:

```air
state board:i32[200] = fill 0

func read_cell(index: i32) -> i32 {
entry:
  %cell:i32 = state.get board, %index
  return %cell
}

func write_cell(index: i32, value: i32) -> i32 {
entry:
  state.set board, %index, %value
  return %value
}
```

Candidate first slice:

- `state name:i32[N] = fill 0`;
- possible literal init form such as `state name:i32[N] = fill 7`;
- `state.len name -> i32`;
- `state.get name, idx -> i32`;
- `state.set name, idx, value`;
- `i32` cells only;
- fixed length;
- zero or literal init;
- per execution instance persistence;
- no compact state;
- no `u8`/`u16`/`i16` state cells;
- no tablegroups;
- no pointer, slice, or reference escape;
- no state export as raw memory;
- no host direct state access.

Rejected/deferred syntax alternatives:

- `state board:i32[200] = 0`;
- `state board { type: i32, len: 200, init: 0 }`.

The chosen syntax is preferred because it is close to existing static table
syntax, compact and AI-friendly, explicit about cell type and fixed length, and
straightforward for parser/formatter implementation in v0.23.

Final parser behavior will be implemented in v0.23. v0.22 remains docs,
RFC, and gates only.

## 5. Verifier Obligations Vs Report Visibility

Verifier must prove or enforce before any implementation is accepted:

- fixed state length;
- deterministic initialization;
- no uninitialized cells;
- scalar cell type validation;
- no pointer, slice, or reference escape;
- static out-of-bounds rejection;
- dynamic bounds check or deterministic trap;
- read/write budget upper bounds;
- loop upper-bound multiplied state read/write accounting;
- no host direct state access;
- no dynamic allocation or resizing;
- aliasing rules that keep each state segment named and non-overlapping.

Report/evidence must show:

- state segment names;
- cell type;
- length;
- static byte size;
- declared read/write budgets where available;
- module-level observed read/write counters where available;
- final state digest for conformance where available;
- diagnostics and budget violations.

Report visibility is not proof. If the verifier cannot prove or enforce a
property, reports must not imply that it was proven.

## 6. Lowering / Runtime Model

Lowering is design-only in v0.22.

Candidate Wasm backend strategies:

- compiler-managed memory region for state;
- per-Wasm-instance linear memory region reserved for state;
- backend-private globals only for scalar singleton state if appropriate;
- data-segment initialization plus mutable per-instance memory;
- deterministic trap on dynamic out-of-bounds access.

Mandatory isolation rule:

- AIR state is a separate semantic address space.
- Current Wasm backend may lower state to compiler-managed memory.
- User-visible memory operations must not alias state.
- State base addresses must not be exposed.
- State pointers, slices, and references must not escape.
- If physical lowering shares Wasm linear memory, aliasing must be impossible by
  construction.
- If aliasing cannot be proven, implementation must stop rather than accept
  unsafe lowering.

The AIR semantic model must not expose Wasm pointers, slices, references, or raw
memory addresses to hosts. It must also avoid raw memory aliasing between state
segments and user-visible memory. Wasm per-instance memory is only the current
backend model, not the semantic definition.

This is not a Host ABI feature. Hosts must not directly read or write AIR state.

Interactions to specify before implementation:

- existing mutable globals;
- static tables;
- arrays and buffers;
- memory operations;
- effect budgets;
- conformance reset/init behavior.

## 7. Conformance And Evidence

Design requirements:

- final state digest;
- optional explicit exported scalar snapshot helpers;
- deterministic reset/init;
- deterministic replay;
- mismatch diagnostics for digest mismatch, cell mismatch, trap mismatch,
  budget violation, and unsupported profile;
- no wall-clock dependency;
- no randomness;
- no local environment dependency;
- no host state read API;
- report fields for state name, cell type, length, static byte size, declared
  read/write budgets, and module-level observed read/write counters where
  available;
- verification evidence fields if state becomes package-visible.

Minimal evidence JSON shape:

```json
{
  "stateSegments": [
    {
      "name": "board",
      "cellType": "i32",
      "length": 200,
      "byteSize": 800,
      "persistent": true,
      "exported": false,
      "shared": false,
      "readBudget": {
        "declared": 1200
      },
      "writeBudget": {
        "declared": 400
      },
      "moduleObservedReads": 800,
      "moduleObservedWrites": 120,
      "finalDigest": "sha256:...",
      "diagnostics": []
    }
  ]
}
```

`finalDigest` may be absent until conformance support lands. Raw state values
are not exposed by default. `exported: false` means the state segment itself is
not exported as ABI. `shared: false` means there is no cross-instance shared
mutable state.

Reports must not include private raw host data. Synthetic example snapshots may
use scalar cells only.

## 8. Migration From Existing Surfaces

Current surfaces remain valid:

- scalar parameters and returns for small pure decisions;
- globals for small scalar state;
- static tables for readonly lookup data;
- arrays and buffers where already supported;
- bounded rowset schemas for host-owned structured input metadata;
- command buffers for output intent metadata;
- conformance fixture JSON as host/test-owned input/output evidence.

Fixed Bounded State Segment must not become dynamic arrays, runtime JSON,
host object handles, or a replacement for host-owned rich state.

## 9. Output Contract Boundary

First slice must not introduce state-conditional Output Contract semantics.
Output Contract manifests remain state-independent declarations.

State may influence:

- exported scalar function results;
- internal deterministic decisions;
- future command buffer contents only if the command buffer contract already
  exists.

State must not:

- mutate Output Contract definitions;
- conditionally grant or revoke host authority;
- imply `output.emit`;
- imply Host ABI `0.11`;
- create automatic host-side action execution.

## 10. Demo Pressure Triage

| Pressure | Classification | Routing |
| --- | --- | --- |
| Airtris board cells | Core pressure for fixed scalar state; example/kit for dimensions and cell meanings. | Core RFC may consider generic fixed state only. Board size, piece IDs, scoring, and visuals stay example/kit/host-owned. |
| Airtris row compaction | Core pressure for bounded reads/writes and loops; stdlib only if a generic pure helper emerges. | Row rules and gameplay semantics stay example/kit. |
| Airtris seven-bag shuffle | Example/kit pressure for deterministic scalar state and pseudo-random policy. | Core must not add game-specific shuffle APIs. Host/test owns seed policy unless a generic deterministic state RFC accepts a scalar pattern. |
| Airtris visual events | Host / command buffer / Output Contract evidence; no Core host authority. | No `output.emit`; host policy owns execution. |
| Minesweeper board/reveal/flag/snapshot | Core pressure for fixed scalar state and final-state digest/snapshot evidence; example/kit for game semantics. | UI semantics, blast visuals, cell naming, and game-specific helpers stay outside Core. |
| PhotoLoop pixel/channel kernels | Example/kit pressure first; possible Core only for generic bounded scalar channel/kernel decisions after RFC acceptance. | No Canvas/ImageData/export/filesystem/browser/renderer/GPU authority in Core. |
| Canvas/ImageData/export | Host-owned / rejected from Core. | Host owns image decode, Canvas, ImageData, export, filesystem/browser/renderer/GPU authority. |

Demo pressure is evidence, not authority.

## 11. PhotoLoop / Pixel Boundary

PhotoLoop pressure must not be interpreted as Canvas, ImageData, pixel-buffer,
filesystem, browser, renderer, or GPU authority in Core. Host owns image decode,
Canvas, ImageData, export, filesystem/browser/renderer/GPU authority.

AIR may eventually compute bounded scalar channel/kernel decisions only if
generic state/kernel RFCs accept that shape. No pixel-specific Core API is
accepted by this RFC.

## 12. API Gates Update Plan

Candidate gate categories:

- no pointer/slice/reference escape from state;
- no shared mutable state across execution instances;
- no state fields that imply runtime JSON/object model;
- no host direct state access;
- no state-conditional Output Contract declarations;
- no Canvas/ImageData/pixel-buffer authority in Core;
- no game-specific state helpers in Core or stdlib;
- no report claim that treats visibility as proof.

Machine checks should remain conservative and low-noise until syntax exists.

## 13. ABI Impact

AIR ABI remains `0.10` during v0.22 planning.

AIR ABI `0.11` may be required only if an accepted implementation changes
executable package/runtime contracts, entrypoints, calling convention,
memory/data layout, runtime-required metadata, or AIR-owned value/payload
representation.

Host ABI remains `0.10`. Fixed Bounded State Segment should not require Host ABI
`0.11`, host imports, host direct state access, or host authority.

## 14. Kill Criteria

Stop or reject the feature if the design requires:

- runtime-sized state;
- dynamic collections;
- dynamic collection length;
- arbitrary runtime JSON values;
- JSON, object, or map state;
- object fields or dynamic keys;
- host object handles;
- pointer, slice, or reference escape;
- shared mutable state across execution instances;
- state-conditional host authority;
- reports pretending to prove unenforced properties;
- Canvas, ImageData, pixel-buffer, renderer, GPU, filesystem, browser, network,
  or raw `chrome.*` authority in Core;
- game-specific Core APIs;
- automatic host-side action execution;
- unbounded read/write effects that cannot be reported or budgeted;
- silent truncation;
- Host ABI `0.11` dependency.

## 15. Deferred

- parser implementation;
- verifier implementation;
- lowering implementation;
- compact state;
- tablegroups;
- state snapshots as ABI;
- host direct state access;
- pixel kernels;
- `output.emit`;
- Host ABI `0.11`;
- AIR ABI `0.11`;
- game-specific helpers.

## Acceptance For v0.22 P0

- RFC exists and clearly separates pressure, design, and implementation.
- Backend-neutral AIR semantic storage framing is explicit.
- Per-execution-instance semantics are explicit.
- Verifier proof/enforcement obligations are separated from report visibility.
- Output Contract manifests remain state-independent declarations.
- PhotoLoop/Canvas/ImageData/export authority remains host-owned and outside
  Core.
- Verifier model, lowering model, conformance/evidence model, and ABI impact
  questions are reviewable.
- Airtris, Minesweeper, and PhotoLoop pressure is triaged without granting demo
  authority.
- Kill criteria are explicit.
- No implementation is added.
