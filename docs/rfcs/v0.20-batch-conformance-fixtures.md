# AIR v0.20 RFC: Batch Conformance Fixtures

Status: active first slice

Target milestone: v0.20

## Purpose

Batch conformance fixtures connect bounded rowset schema metadata, expected
output intent records, and deterministic replay reports without adding runtime
JSON, command buffers, or Host ABI output imports.

The first slice covers two non-game pressure fixtures:

- FlowDesk-style task summary pressure;
- AirOps-style incident observation pressure.

## Boundary

Fixture JSON is host/test-harness input. It is not AIR runtime JSON. AIR does
not parse fixture JSON, receive arbitrary JSON objects, access dynamic object
fields, or receive host object handles.

The harness owns fixture decoding. AIR remains responsible only for deterministic
scalar logic and package-visible metadata. Hosts remain responsible for rich
state, secrets, URLs, private text, browser/platform authority, and real
side-effect execution.

## Trace Shape

Batch fixtures use `airc conformance <package-dir> --profile <profile> --trace
<trace.json> --json` with:

```json
{
  "schemaVersion": "0.20",
  "kind": "air.conformance.batchFixture",
  "id": "flowdesk-task-summary-batch",
  "package": "flowdesk-batch-conformance-fixture",
  "profile": "cli",
  "rowsets": [
    {
      "name": "task_summary",
      "schema": "facts/task_summary.rowset.schema.json",
      "rows": [
        { "task_id": 101, "status_id": 2, "priority": 95, "flags": 1 }
      ]
    }
  ],
  "observedOutputs": [
    {
      "id": 1001,
      "name": "priority_alert_requested",
      "channel": "notification",
      "args": [101, 3, 1],
      "flags": 0
    }
  ],
  "expectedOutputs": [
    {
      "id": 1001,
      "name": "priority_alert_requested",
      "channel": "notification",
      "args": [101, 3, 1],
      "flags": 0
    }
  ]
}
```

`observedOutputs` are harness-captured scalar output intent records. In v0.20
they are fixture evidence, not runtime `output.emit` records. A future command
buffer or Host ABI can replace the capture source only after a separate accepted
RFC.

## Validation

The replay harness validates:

- trace schema version and kind;
- package/profile match;
- package-check status in source-only mode;
- rowset fixture names and referenced bounded rowset schemas;
- row counts against schema `maxRows`;
- row fields against declared scalar `i32`/`bool` columns;
- row ranges where declared by schema metadata;
- expected and observed output intent record count;
- output intent ID, channel, args, and flags;
- scalar-only output args;
- absence of raw text, raw URLs, tokens, secrets, credentials, host-local paths,
  timestamps, random IDs, nonces, and other nondeterministic fields.

## Report Fields

Batch conformance reports use `kind: "air.conformance.report"` and include:

- `schemaVersion: "0.20"`;
- `mode: "batch"`;
- package and profile;
- trace ID, trace kind, and trace fingerprint;
- deterministic `replayChecksum`;
- rowset summaries;
- observed and expected output intent summaries;
- package-check diagnostics;
- mismatch diagnostics;
- unsupported profile summary.

The replay checksum is derived from stable package/profile/trace metadata,
rowset summaries, and output intent comparison records. It must not include
wall-clock time, absolute paths, randomness, or mutable local state.

## Mismatch Diagnostics

The first slice defines stable diagnostics for:

- `air.conformance.wrong_output_count`;
- `air.conformance.wrong_output_id`;
- `air.conformance.wrong_output_channel`;
- `air.conformance.wrong_args`;
- `air.conformance.unsupported_profile`;
- `air.conformance.privacy_leak`;
- `air.conformance.row_bound_exceeded`;
- `air.conformance.nondeterministic_output`.

## Non-goals

- no command/result buffer implementation;
- no `output.emit`, `output.event`, `audio.event`, or `effect.event`;
- no Host ABI `0.11`;
- no AIR ABI `0.11`;
- no AIR runtime JSON object model;
- no dynamic maps;
- no tablegroup syntax;
- no generated rowset handles;
- no browser, Chrome, infra, or host authority.

## Acceptance Tests

- FlowDesk-style fixture passes;
- AirOps-style fixture passes;
- wrong expected output fails;
- row bound exceeded fails;
- privacy leak fails;
- unsupported profile fails;
- replay report and checksum are deterministic;
- reports contain no absolute paths or timestamps.
