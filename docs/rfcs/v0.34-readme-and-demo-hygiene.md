# AIR v0.34 README and Demo Hygiene RFC

Status: proposed / v0.34 P0 planning

## Purpose

AIR's README and docs index have accumulated useful milestone history. That
history now creates agent-context noise and makes active guidance harder to
scan.

v0.34 should separate active onboarding from historical release context without
deleting old docs or moving demos.

## Current Problem

The root README currently carries:

- current project identity;
- active milestone status;
- ABI status;
- long milestone history;
- architecture overview;
- quick start commands;
- host/demo notes.

This is accurate but too dense for agent preflight context. Agents need the
current status, boundaries, and next links first; historical detail should be
available through a release index.

## P0 Decisions

v0.34 should:

- slim the root README to current AIR identity, ABI status, active milestone,
  boundaries, quick start, and durable strategy links;
- move detailed milestone history to `CHANGELOG.md` or `docs/releases/`;
- keep old milestone docs in place;
- avoid deleting historical docs;
- avoid moving demos;
- document examples/demos/snapshots classification;
- keep AIR strategy docs linked from active guidance.

## Milestone History Destination

Acceptable first-slice destinations:

- root `CHANGELOG.md`; or
- `docs/releases/README.md` plus per-release summaries.

The destination should preserve links to existing milestone docs instead of
copying every detail into the README.

## Examples / Demos / Snapshots Classification

v0.34 should document the review role of common repository surfaces:

| Surface | Role | Review-bundle expectation |
| --- | --- | --- |
| `examples/` | Canonical and educational AIR examples. | Include small deterministic sources and package descriptors. |
| `test/fixtures/` | Deterministic test and conformance fixtures. | Include required fixtures for Core tests and review surfaces. |
| `benchmarks/` | Deterministic benchmark descriptors and READMEs. | Include descriptors, not large runtime output. |
| `evals/` | Deterministic replay eval fixtures. | Include prompts, captured outputs, repair transcripts, constraints, and reports that are safe. |
| `demo/` / `demos/` | Project-specific demos or external pressure surfaces. | Keep separate from Core review unless explicitly using demo review flow. |
| review snapshots | Generated review artifacts. | Include only selected summaries and bundle metadata; exclude large logs unless required. |

## Demo Boundary

Demo-specific behavior must remain outside Core language/API decisions unless
routed through an accepted pressure request, RFC, or architecture gate.

v0.34 should not:

- move demos;
- delete demos;
- change demo code;
- import demo vocabulary into Core;
- use demo-local pressure as direct authority.

## README Target Shape

The slim README should prioritize:

1. project identity;
2. current milestone;
3. AIR ABI and Host ABI status;
4. what AIR is and is not;
5. quick start;
6. links to strategy, architecture, version/ABI policy, active feature status,
   release plan, and docs index.

Detailed milestone history should move out of the first viewport.

## Docs Index Target Shape

`docs/README.md` should keep:

- active guidance;
- durable strategy/governance links;
- previous milestone index;
- archive pointer.

It should not present old milestones as active.

## Non-goals

- no compiler changes;
- no AIR ABI changes;
- no Host ABI changes;
- no language features;
- no demo edits;
- no deletion of old docs;
- no repository directory restructuring;
- no lan-observer proof.

## Acceptance Criteria

Before v0.34 closes:

- README is slim enough for agent preflight context;
- detailed milestone history is moved to a changelog or release index;
- active docs still link AIR strategy and architecture boundaries;
- examples/demos/snapshots classification is documented;
- review bundle policy is aligned with the classification;
- markdown links pass;
- `git diff --check` passes.
