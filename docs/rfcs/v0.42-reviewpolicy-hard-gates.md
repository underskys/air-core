# RFC v0.42: ReviewPolicy Hard Gates

Status: planning

## Summary

Define hard gates for reviewPolicy regressions after readonly tablegroups and
declared fixed-capacity pools. The goal is to make anti-slop diagnostics
actionable without blocking known baseline debt.

## Motivation

reviewPolicy already flags patterns such as:

- select-chain-as-table;
- undeclared mutable slot families;
- debug.metric misuse;
- table-like scalar families.

v0.37 introduced readonly tablegroups for intentional static related data.
v0.41 introduced declared pools for intentional bounded mutable repeated state.
v0.42 defines how reviewPolicy uses those accepted constructs to distinguish
intentional structure from accidental AI-slop.

## Hard Gate Model

The hard gate should fail on new regressions for:

- select-chain-as-table patterns not represented as readonly tablegroups;
- undeclared mutable slot-family patterns not represented as declared pools;
- debug.metric usage as an event bus or runtime control surface;
- generated handle drift where source contracts are unchanged;
- package/resource validation failures promoted to hard errors.

Known baseline debt may be recorded and allowed only when explicit.

The gate input is a deterministic reviewPolicy report plus an explicit baseline
file. The gate output is a deterministic pass/fail report. It must not depend on
wall-clock time, filesystem traversal order, or external services.

## Baseline Debt

Baseline debt records should include:

- diagnostic id;
- affected file/module;
- first accepted baseline commit or release;
- reason;
- owner;
- cleanup status;
- whether new instances are forbidden.

Baseline hash:

- should be computed from normalized baseline entries;
- must use stable sorting;
- must omit timestamps and absolute paths;
- should be emitted as `baselineHash` in reports/evidence.

Allowed waiver model:

- waivers must be explicit and package/repo-local;
- every waiver must include diagnostic id, affected path/module, reason, owner,
  and expiry or review milestone when possible;
- broad wildcard waivers are invalid unless they name a specific baseline debt
  bucket;
- waivers cannot permit forbidden host authority, ABI drift, runtime JSON/object
  model, or demo-specific Core APIs.

The trend compare must fail when:

- a diagnostic count increases outside accepted baseline;
- a new diagnostic id appears as hard-gated;
- a baseline exception is removed from config but issue remains;
- a declared-pool/tablegroup exception is misapplied.
- a waiver is malformed, expired, too broad, or references a missing diagnostic.

Regression model:

- known baseline debt can remain as `waived` only when matched exactly;
- new instances are `regressions`;
- fixed baseline entries reduce debt and should not fail;
- reintroduced fixed debt fails as a regression;
- diagnostic ordering must be stable.

## Exceptions

Readonly static related data:

- should use tablegroups;
- may suppress select-chain-as-table warnings when represented as tablegroups;
- should not suggest declared pools.

Mutable repeated state:

- should use declared pools when it is bounded and intentional;
- may suppress slot-family warnings when represented as declared pools;
- should not suggest readonly tablegroups.

Generated handles:

- should use generated handle freshness checks;
- should not be treated as semantic source of truth.
- may suppress generated-artifact drift warnings only when freshness metadata
  proves the artifact was derived from the current source contract.

Command streams:

- should use output contracts, bounded `output.emit`, or command buffers;
- should not be modeled as tablegroups or pools.

## `debug.metric`

`debug.metric` remains diagnostics-only. It must not become:

- event bus;
- host command channel;
- runtime policy input;
- hidden authority surface.

Misuse as an event bus should produce
`air.review_policy.debug_metric_event_bus`.

## Stable Diagnostics

Planned diagnostic codes:

- `air.review_policy.select_chain_regression`;
- `air.review_policy.slot_family_regression`;
- `air.review_policy.debug_metric_event_bus`;
- `air.review_policy.baseline_missing`;
- `air.review_policy.waiver_invalid`.

## Report/Evidence

Reports and evidence should expose:

- `reviewPolicyGateResults[]`;
- hard-gated diagnostics;
- baseline debt entries;
- new regressions;
- exceptions applied;
- declared-pool/tablegroup suppressions;
- repair hints where safe.
- `baselineHash`;
- `regressionCount`;
- `waivedCount`;
- `failedGateCount`.

## Non-Goals

- no automatic code actions;
- no automatic rewrite;
- no new language features;
- no Host ABI changes;
- no AIR ABI changes;
- no demo-specific Core APIs;
- no external demo source changes.
- no browser/Vite bundling;
- no asset pipeline rewrite;
- no external service validation.

## Kill Criteria

Stop if the hard gate model requires:

- domain-specific platformer rules in Core;
- browser/Vite bundling semantics;
- hidden host authority;
- generated artifacts as semantic source of truth;
- nondeterministic trend comparison;
- broad false-positive suppression that hides new AI-slop.
