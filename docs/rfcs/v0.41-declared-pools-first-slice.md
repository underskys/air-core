# RFC v0.41: Declared Pools First Slice

Status: implemented first slice

Milestone: v0.41

## Summary

v0.41 implements the first slice for declared fixed-capacity pools.
The goal is to distinguish intentional bounded mutable repeated state from
accidental scalar slot-family slop without adding a dynamic heap, object model,
GC, host handles, or game-specific APIs.

This document remains the implementation decision record. The implemented first
slice follows this record without changing AIR ABI or Host ABI.

## Source Of Truth

The pool declaration is the semantic source of truth:

- capacity;
- field list;
- field types;
- required active flag;
- owner module;
- package/report visibility.

Generated pool handles, metadata, or host binding helpers are derived artifacts.
They must never become semantic source of truth and must be freshness-checked if
introduced later.

## Exact First-Slice Syntax

The accepted first-slice syntax is:

```air
pool projectiles capacity 8 {
  active:bool = false
  x:i32 = 0
  y:i32 = 0
  vx:i32 = 0
  vy:i32 = 0
}
```

Rules:

- `capacity` must be a positive integer literal;
- `active:bool` is required;
- field names are static source names, not runtime values;
- fields must be scalar;
- allowed field types are exactly `i32` and `bool`;
- field initializers must be scalar literals of the declared field type;
- no nested records;
- no strings;
- no dynamic field names;
- no object, map, `any`, or JSON fields.

The `active` field is required for reviewability and future helper semantics,
but in the first slice it is only an ordinary declared `bool` field. It does not
create implicit allocation, free, spawn, or find-inactive behavior.

## Exact First-Slice Operations

The accepted first-slice operations are:

```air
%cap:i32 = pool.capacity @projectiles
%v:i32 = pool.get.i32 @projectiles.x, %idx
pool.set.i32 @projectiles.x, %idx, %value
%a:bool = pool.get.bool @projectiles.active, %idx
pool.set.bool @projectiles.active, %idx, %value
```

First-slice operations are direct indexed reads/writes. They do not allocate,
free, spawn, compact, iterate, search for inactive slots, or expose backing
storage.

Deferred operations and surfaces:

- `pool.spawn`;
- `pool.free`;
- `pool.find_inactive`;
- `pool.clear`;
- `pool.iter`;
- slices/pointers/references;
- host readback;
- compact storage.

## Semantics

A pool is per-execution-instance mutable AIR state. It is not shared between
package runs unless existing runtime instance semantics already preserve module
state for a long-lived instance. v0.41 does not add a new sharing or persistence
contract.

Semantics:

- pool capacity is fixed at declaration time;
- every field is a private array of `capacity` slots;
- every slot starts with the declared field initializer value;
- writes are deterministic AIR state updates;
- reads return the current field value at the selected slot;
- the active flag is just a first-slice field, not an implicit allocator;
- static out-of-bounds indexes are verifier errors;
- dynamic indexes must use deterministic bounds checks or existing
  state/table-style bounds semantics;
- no pointer, slice, reference, host handle, or field/slot address may escape;
- no runtime JSON/object/map behavior is created.

## Relation To Fixed State And Tablegroups

Fixed state, readonly tablegroups, and declared pools are distinct:

- fixed state is individual mutable scalar values or fixed state cells;
- readonly tablegroup is static readonly row data;
- declared pool is repeated mutable scalar state with declared capacity;
- pool is not tablegroup mutation;
- pool is not a dynamic array, map, object model, or hidden heap.

reviewPolicy should recommend tablegroups for readonly related static data and
declared pools for intentional mutable repeated state.

## Lowering Strategy

Preferred lowering:

- lower each pool field to existing fixed-state/private storage machinery when
  practical;
- otherwise use minimal compiler-managed private storage;
- keep layout private to the compiler/lowered module;
- expose no host-visible pool layout contract;
- add no Host ABI imports.

Implementation must stop and report instead of proceeding if it needs:

- a broad `lower_wasm` rewrite;
- a new runtime ABI;
- host/runtime understanding of pool layout;
- new host-visible import/export semantics.

## Verifier Obligations

The verifier must prove or reject:

- capacity is a positive fixed integer literal;
- every field type is supported;
- the required `active:bool` field exists;
- every operation targets an existing pool and field;
- operation type suffix matches field type;
- static indexes are within capacity;
- dynamic indexes lower to deterministic checked behavior;
- writes target declared fields only;
- no field, slot, pointer, slice, reference, or host object handle escapes;
- no dynamic capacity;
- no runtime JSON/object/map fields;
- loop/update patterns remain within existing bounded execution rules;
- loop budget accounting uses static upper bounds where available.

## Report, Evidence, Diff, And Replay

Pool metadata appears under `pools[]` without raw private slot values by
default.

Required fields:

- `name`;
- `ownerModule`;
- `capacity`;
- `fields[]`;
- `activeField`;
- `storageFootprint` when statically known;
- read/write budget or operation counts if available;
- generated artifact status if generated handles exist;
- diagnostics.

Package diff should show changes to pool capacity, fields, active flag, owner,
and generated artifact status. Replay/evidence should summarize pool metadata
and bounds without exposing raw slot values by default.

## reviewPolicy Behavior

reviewPolicy must distinguish:

- declared pools suppress intentional slot-family warnings for owned slots;
- undeclared mutable slot-family patterns remain warnings/errors;
- readonly static related data should suggest readonly tablegroup, not pool;
- mutable repeated state may suggest declared pool, not tablegroup;
- generated handles remain derived artifacts, not pool semantics;
- command streams remain command buffers, not pools.

Declared pools suppress intentional slot-family warnings only for the declared
pool surface. They must not suppress unrelated scalar slop.

## Diagnostics

Stable planned diagnostics:

- `air.pool.invalid`;
- `air.pool.capacity_invalid`;
- `air.pool.active_flag_missing`;
- `air.pool.field_type_invalid`;
- `air.pool.unknown_pool`;
- `air.pool.unknown_field`;
- `air.pool.index_out_of_bounds`;
- `air.pool.dynamic_capacity_rejected`;
- `air.pool.object_model_rejected`;
- `air.pool.pointer_escape`;
- `air.pool.loop_budget_exceeded`;
- `air.pool.mutable_tablegroup_rejected`.

## ABI Decision

AIR ABI remains `0.10` if implementation uses private compiler-managed state and
existing call/runtime conventions.

Host ABI remains unchanged. Pools are AIR-owned bounded state and do not add
host imports.

If implementation needs a new runtime/executable contract, new calling
convention, host/runtime-visible pool layout contract, or new import/export
semantics, implementation must stop and require ABI review.

## Acceptance Tests

Implementation is complete when tests cover:

- valid pool parses, verifies, lowers, and runs;
- missing active flag fails;
- invalid capacity fails;
- invalid field type fails;
- unknown pool fails;
- unknown field fails;
- static out-of-bounds access fails;
- dynamic bounds behavior is deterministic;
- pool report/evidence visibility exists;
- package diff shows pool metadata changes;
- reviewPolicy distinguishes declared pool from accidental slot family;
- readonly static related data suggests tablegroup, not pool;
- mutable repeated undeclared state suggests declared pool, not tablegroup;
- runtime JSON/object/map fields fail;
- host object handles fail;
- pointer/slice/reference escape fails;
- Host ABI remains unchanged;
- AIR ABI remains `0.10`.

## Deferred

- pool allocation/free helpers;
- spawn/find-inactive helpers;
- compact pool storage;
- nested records;
- dynamic capacity;
- heap/GC;
- dynamic maps;
- object identity;
- runtime JSON;
- host object handles;
- tablegroup mutation;
- real game APIs;
- Host ABI expansion;
- AIR ABI change without separate review.

## Kill Criteria

Stop implementation if the design requires:

- dynamic allocation;
- GC;
- runtime JSON;
- object identity;
- dynamic maps;
- host object handles;
- platform-specific APIs;
- tablegroup mutation;
- hidden host gameplay authority;
- generated bindings as source of truth;
- AIR ABI or Host ABI change without accepted review.
