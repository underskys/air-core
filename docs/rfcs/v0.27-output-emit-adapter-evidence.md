# AIR v0.27 RFC: Output Emit Adapter Evidence

Status: stabilization evidence

Target milestone: v0.27

This RFC defines the reference adapter evidence shape for the Host ABI `0.11`
bounded `output.emit` first slice. It does not implement real platform
adapters, add raw host authority, expand Host ABI, or change AIR ABI.

The only accepted Host ABI `0.11` import remains:

```text
output.emit(output_id:i32, arg0:i32, arg1:i32, arg2:i32, arg3:i32) -> i32
```

## 1. Role

Adapter evidence is review and conformance data. It proves that a host adapter
or mock adapter can interpret bounded output intents consistently with package
Output Contracts and host policy.

Adapter evidence is not:

- proof that a real platform side effect happened;
- a general event stream;
- a payload transport;
- a host object handle surface;
- a reason to accept `output.event`, `audio.event`, or `effect_event`.

## 2. Evidence Kind

The reference evidence artifact uses the existing kind:

```json
{
  "schemaVersion": "0.25",
  "kind": "air.hostInteractionEvidence"
}
```

v0.27 hardens the required content for `output.emit` adapter evidence without
changing Host ABI.

## 3. Required Fields

Evidence must cover:

- package id/name;
- `packageHash`;
- `abiHash`;
- AIR ABI version;
- Host ABI version;
- selected host profile;
- policy id;
- whether the profile supports Host ABI `0.11` `output.emit`;
- Output Contract mapping;
- observed command records or observed `output.emit` records;
- policy allow/deny decisions;
- unsupported profile behavior;
- denied output behavior;
- invalid/unknown output behavior;
- diagnostics;
- replay checksum.

Reference shape:

```json
{
  "schemaVersion": "0.25",
  "kind": "air.hostInteractionEvidence",
  "status": "passed",
  "package": "output-emit-fixture",
  "packageHash": "sha256:...",
  "abiHash": "sha256:...",
  "airAbi": "0.10",
  "hostAbi": "0.11",
  "hostProfile": "mock-output-v011",
  "policyId": "output-emit-allow",
  "outputContracts": [
    {
      "id": 1,
      "name": "notify_status_recorded",
      "channel": "policy",
      "capability": "output.emit",
      "argCount": 4,
      "contract": "outputs/output_contracts.json"
    }
  ],
  "commandRecords": [
    {
      "kind": "output.emit",
      "source": "traces/accepted_emit.json#observedOutputEmits",
      "index": 0,
      "output_id": 1,
      "args": {
        "arg0": 7,
        "arg1": 0,
        "arg2": 0,
        "arg3": 0
      },
      "argsHash": "sha256:..."
    }
  ],
  "decisions": [
    {
      "output_id": 1,
      "output": "notify_status_recorded",
      "capability": "output.emit",
      "decision": "allow",
      "reasonCode": "allowed",
      "statusCode": 0,
      "argsHash": "sha256:...",
      "diagnostics": []
    }
  ],
  "deniedCapabilities": [],
  "diagnostics": [],
  "replayChecksum": "sha256:..."
}
```

## 4. Policy Decision Semantics

Denied output is a valid host policy outcome when the output id is known and the
host profile supports the package. Denial is reported as:

- `decision: "deny"`;
- `reasonCode: "denied_output"` or `denied_capability`;
- `statusCode: 1` for `output.emit`;
- warning diagnostic `air.host_policy.denied_output`.

Denied output does not imply that a side effect ran.

## 5. Failure Semantics

The evidence status must be `failed` for:

- output ids not declared by Output Contracts;
- unsupported host profiles;
- raw host authority in policies, contracts, or traces;
- payload/object/map/JSON command records;
- nondeterministic fields such as timestamps, random ids, absolute paths, or
  wall-clock values.

For `output.emit`, unknown output ids use status code `3` in the decision record
when a decision can be attached to an observed emit.

## 6. Output Contract Mapping

Adapter evidence must include enough Output Contract mapping for reviewers to
connect a scalar `output_id` to a stable package declaration:

- id;
- name;
- channel;
- capability;
- arg count;
- package-local contract path.

This mapping is evidence metadata. It is not a runtime host object, registry
entry, or host authority grant.

## 7. Payload Boundary

First-slice `output.emit` args are scalar `i32` only. Evidence may show scalar
args when they are non-sensitive and package-local. Evidence must not include:

- strings;
- JSON objects;
- maps;
- binary payloads;
- pointers or slices;
- raw URLs;
- logs;
- tokens;
- credentials;
- private text;
- host object handles.

If a future Output Contract marks scalar args private or sensitive, evidence
must prefer hash-only representation before canonical examples depend on that
mode.

## 8. Fixture Coverage

v0.27 adapter evidence should cover:

- CLI/mock adapter fixture through the reference `mock-output-v011` profile;
- non-game policy/ops fixture through the AirOps-style command buffer path;
- interactive/visual-like fixture through the synthetic visual panel command
  buffer path;
- `output.emit` fixture with accepted, denied, unsupported profile, and unknown
  output behavior.

These fixtures must not depend on demos or real platform adapters.

## 9. ABI Decision

AIR ABI remains `0.10`.

Host ABI remains `0.11` only for bounded `output.emit`.

This RFC adds no host imports and no real side-effect authority.
