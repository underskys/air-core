# AIR v0.15 RFC: Review Trend Baselines

Status: accepted v0.15 first slice
Target milestone: v0.15
Scope: deterministic anti-slop baseline and trend comparison format

## Purpose

AIR review diagnostics should show whether a package is becoming easier or
harder to review over time. v0.15 defines and implements a local deterministic
baseline/compare first slice that package report can run without a remote
service.

The active first slice covers deterministic baseline output and local comparison
for graph, module, function, diagnostic-count, generated, and manifest metrics.
Richer historical trend storage remains future work.

## Non-goals

- No remote telemetry service.
- No timestamps in baseline files.
- No absolute paths.
- No user identity or machine identity.
- No demo-specific metrics.
- No automatic code rewrite.
- No full historical database.

## Baseline File

Default path:

```text
air.review.baseline.json
```

The file is package-local and may be committed by a package owner when they want
trend gates.

## Format

```json
{
  "schemaVersion": "0.15",
  "package": "policy-audit-package",
  "profile": "cli",
  "pathClasses": ["authored", "generated", "vendor"],
  "metrics": {
    "graph": {
      "modules": 3,
      "edges": 2
    },
    "modules": {
      "src/main.air": {
        "pathClass": "authored",
        "lines": 80,
        "statements": 52,
        "mutableGlobals": 2,
        "functions": {
          "run": {
            "statements": 18
          }
        }
      }
    },
    "diagnostics": {
      "air.review.large_function": 0,
      "air.review.repeated_literal": 2,
      "air.review.select_chain_table": 0,
      "air.review.slot_family_state": 0,
      "air.review.debug_metric_event_bus": 0,
      "air.generated.stale": 0,
      "air.manifest.id_missing": 0
    }
  }
}
```

Required top-level fields:

| Field | Meaning |
| --- | --- |
| `schemaVersion` | Baseline schema version. |
| `package` | Stable package name from `air.package.json`. |
| `profile` | Host profile or review profile used to produce the baseline, if applicable. |
| `pathClasses` | Stable ordered path classes used by reviewPolicy. |
| `metrics` | Deterministic package metrics. |

## Determinism Rules

- Use package-local slash-separated paths.
- Do not store absolute paths.
- Do not store timestamps.
- Do not store commit hashes by default.
- Sort object keys lexicographically.
- Sort diagnostics by canonical diagnostic code.
- Sort modules by package-local path.
- Sort functions by function name.
- Store numeric counts only, not prose report text.
- Store generated/vendor metrics separately by `pathClass`.

The same package source and policy must produce byte-stable baseline JSON.

## Metrics

### Function Metrics

Per function:

- statement count;
- block count if already available;
- exported/private status if useful for entry/frame budgets;
- diagnostic counts affecting that function when available.

Required first slice:

```json
{
  "functions": {
    "run": {
      "statements": 18
    }
  }
}
```

### Module Metrics

Per module:

- line count;
- statement count;
- mutable globals;
- function count;
- table count if available;
- path class.

Required first slice:

```json
{
  "src/main.air": {
    "pathClass": "authored",
    "lines": 80,
    "statements": 52,
    "mutableGlobals": 2
  }
}
```

### Diagnostic Counts

Counts by canonical code:

- `air.review.large_function`;
- `air.review.large_entry`;
- `air.review.large_module`;
- `air.review.mutable_globals`;
- `air.review.repeated_literal`;
- `air.review.select_chain_table`;
- `air.review.slot_family_state`;
- `air.review.debug_metric_event_bus`;
- `air.generated.missing`;
- `air.generated.stale`;
- `air.generated.untraced`;
- `air.manifest.missing_runtime_resource`;
- `air.manifest.forbidden_runtime_path`;
- `air.manifest.id_missing`;
- `air.manifest.unused_entry`;
- `air.package.linked_wasm_deferred`.

Unknown future codes may be included if they are stable registry codes.

### Generated Freshness

Generated artifact trend metrics:

- missing generated file count;
- stale generated file count;
- untraced generated file count.

Generated freshness failures are hard package-check concerns. Baselines may track
counts but must not downgrade freshness failures into style warnings.

### Manifest Consistency

Manifest/resource metrics:

- missing runtime resource count;
- forbidden runtime path count;
- manifest ID mismatch count;
- unused manifest entry count.

### Graph Metrics

Package graph metrics:

- module count;
- edge count;
- unresolved import count;
- private cross-module call count if present.

Required first slice:

```json
{
  "graph": {
    "modules": 3,
    "edges": 2
  }
}
```

## Comparison Rules

A trend comparison computes current metrics from package-check/report and
compares them to `air.review.baseline.json`.

Default comparison:

- Increased hard-error diagnostic counts fail when gated.
- Increased review diagnostic counts warn unless gated.
- Increased largest function/module size warns when over configured delta.
- New `debug.metric` event-bus warnings fail only when policy gates them.
- Decreased metrics are reported as improvement but do not change pass/fail.

Comparison must be deterministic and should include old/current/delta values.

Example comparison result:

```json
{
  "code": "air.trend.function_statements_increased",
  "severity": "warn",
  "file": "src/main.air",
  "symbol": "run",
  "metric": "statements",
  "baseline": 18,
  "value": 34,
  "delta": 16,
  "threshold": 8
}
```

## Trend Gates

`reviewPolicy` may define trend gates:

```json
{
  "reviewPolicy": {
    "trend": {
      "baseline": "air.review.baseline.json",
      "gates": {
        "air.trend.function_statements_increased": "warn",
        "air.review.debug_metric_event_bus": "fail",
        "air.generated.stale": "fail"
      },
      "thresholds": {
        "functionStatementDelta": 12,
        "moduleStatementDelta": 80,
        "diagnosticCountDelta": 1
      }
    }
  }
}
```

Gate actions:

- `off`: comparison is recorded but not surfaced as a warning/failure.
- `warn`: comparison appears as a warning.
- `fail`: comparison fails package-check.

Trend gates must not waive parser/verifier/capability/Host ABI/profile/generated
hard errors. They only compare current state to a baseline.

## Generated and Vendor Handling

Path classes affect trend interpretation:

- `authored`: strictest trend checks.
- `generated`: size growth may be expected, but freshness remains strict.
- `vendor`: usually warning-only unless a package explicitly gates it.

Baselines must record path class per module so path movement is visible.

If a file changes path class, trend comparison should report it with a stable
trend diagnostic code. It should not silently compare generated code against
authored thresholds.

## Relation to LSP-lite Diagnostics

Trend comparison diagnostics should use the same envelope shape as
[LSP-lite Diagnostics](./v0.15-lsp-lite-diagnostics.md).

Trend diagnostics:

- use `category: "trend"`;
- use canonical `air.trend.*` codes;
- include `metric`, `value`, `threshold`, and related baseline fields when
  available;
- may have package-level `file: null` when the metric is graph-wide.

LSP-lite output should be able to show trend diagnostics next to parser,
verifier, package-check, reviewPolicy, generated, and manifest diagnostics.

## Implemented v0.15 First Slice

v0.15 implements:

- `airc report package <dir> --review-baseline`;
- `airc report package <dir> --compare-baseline air.review.baseline.json`;
- deterministic baseline JSON without timestamps or absolute paths;
- trend diagnostics for graph, module, function, mutable-global, and
  diagnostic-count increases;
- stable `air.trend.*` diagnostic codes with structured `fields` metadata.

## Acceptance Tests

The v0.15 first slice includes tests for:

- baseline JSON is deterministic;
- no timestamps or absolute paths appear;
- function statement increase produces a trend diagnostic;
- module statement increase produces a trend diagnostic;
- diagnostic count increase is detected by code;
- generated stale remains hard failure even if baseline had stale count;
- vendor path class is warning-only unless gated;
- graph module/edge count deltas are stable;
- LSP-lite serialization preserves trend diagnostic `fields`.

## Deferred

- Historical trend database.
- Remote metrics service.
- CI dashboard generation.
- Automatic baseline update command.
- Cross-repository package trend aggregation.
- Longitudinal trend history across many commits or packages.
