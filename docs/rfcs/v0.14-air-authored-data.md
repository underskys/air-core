# RFC: v0.14 AIR-authored Deterministic Data

Status: draft

Target milestone: AIR v0.14

## Summary

v0.14 should let AIR packages express small deterministic data directly in
authored AIR modules instead of pushing source-of-truth data into external JSON,
Python flatteners, or long select chains.

This RFC keeps the data model narrow: compile-time constants, enum-like integer
ids, and static readonly scalar tables. It does not add dynamic arrays, maps,
GC, runtime mutation, host-backed containers, or object models.

## Goals

- Reduce repeated magic literals in AI-authored AIR.
- Make deterministic static data visible to verifier, report, and package-check.
- Keep table sizes known at compile time.
- Provide deterministic `table.get` behavior.
- Add bounds/guarded access diagnostics.
- Preserve table metadata in reports.
- Keep generated data modules deterministic and stale-checkable.

## Non-goals

- No runtime mutation of readonly tables.
- No dynamic arrays.
- No maps.
- No GC.
- No host-backed containers.
- No records or nested structures in P0.
- No arbitrary JSON-in-AIR semantics.
- No demo-specific data syntax.

## Motivation

Without AIR-authored deterministic data, generated packages drift toward:

- repeated constants;
- magic integer handles;
- `select` chains used as tables;
- large generated frame functions;
- external source-of-truth transformations;
- generated AIR that is hard to review.

Games expose this pressure clearly, but the issue is broader. AIR packages also
need deterministic data for:

- DevOps/SRE policy tables;
- network allowlists;
- service capability matrices;
- deployment target tables;
- secret boundary metadata;
- CI pipeline step tables;
- UI/dashboard config tables;
- compliance rule ids;
- static decision matrices.

The goal is generic AI-generated system integrity, not game-specific language
features.

## P0 Data Model

### Named Constants

Named constants are immutable compile-time scalar values.

Example:

```air
const MAX_RETRIES:i32 = 3
const ENABLE_DEBUG:bool = false
const DEFAULT_TIMEOUT_MS:i64 = 30000
```

Rules:

- module-local names;
- scalar literal initializers only;
- compile-time only;
- no runtime storage required;
- deterministic report metadata.

### Enum-like Integer IDs

Enum-like ids are named integer constants used for stable package-local ids.

Example:

```air
const SERVICE_AUTH:i32 = 1
const SERVICE_API:i32 = 2
const SERVICE_WORKER:i32 = 3
```

Rules:

- ids are ordinary constants, not a separate runtime type in P0;
- package-check/report can identify dense id families as review metadata;
- ids do not grant capability or host authority;
- manifest/resource binding must still be validated separately.

### Static Readonly Scalar Tables

Static tables hold fixed-size scalar values known at compile time.

Example:

```air
table retry_budget_ms:i32[4] = [100, 250, 500, 1000]
table service_enabled:bool[3] = [true, true, false]
```

P0 scalar element types:

- `i32`;
- `i64`;
- `f32`;
- `f64`;
- `bool`.

Rules:

- fixed length only;
- literal or same-module constant initializer values only;
- initializer length must match declared length;
- read-only;
- no runtime mutation;
- no nested tables;
- no records;
- no dynamic size expression.

Constants may appear in table initializers only when they are compile-time
scalar constants of the table element type.

Example:

```air
const RETRY_FAST_MS:i32 = 100
const RETRY_SLOW_MS:i32 = 1000
table retry_budget_ms:i32[2] = [RETRY_FAST_MS, RETRY_SLOW_MS]
```

Rules:

- constants must be defined in the same module in P0;
- constants must be scalar and compile-time only;
- constants must match the table element type;
- no expressions are allowed in table initializers;
- imported constants and generated-module constants require a later resolver
  decision.

## Deterministic Table Access

P0 introduces deterministic table access semantics.

Example shape:

```air
%delay:i32 = table.get retry_budget_ms, %index
```

The exact syntax may adapt to existing AIR instruction conventions, but the
semantics must be stable:

- table name resolves module-locally or through accepted generated module rules;
- index is integer typed;
- access is deterministic;
- out-of-bounds behavior is specified and tested;
- report identifies guarded and potentially unsafe access when statically
  knowable.

## Bounds And Guarded Access Diagnostics

Verifier/report diagnostics should distinguish:

- statically valid literal index;
- statically out-of-bounds literal index;
- dynamic index guarded by known range check;
- dynamic index without a recognizable guard.

Required diagnostics:

- invalid negative literal index;
- literal index greater than or equal to table length;
- non-integer index;
- unknown table;
- attempted table mutation;
- table length mismatch.

Diagnostics should include stable codes and repair hints.

## Table Report Metadata

Reports should include table metadata per module.

Example JSON concept:

```json
{
  "modules": [
    {
      "path": "src/policy.air",
      "tables": [
        {
          "name": "retry_budget_ms",
          "elementType": "i32",
          "length": 4,
          "approxBytes": 16,
          "origin": "manual"
        }
      ]
    }
  ],
  "tableSummary": {
    "count": 1,
    "approxBytes": 16
  }
}
```

Metadata should include:

- table count;
- table names;
- module origin;
- element type;
- length;
- approximate storage size;
- manual or generated origin where known.

## Generated Data Modules

Generated modules may contain constants and static tables derived from package
manifests or deterministic tooling.

Examples:

- `generated/assets.air`;
- `generated/asset_handles.air`;
- `generated/audio_handles.air`;
- `generated/material_handles.air`;
- `generated/service_matrix.air`.

Rules:

- generated data is derived artifact, not source of truth;
- generated data must be deterministic;
- generated data must be package-local;
- generated data must not grant authority;
- generated data must be stale/missing checked;
- generated data headers must identify their generator and source inputs.

## Resource And Authority Boundary

AIR-authored data can define ids and static policy data. It does not authorize
host behavior by itself.

Examples:

- an audio id does not grant audio playback authority;
- a texture id does not grant graphics capability;
- a service id does not grant network capability;
- a secret-boundary id does not grant filesystem or secret access.

Capabilities, host profiles, manifests, and Host ABI validation remain the
authority boundary.

## P1 / Deferred

### Tablegroups

Tablegroups may group parallel tables with shared length and related semantic
ownership.

Status: RFC/P1.

### Record-like Static Schemas

Record-like schemas may make static rows easier to review.

Status: RFC/P1.

### Fixed Mutable Pools

Fixed mutable pools may model bounded runtime slots for tasks, events,
projectiles, checks, or particles.

Status: deferred/RFC. They require memory, mutation, and effect-budget design.

### Dynamic Arrays, Maps, GC

Dynamic arrays, maps, and GC are rejected for this v0.14 P0 scope.

## Acceptance Tests

### Valid Table Access

Fixture:

```air
table retry_budget_ms:i32[4] = [100, 250, 500, 1000]

func delay_for_first_retry() -> i32 {
entry:
  %delay:i32 = table.get retry_budget_ms, 0
  return %delay
}
```

Expected:

- parser/verifier accepts the table;
- report lists table metadata;
- lowering produces deterministic output.

### Invalid Out-of-bounds Access

Fixture:

```air
table retry_budget_ms:i32[4] = [100, 250, 500, 1000]

func invalid_delay() -> i32 {
entry:
  %delay:i32 = table.get retry_budget_ms, 4
  return %delay
}
```

Expected:

- verifier or package-check rejects the literal out-of-bounds access;
- diagnostic includes table name, length, index, and repair hint.

### Mismatched Generated Artifact Freshness

Fixture:

```text
assets/manifest.json
generated/assets.air
```

Procedure:

1. Generate `generated/assets.air` from the manifest.
2. Modify the manifest.
3. Run package-check.

Expected:

- package-check reports stale generated data;
- diagnostic identifies generated file and source manifest;
- authority is not granted by the generated handles.

### Report Lists Tables Per Module

Fixture:

```text
src/main.air
src/policy.air
generated/assets.air
```

Expected:

- JSON report lists tables under the owning module;
- generated/manual origin is visible where known;
- table summary is deterministic across repeated runs.

### Constants Usable In Table Literals

Fixture:

```air
const WARN:i32 = 70
const FAIL:i32 = 90
table thresholds:i32[2] = [WARN, FAIL]
```

Expected:

- parser/verifier accepts compile-time constants in table literals;
- type mismatches are rejected;
- report preserves the final table shape and source constant names where
  practical.

## Initial Recommendation

Implement P0 in this order:

1. table metadata/report support for existing static table syntax;
2. verifier diagnostics for bounds and mutation rejection;
3. generated data freshness checks;
4. package-check/report anti-slop hints for select-chain-as-table patterns.

Do not expand the data model to records, mutable pools, maps, or runtime objects
until the P0 deterministic scalar table path is stable.
