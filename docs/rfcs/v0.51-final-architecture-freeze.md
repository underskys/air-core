## One architecture, one ownership model

AIR Core owns typed-decision semantics, deterministic evaluation, canonical
typed values, closed tags, verification, and the verified artifact. AIR does
not own clocks, callbacks, files, networks, model objects, device objects, or
actual effects.

The Host Contract owns typed observation/grant/intent/decision/receipt records
and their evidence framing. A host profile adapts platform facts into those
records and executes only a decision's effective limits. Swift is a host and
conformance implementation, never a second compiler or semantic authority.

The artifact boundary is a host-provided immutable verified artifact plus its
canonical manifest, verifier disposition, evidence identity, declared AIR ABI
lane, and declared Host Contract version. `.airpkg` remains optional transport;
it is not semantic authority and an unpacked verified artifact is equally
admitted when its identity is explicit.

profile as generally available before the companion conformance gates pass.

## DecisionEvidence v1

`DecisionEvidence` is the exact record schema for
`air.host-contract/1.0.0-candidate.1`. It has no extension bag. Unknown,
missing, duplicate, or reordered semantic fields fail closed.

The canonical JSON object fields are serialized in ascending Unicode code-point
order. Strings and typed values use A2 canonical UTF-8/no-whitespace encoding.
An optional value uses the A2 canonical `option<T>` form rather than omission.

### Keyed collections and canonical ordering

Before any semantic collection is sorted or digested, the validator MUST first
validate every member, derive its semantic key, and reject a duplicate key.
Sorting then uses only the rule below; stable-sort preservation of caller input
order is never a tie-breaker or a source of canonicality. A duplicate is an
invalid input even when the duplicate records have byte-identical values.

| Collection | Semantic key and duplicate rule | Canonical order |
| --- | --- | --- |
| `Argument[]` | `Argument.name`; duplicate names fail closed. | ASCII ascending `name`. |
| `CapabilityObservation[]` supplied to evaluation | `CapabilityObservation.observation_id`; a repeated ID with identical canonical bytes is a duplicate and a repeated ID with changed canonical bytes is an identity collision. Both fail closed. | ASCII ascending `observation_id`. |
| `Budget[]` | `ResourceClass.discriminant`; duplicate discriminants fail closed. | Ascending numeric discriminant. |
| `required_capabilities[]` | full identifier string; duplicates fail closed. | ASCII ascending identifier. |
| `effect_types[]` | full identifier string; duplicates fail closed. | ASCII ascending identifier. |
| `resource_classes[]` | `ResourceClass.discriminant`; duplicate discriminants fail closed. | Ascending numeric discriminant. |
| grant inputs | `CapabilityGrant.grant_id`; a repeated ID with identical bytes is a duplicate and a repeated ID with changed bytes is an identity collision. Both fail closed. | ASCII ascending `grant_id`. |
| digest-reference arrays | digest string, unless the owning record explicitly declares identical duplicates idempotent. | ASCII ascending digest string. |

For this v1 contract, a collection ordered as ASCII MUST reject a non-ASCII key
rather than delegate locale, Unicode normalization, or host-language comparison
to Node or Swift. `ResourceClass` ordering compares its closed numeric
discriminant, not display name or host enum order. The rule applies recursively
to `DecisionIntent`, `CapabilityObservation`, `GrantScope`, `CapabilityGrant`,
`DecisionEvidence`, and every component-digest input below. An explicit
idempotency declaration is record-local; it does not make an otherwise repeated
semantic input valid.

Every component digest in this section is exactly
`sha256(UTF8(domain) || 0x00 || canonical(record))`. `canonical(record)` means
the recursive canonical JSON encoding above after all keyed-collection checks
have passed. `Digest256` fields are lowercase `sha256:` strings with 64 lowercase
hexadecimal digits. These domains and records are semantic inputs; neither Node
nor Swift may substitute native serialization, map iteration, input order, or a
different digest domain.

| DecisionEvidence field | Domain | Exact canonical input record |
| --- | --- | --- |
| `canonical_typed_input_digest` | `AIR_CANONICAL_TYPED_INPUT_V1` | `CanonicalTypedInputV1 = {"observations": CapabilityObservation[]}`. It contains all and only observations supplied to this AIR policy evaluation. Observation facts are data, never grants. |
| `grant_set_digest` | `AIR_GRANT_SET_V1` | `GrantSetV1 = {"grants": CapabilityGrant[]}` over every grant supplied to the evaluation, before intersection, after `grant_id` duplicate/collision validation. |

| `package_identity_digest` | `AIR_PACKAGE_IDENTITY_V1` | `PackageIdentityV1 = {"air_abi_lane": String, "interface_descriptor_digest": Digest256, "manifest_digest": Digest256, "verified_artifact_digest": Digest256}`. `interface_descriptor_digest` and `manifest_digest` are references, not places
to invent a Node- or Swift-specific encoding. I2 MUST define and validate their
closed schemas before it accepts an AIR ABI 0.12 candidate. Until that gate
passes, no package may claim an exported typed interface or any corresponding
`package_identity_digest` as admitted. Existing AIR ABI 0.10/0.11 package
identity remains unchanged.

`.airpkg` and unpacked delivery are transport/container provenance, not a
package-identity or policy input. The same immutable artifact and canonical
manifest therefore produce the same `PackageIdentityV1` and DecisionEvidence
digest through either transport. `ArtifactTransportProvenanceV1` may record the
observed transport for host/tooling diagnostics only. It is excluded from
`AIR_DECISION_EVIDENCE_V1`, cannot create a grant or authority, and is not an
AIR v0.51 policy input.

### Total effective authority derivation

This section defines the total, deterministic, fail-closed derivation used by
every candidate A3 decision. It elaborates the frozen A3 terms
`intersection`, `minimum`, and `earliest`; it does not add or alter an A2, A3,
or A4 record, enum, digest domain, or ABI.

`SuppliedGrantSet` is exactly the canonical `GrantSetV1` bound by
`grant_set_digest`: every `CapabilityGrant` provided to this evaluation,
ordered by ASCII `grant_id`. Before authority derivation, the evaluator MUST
reject duplicate `grant_id`, same-`grant_id` changed-byte collision, malformed
grant, unknown semantic field, stale/future/wrong generation, expired grant,
or unrecognized capability. It MUST NOT drop, filter, or otherwise ignore a
supplied grant. `AdmittedGrantSet` is the complete validated `SuppliedGrantSet`.
Thus `grant_set_digest` always binds the exact supplied and admitted set, not a
post-filter subset.

AIR Host Contract v1 authorizes only effectful `DecisionIntent` values. Such an
intent MUST contain at least one `required_capabilities` identifier; an empty
array is `deny/invalid_intent`. `SuppliedGrantSet=[]` is
`deny/grant_missing`. There is no zero-grant intersection identity that yields
the requested scope, and no host/profile-specific "otherwise usable"
capability mapping in AIR Core. A future pure or non-effect decision type
requires a separate, explicit versioned architecture decision.

For every `DecisionIntent.required_capabilities` identifier, at least one
grant in `AdmittedGrantSet` MUST have exactly that capability identity; absence
is `deny/grant_missing`. Conversely, every supplied grant capability MUST be
exactly present in `required_capabilities`; absence is `deny/unknown_capability`.
A supplied grant is never ignored. Grant presence does not union scope. All
restrictions of every admitted grant participate in derivation.

Given a valid intent and its complete `AdmittedGrantSet`, the evaluator derives
the following values in the stated order. Every keyed collection is validated
for duplicates before sorting; no stable input order, host map order, wildcard,
closest-match, provider-specific coercion, absent-as-infinity value, or host
default is canonical.

1. `effective_effect_types` is the set intersection of
   `DecisionIntentV1.requested_scope.effect_types` and every admitted
   `grant.scope.effect_types`, ordered ASCII. Empty is
   `deny/grant_scope_mismatch`. The requested `DecisionIntent.effect_type`
   MUST belong to that intersection or the result is
   `deny/grant_scope_mismatch`.
2. `DecisionIntentV1.requested_scope.resource_classes` is non-empty if and
   only if the request is resource-consuming for v1 derivation purposes. No
   external host/profile effect metadata determines that property.
   `DecisionIntentV1.budgets` must have exactly the same
   `ResourceClass.discriminant` key set as requested scope; each grant
   `budgets` must have exactly the same key set as its own `scope.resource_classes`.
   Duplicate, missing, or extra budget keys fail closed. If requested resource
   classes are empty, intent budgets must be empty. `effective_resource_classes`
   is the numeric-discriminant-ordered intersection of requested and every
   admitted grant `scope.resource_classes`. An empty intersection of a
   non-empty requested set is `deny/grant_scope_mismatch`; there is no implicit
   resource-class widening.
3. `target_class` is exact equality, not an intersection. The requested target
   class and every admitted grant target class must have the same canonical
   qualified identifier. A none-vs-value comparison is a mismatch: the frozen
   v1 `GrantScope.target_class` is required, so no omitted value is admitted.
   A mismatch is `deny/grant_scope_mismatch`.
4. `effective_max_uses` is the checked-i64 minimum of requested and every
   admitted grant `scope.max_uses`. Overflow, invalid encoding, or a result
   less than or equal to zero is `deny/grant_scope_mismatch`. No absent value
   means infinity because v1 defines no absent `max_uses` representation.
5. For each class in `effective_resource_classes`, a requested intent budget
   and an explicit budget from every admitted grant are required by the exact
   key-set rules in step 2. A missing required intent entry remains the frozen
   `deny/budget_exceeded` result of IC08; an extra intent entry is
   `deny/invalid_intent`. A missing or extra grant entry is
   `deny/grant_scope_mismatch`.
   `effective_budget[R]` is the checked-i64 minimum of the requested budget
   and all corresponding admitted-grant budgets. Negative or overflowing
   values fail closed; an effective limit less than or equal to zero is
   `deny/budget_exceeded` where resource consumption is required.
   `effective_budgets` are ordered by ascending `ResourceClass.discriminant`.
6. `effective_deadline` is the earliest non-none `not_after_ns` among the
   intent deadline and every admitted grant deadline. Every non-none
   participating deadline MUST have the same exact `clock_domain` and the same
   exact `now_ns`; either mismatch is `deny/invalid_intent` before decision
   acceptance. AIR evaluation MUST NOT source a fresh clock value, choose
   `now_ns` by input order, or select it from the deadline with the earliest
   `not_after_ns`. Given common `clock_domain` and `now_ns`, the effective
   deadline is exactly that pair plus the minimum participating
   `not_after_ns`. All none yields none. `now_ns > effective.not_after_ns` is
   `deny/deadline_exceeded`; equality remains valid under frozen A3. A retry
   never refreshes an existing grant deadline.
7. `DecisionEvidence.generation_fence`, `DecisionIntent.generation`, and every
   admitted grant generation must be exactly equal. Any mismatch is
   `deny/stale_generation`; no partial grant-set admission follows it.

After all validation and derivation, `deny` has
`effective_scope=none` and empty effective budgets. `allow` is permitted only
when canonical effective authority is exactly the requested authority.
`limit` is required when valid effective authority is a strict narrowing,
including a smaller budget, `max_uses`, or deadline. A host MUST execute only
the resulting `Decision.effective_scope`, `Decision.effective_budgets`, and
effective deadline; it MUST NOT use the broader request as fallback.

### Decision input closure and cross-field coherence

Before evaluation, the host supplies one closed observation set. Every supplied
`CapabilityObservation` MUST be included in `CanonicalTypedInputV1`; omitting a
supplied or consumed observation invalidates evidence. An observation that was
not supplied to the evaluation MUST NOT be appended afterward. Source order and
host dictionary order have no semantic effect after the observation-key checks.
Intent typed arguments remain exclusively in `DecisionIntentV1`; they are not
duplicated in the observation component.

The following equality and derivation checks are part of DecisionEvidence
acceptance and fail closed before that evidence is accepted:

- `requested_budgets` equals `DecisionIntent.budgets`.
- `requested_scope` equals `DecisionIntentV1.requested_scope`.
- `generation_fence` equals `DecisionIntent.generation`, and every admitted
  grant has that exact fence.
- `effective_scope`, `effective_budgets`, and `deadline` are the total values
  derived by **Total effective authority derivation** above.
- `DecisionEvidence.air_abi_lane == PackageIdentityV1.air_abi_lane ==
  VerifiedArtifactV1.air_abi_lane`.
- `DecisionEvidence.verified_artifact_digest ==
  PackageIdentityV1.verified_artifact_digest == digest(VerifiedArtifactV1)`.
- `DecisionEvidence.policy_identity == PolicyArtifactV1.policy_identity`.
- `DecisionEvidence.intent_digest == DecisionIntent.intent_id ==
  digest(DecisionIntentV1)`.

Every component input record MUST be present in the evidence package or be
resolvable by its exact digest from an immutable verified evidence store. A
missing, substituted, or mismatched component is not recoverable by a host
default, transport record, or generated value.

## Swift codec and runtime boundary

Swift may implement a conformance-checked encoder/decoder for the frozen
record. It consumes and emits the canonical bytes above, validates closed tags
and exact `Int64` ranges, and must reject any mismatch. Swift dictionaries,
`Codable` defaults, native struct layout, `Optional`, and `Result` layouts are
not canonical byte authority. Generated bindings are views over this schema;
they do not define it.

`AIRSwift` shipping runtime requirements are:

- no Node/npm dependency and no shell-out to Node/npm;
- no broad main-process JIT entitlement by default;
- JavaScriptCore remains development/shadow-only until termination is proven;
- authority mode requires killable isolation, proven termination, or process
  replacement after timeout;
- pre-decision timeout, poison, and quarantine produce
  `RuntimeEvaluationFailure`/containment records, never `EffectReceipt`;
- an `EffectReceipt` is possible only after a valid A3 `Decision` and a host
  attempt to execute its bounded effect.

## Limits, models, locality, and shadow features

For `Decision.limit`, the host MUST execute only `effective_scope` and
`effective_budgets`. Requested scope/budgets are proposal data and cannot be
used as an execution fallback.

The closed model lifecycle is:

```text
requested -> downloadRequested -> downloading -> verifying -> ready -> active
failed | quarantined | superseded | rollback
```

Transitions are host observations, not AIR network/filesystem authority. Model
manifest facts are bounded identifiers, version/digest, signer/provenance
digest, locality class, declared resource limits, and lifecycle state. Raw
model data, prompts, private text, URLs, tokens, and filesystem paths are not
AIR facts or evidence fields.

Remote/Watch fallback after AIR authority activation may observe, queue a new
intent, or enter safe no-op mode; it MUST NOT execute a denied effect or any
effect beyond the decision's effective limits. Voice Tool Gate is a bounded
proposal/intent adapter only. Cinema remains shadow/presentation policy; it
cannot alter AIR decisions, grants, receipts, or host authority.
