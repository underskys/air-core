# AIR v0.51 Typed Host Contract and Effect Receipts

Status: normative A3 specification and A1 versioning candidate.

## Scope and frozen inputs

This document defines the host-contract records for the sequence `OBSERVE ->
DECIDE -> EXECUTE outside AIR -> REPORT -> DECIDE AGAIN`. It consumes the A2
terminal commit `d4450914cb73fb21ad63b7743cda021986db1f4f` and reuses, without
reinterpretation, A2 scalar, tag, checked-i64, type-identity, typed-value
equality, and canonical typed-value byte semantics.

The records below are host-contract envelopes, not AIR source values or a new
AIR ABI. This RFC does not change AIR ABI, Host ABI, parser, verifier, or
runtime. AIR stays deterministic, bounded, synchronous, and capability
constrained. The host owns clocks, asynchronous work, callbacks, cancellation,
devices, telemetry, and every actual filesystem, network, model, or device
effect.

All `TypedValue` fields use the A2 canonical typed-value representation.
Records use A2 fixed-layout record identity and closed-enum discriminants;
field order is the declared order. Canonical bytes are A2 canonical typed-value
bytes, including sorted object keys and UTF-8 encoding. No JSON insertion order
or host-object identity is semantic authority.

`Digest256` is exactly `sha256:` followed by 64 lowercase hexadecimal digits.
`Identifier` is ASCII `[a-z][a-z0-9_.-]{0,95}`. `QualifiedIdentifier` is an
`Identifier` containing a dot. These envelope strings are not new AIR scalar
types. Every quantity below is a nonnegative checked A2 `i64`; overflow,
negative values, unknown discriminants, or an invalid typed value fail closed.

## Canonical records

### CapabilityObservation

```
CapabilityObservation {
  observation_id: Digest256,
  observation_type: QualifiedIdentifier,
  generation: GenerationFence,
  observed_value: TypedValue,
  source_class: SourceClass,
  logical_observation_id: Digest256,
  precision: ObservationPrecision,
  provenance: Digest256
}
```

`SourceClass` is closed: `declared_profile=0`, `verified_artifact=1`,
`host_measurement=2`, `host_policy=3`. `ObservationPrecision` is closed:
`exact=0`, `quantized=1`, `upper_bound=2`, `lower_bound=3`, `estimated=4`,
`unknown=5`. An observation describes availability or a fact; it never grants
authority. It may be stale. An unknown observation type or unknown precision
fails closed whenever authority depends on it. Telemetry cannot alter a prior
decision; it may be a new observation for a later decision. Platform facts
belong in Host Profiles, not Core.

### GenerationFence and Deadline

```
GenerationFence { domain: QualifiedIdentifier, epoch: i64, fence_id: Digest256 }
Deadline { clock_domain: QualifiedIdentifier, now_ns: i64, not_after_ns: i64 }
```

Generation equality requires all three fields to match exactly. A replacement
or restart increments `epoch`, publishes a new `fence_id`, and never wraps.
Stale, future, or unknown fences fail closed; synchronization is the provision
of a new host observation and a newly evaluated decision, never reuse of old
authority. A deadline uses host-supplied nanoseconds and is valid exactly when
`now_ns <= not_after_ns` in the same `clock_domain`. AIR does not read a clock.

### Budget, ResourceClass, and CapabilityGrant

```
Budget { resource_class: ResourceClass, limit: i64 }
CapabilityGrant {
  grant_id: Digest256, capability: QualifiedIdentifier, scope: GrantScope,
  budgets: Budget[], generation: GenerationFence, deadline: Deadline?,
  issuer_class: QualifiedIdentifier, issuer_id: Digest256,
  constraints_digest: Digest256
}
GrantScope { effect_types: QualifiedIdentifier[], resource_classes: ResourceClass[],
             target_class: QualifiedIdentifier, max_uses: i64 }
```

`ResourceClass` is closed: `bytes=0`, `tokens=1`, `operations=2`,
`duration_ns=3`, `memory_bytes=4`, `compute_units=5`. Financial values are not
represented by `f64`. Multiple grants are intersected: capabilities/effects and
resource classes intersect, budgets and `max_uses` take the minimum, and no
deadline becomes later. Empty intersection denies. There is no implicit union.
Observation, API availability, proposal, receipt, and a prior invalidated grant
are not grants. Unknown or widened grant fields fail closed in strict mode.

### DecisionIntent and Decision

```
DecisionIntent {
  intent_id: Digest256, effect_type: QualifiedIdentifier,
  typed_arguments: Argument[], required_capabilities: QualifiedIdentifier[],
  generation: GenerationFence, deadline: Deadline?, budgets: Budget[],
  provenance: Digest256
}
Argument { name: Identifier, value: TypedValue }
Decision { outcome: DecisionOutcome, reason: FailureReason?,
           effective_scope: GrantScope?, effective_budgets: Budget[],
           decision_evidence_digest: Digest256 }
```

Lists are canonically sorted by their identifier or class. An intent is a
proposal, not proof of execution. Given equal canonical inputs, AIR produces
the same decision. `DecisionOutcome` is closed: `allow=0`, `deny=1`,
`limit=2`. `limit` is valid only when its effective scope is a strict subset of
the requested scope and every effective budget is less than or equal to the
request. It never adds authority. A deny produces no permitted effect.

`FailureReason` is a closed A2 enum:
`capability_missing=0`, `grant_missing=1`, `grant_scope_mismatch=2`,
`stale_generation=3`, `deadline_exceeded=4`, `budget_exceeded=5`,
`invalid_intent=6`, `unknown_capability=7`, `unknown_effect=8`,
`authority_widening=9`, `replay_rejected=10`, `duplicate_rejected=11`,
`invalid_receipt=12`, `host_failure=13`. The first thirteen are decision or
validation reasons as applicable; `host_failure` reports a host execution
outcome and does not rewrite a historical AIR decision.

## Evidence and receipt domains

The decision digest is:

```
sha256(UTF8("AIR_DECISION_EVIDENCE_V1") || 0x00 || canonical(DecisionEvidence))
```

`DecisionEvidence` contains package identity, verified-artifact identity,
canonical typed-input digest, grant digest, generation fence, intent digest,
deadline and budget inputs, semantic-policy identity, outcome, effective
limits, and stable reason. It excludes measured latency, actual CPU/GPU use,
post-decision thermal data, completion time, callback ordering, presentation
time, network/model result, and execution telemetry.

```
EffectReceipt {
  receipt_id: Digest256, decision_evidence_digest: Digest256, intent_id: Digest256,
  generation: GenerationFence, outcome: ReceiptOutcome, failure_reason: FailureReason?,
  consumed_budgets: Budget[], host_execution_id: Digest256,
  terminal_state: TerminalState, redacted_observation_refs: Digest256[]
}
```

`ReceiptOutcome` is `executed=0`, `host_refused=1`, `host_failed=2`,
`cancelled=3`, `not_started=4`; `TerminalState` is `final=0`,
`coalesced=1`, `rejected=2`. Its digest is:

```
sha256(UTF8("AIR_EFFECT_RECEIPT_V1") || 0x00 || canonical(EffectReceipt))
```

The receipt domain is distinct from the decision domain even when fields
overlap. A receipt reports a host observation; it cannot grant authority,
mutate a decision digest, or retroactively authorize excess. Mismatch or a
forged receipt fails verification but does not invalidate historical decision
evidence. Redacted references are digest identifiers only, never raw telemetry
or buffer contents.

## Replay, duplicate, extensions, and profiles

A decision-evidence digest is single-use for execution. A repeated delivery
before a terminal record may coalesce to the same host execution; a delivery
after a final record is a rejected replay. Same `intent_id` with different
canonical bytes is identity collision/corruption and is rejected. Repeating a
receipt ID with identical canonical bytes is idempotent; changing its bytes is
`invalid_receipt`. Old-generation intents and receipts are rejected. The host
ledger enforces these rules; its record is observational and creates no new
AIR authority.

Semantic fields are strict and fail closed when unknown fields could affect
authority, capability, effect, budget, scope, fence, deadline, replay, or
digest meaning. `observational_extensions` may be ignored only when a profile
namespaces them, they do not affect policy, and they are excluded from both
canonical digest inputs. Display/debug metadata is nonsemantic and likewise
excluded. Future A1 version negotiation must select an explicitly supported
record version; A3 proposes version `v1` only and changes no ABI.

Host Profiles map generic classes such as compute resource, model capability,
memory pressure, tool capability, and network capability to platform APIs.
Profiles are descriptive and do not grant authority or create an ABI. No
product or framework names are Core semantics.

## Compatibility and carry-forward

Semantic-patch classification is normative: capability addition, grant/scope
widening, budget increase, deadline relaxation, a new effect, fence/replay or
unknown-field weakening are `AUTHORITY_OR_BEHAVIOR_WIDENING`; grant/scope
narrowing, budget decrease, and stricter deadline are `COMPATIBLE_NARROWING`;
receipt semantic changes, reason renumbering, and digest-domain changes are
`BREAKING_SEMANTIC_CHANGE`; an invalid closed enum or unknown strict field is
`INVALID`; a nonsemantic display addition is `NO_SEMANTIC_CHANGE`.

A2 P2 items R1 (example key order/self-test vector), R2 (finite-f32 corpus and
transcendental policy), and R3 (executable runners) remain nonblocking A1 debt.
They neither alter these records nor block this specification.
