# AIR v0.17 RFC: airpkg Artifact Validation

Status: draft

Target milestone: v0.17

## Purpose

Validate an `airpkg` artifact as a deterministic, inspectable AIR package
artifact. v0.16 introduced metadata-only `airpkg` artifacts and
`inspect-airpkg`; v0.17 should let release gates validate artifacts directly,
without requiring the original source package to be traversed for every check.

Artifact validation is not a package registry, product bundle, native installer,
or runtime execution contract. It checks that the artifact faithfully records
package identity, graph, ABI/profile requirements, linked output metadata,
generated artifacts, manifests, diagnostics, and build-time/runtime boundary
information.

## Command Shape

Candidate command shapes:

```sh
airc check-airpkg <file-or-dir> --json
airc check-airpkg <file-or-dir> --profile <profile> --json
```

Alternative if this fits existing CLI routing better:

```sh
airc package-check --artifact <file-or-dir> --json
airc package-check --artifact <file-or-dir> --profile <profile> --json
```

`check-airpkg` is preferred because it makes the target explicit: the command
checks an artifact, not an authored source package.

## Validation Requirements

`airpkg` validation must check:

- `schemaVersion` is present and supported;
- artifact kind is recognized as `airpkg`;
- package identity is present and stable;
- package manifest path and fingerprint are present when the artifact claims a
  package manifest;
- source graph hash or fingerprint is present;
- source graph summary is deterministic and path-relative;
- linked output metadata is well-formed;
- referenced linked output files exist when the artifact declares them
  artifact-relative;
- referenced linked output hashes match when files are present;
- generated artifact fingerprints are well-formed and deterministic;
- generated artifact entries do not claim authority;
- manifest/resource references are path-relative and deterministic;
- host profile requirements are explicit;
- AIR ABI requirement is present and compatible with current tooling policy;
- Host ABI requirement is present and compatible with current tooling policy;
- no absolute paths appear anywhere in artifact metadata;
- no timestamp-like fields appear in deterministic metadata;
- runtime metadata does not require Node, npm install, Python, source AIR repo,
  Codex, build scripts, or local build-only files;
- all diagnostics are deterministic and use stable codes where available.

Validation should be source-independent by default. If a check requires source
files, the report must label it as a source-backed check rather than silently
depending on the local checkout.

## Profile Compatibility

When a profile is supplied, artifact validation must check:

- profile exists;
- profile supports the artifact's required Host ABI;
- profile supports required capabilities;
- profile supports required host imports;
- profile supports required or declared linked output kind when applicable;
- profile does not require capabilities/imports absent from the artifact;
- profile mismatch diagnostics are deterministic.

The profile check validates compatibility metadata. It does not execute linked
output and does not imply Host ABI changes.

## Diagnostics

Artifact validation should emit normalized diagnostics using stable codes:

| Code | Default severity | Meaning |
| --- | --- | --- |
| `air.artifact.schema_invalid` | error | Artifact schema is missing, unsupported, or structurally invalid. |
| `air.artifact.hash_mismatch` | error | Declared artifact, linked output, graph, manifest, or generated fingerprint does not match available bytes. |
| `air.artifact.missing_linked_output` | error | Artifact declares linked output that is absent from artifact-relative storage. |
| `air.artifact.absolute_path` | error | Artifact metadata contains an absolute path. |
| `air.artifact.runtime_boundary_violation` | error | Runtime metadata requires build-time tools or source checkout state. |
| `air.artifact.profile_mismatch` | error | Supplied profile cannot satisfy artifact Host ABI, capability, import, or linked output requirements. |

Required diagnostic fields should include:

- artifact path;
- JSON pointer or field path when available;
- expected value when deterministic;
- actual value when deterministic;
- profile id when profile validation is active;
- repair hint;
- related linked output or manifest path when applicable.

## Non-goals

- no package registry;
- no remote fetching;
- no native installer;
- no Steam packaging;
- no web/native target bundle implementation;
- no runtime imports;
- no dynamic linking;
- no Host ABI changes;
- no AIR ABI changes;
- no game-specific artifact fields.

## ABI Impact

Validating `airpkg` metadata does not require an AIR ABI bump when it only
checks package metadata, linked output fingerprints, generated artifacts,
manifests, diagnostics, profile requirements, or build-time/runtime boundary
fields.

Validating `airpkg` metadata does not require a Host ABI bump when it only
checks existing host imports, capabilities, and host profile compatibility.

AIR ABI changes are required only if artifact validation defines a new runtime
execution contract, package entrypoint runtime semantics, import/export layout,
memory/data representation, or runtime-required package metadata contract.

Host ABI changes are required only if validation depends on new host imports,
changed host import signatures, changed required host semantics, or accepted
event/output Host ABI imports.

## Acceptance Tests

- valid `airpkg` artifact passes deterministically;
- repeated validation emits identical JSON;
- unsupported `schemaVersion` fails with `air.artifact.schema_invalid`;
- malformed package identity fails with `air.artifact.schema_invalid`;
- hash mismatch fails with `air.artifact.hash_mismatch`;
- declared but missing linked output fails with
  `air.artifact.missing_linked_output`;
- absolute path anywhere in metadata fails with `air.artifact.absolute_path`;
- timestamp-like deterministic metadata fails with
  `air.artifact.schema_invalid` or a more specific future code;
- runtime dependency on Node, npm install, Python, source repo, Codex, or build
  scripts fails with `air.artifact.runtime_boundary_violation`;
- profile Host ABI mismatch fails with `air.artifact.profile_mismatch`;
- missing profile capability/import support fails with
  `air.artifact.profile_mismatch`;
- validation does not require source package files unless explicitly requested;
- AIR ABI remains `0.10`;
- Host ABI remains `0.10`.

## Open Questions

- Should `check-airpkg` accept only JSON artifacts in v0.17, or also directory
  artifacts containing `airpkg.json`?
- Should missing optional linked output be an error only when
  `linkedOutput.status` is `available`?
- Should artifact validation reserve additional codes for timestamp-like fields
  and source-dependency checks?
- Should `package-check --artifact` remain an alias for `check-airpkg`, or stay
  source-package-only to avoid ambiguity?
