# Development Method

AIR is developed with AI assistance under human direction.

Dmitriii created and directs the project: product direction, architecture
constraints, acceptance criteria, review orchestration, evidence gates, release
decisions, and the AI-orchestrated engineering process.

## How Work Is Accepted

Changes are expected to be:

- scoped to the milestone;
- backed by tests, fixtures, reports, or docs as appropriate;
- checked against API gates and architecture boundaries;
- reviewed for ABI impact;
- documented with migration notes when behavior changes.

The project uses AI tools for implementation assistance, test generation,
documentation drafts, review bundle hygiene, and independent critique. These
tools do not replace ownership or release responsibility.

## Evidence-First Workflow

AIR work generally favors:

- explicit release plans and feature status docs;
- API gates for milestone boundaries;
- conformance fixtures for supported behavior;
- negative tests for rejected behavior;
- evidence reports and review bundles for human inspection;
- public-clean sanitation before launch.
